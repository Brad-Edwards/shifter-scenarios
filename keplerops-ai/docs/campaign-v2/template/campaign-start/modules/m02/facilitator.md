# Module 02 Facilitator Guide

## kep-m02-h: The Document That Opened A Room

- **Lesson / reality:** Public document intake can carry instructions through extraction, retrieval, assistant triage, and an authorized provisioning tool.
- **Method / cause:** A valid partner PDF is cited and objectively routed; the tool creates a real Nextcloud room and invitation.
- **Milestones:** ticket, extraction, vector, cited triage, invitation, authenticated room, `WELCOME.md` flag.
- **Stalls / hints:** Orient to Partner Intake, explain exact-document reuse, then direct attention to routing state and mailbox. Unsupported documents must explain rejection.
- **Defense:** Treat extracted text as untrusted, separate routing criteria from model prose, constrain room provisioning, and inspect invitations.
- **Diagnostics / reset:** Join Zammad, object, Tika, Qdrant, assistant, mail, and Nextcloud IDs. Remove rejected attempts; preserve accepted room and grant.

## kep-m02-i: A Conversation Worth Having

- **Lesson / reality:** AI-assisted spearphishing is an adaptive human interaction, not a prewritten email or model-attribution checkbox.
- **Method / cause:** GLM grounds the draft in verified facts, the participant sends real SMTP, then adapts to the actual response. Objective policy fields govern disclosure.
- **Milestones:** generated/draft/sent lineage, first reply, adapted follow-up, qualifying reply with review window, alias, and flag.
- **Stalls / hints:** Orient to a role-relevant target, explain using the actual reply as context, then identify one bounded process detail to request.
- **Defense:** Minimize public dossiers, train recipients on bounded disclosures, authenticate external mail, and detect sensitive process data leaving trusted domains.
- **Diagnostics / reset:** Inspect GLM request IDs, message digests, SMTP headers, and criterion state. Clear rejected drafts/attempts; preserve successful thread.

## kep-m02-j: The Voice In The Thread

- **Lesson / reality:** Deepfake media amplifies an already trusted thread; it does not bypass context and policy by itself.
- **Method / cause:** The recipient opens and plays the delivered audio, validates phrase/context, and creates a real Keycloak invitation.
- **Milestones:** same-thread delivery, exact media digest, playback, policy checks, invitation, partner login, welcome flag.
- **Stalls / hints:** Orient to thread continuity, explain matching identity and fresh phrase, then request only the scoped partner role.
- **Defense:** Verify requests out of band, bind fresh challenges to enrollment, detect synthetic media, and make invitations least-privileged and expiring.
- **Diagnostics / reset:** Join mail, media registry, FFmpeg, browser, and Keycloak records. Clear rejected invitations/sessions; preserve earned identity.

## kep-m02-k: Read The Review Notes

- **Lesson / reality:** A trusted recipient can trigger drive-by execution when a local coding agent follows malicious repository documentation through a vulnerable MCP tool.
- **Method / cause:** `mcp-package-docs` 0.1.27 passes an unsanitized tool argument to `child_process.exec` during the real review procedure.
- **Milestones:** trusted mail click, repository render, agent request, documentation retrieval, extra MCP call, callback, session flag.
- **Stalls / hints:** Orient to public review instructions, explain the vulnerable tool version, then trace each browser/agent stage separately.
- **Defense:** Patch the tool, treat retrieved docs as untrusted, require confirmation for command-capable calls, and sandbox coding agents without ambient sessions.
- **Diagnostics / reset:** Inspect mail click, Chromium trace, agent transcript, MCP arguments, process execution, and callback. Recreate disposable reviewer state.

## kep-m02-l: The Helpful Orion Package

- **Lesson / reality:** Useful external AI software can execute in a victim environment through ordinary package publication, resolution, and import.
- **Method / cause:** The participant preserves the declared helper API while bounded import-time code returns workbench context through the relay.
- **Milestones:** signed package, accepted reproducer, exact resolution, install/import, compatibility pass, context flag callback.
- **Stalls / hints:** Orient to the helper used by the reproducer, explain preserving advertised behavior, then inspect victim-side pip output.
- **Defense:** Pin digests, verify publishers and SBOMs, isolate review installs, and reject import-time side effects or unexpected egress.
- **Diagnostics / reset:** Inspect index metadata, package digest, reviewer job, pip/import output, and relay. Reset rejected workstations/jobs; preserve accepted contribution state.

## kep-m02-m: A Tool The Agent Wants

- **Lesson / reality:** Agent-tool onboarding combines browser persuasion with a technically valid but malicious MCP integration.
- **Method / cause:** The fixed reviewer browses participant content, registers a standards-compliant tool, and genuinely invokes it on a protected fixture.
- **Milestones:** browser trace, manifest, TLS/ownership, health, schema, fixture, registration, invocation, relay flag/token.
- **Stalls / hints:** Orient to genuine compatibility first, explain how the reviewer interprets the page, then inspect the invocation trace. Cap at six attempts.
- **Defense:** Separate content from registration authority, test tools with synthetic least-privilege fixtures, constrain egress, and require human review of capabilities.
- **Diagnostics / reset:** Inspect browser frames, admission checks, catalog history, MCP exchange, and relay. Clear rejected traces; preserve an accepted tool/version/token.

## kep-m02-c: The Indexed Exception

- **Lesson / reality:** RAG behavior changes when a normal writable source enters the trusted index.
- **Method / cause:** Nextcloud content flows through Airflow/Tika into Qdrant and changes a fresh Orion answer with visible provenance.
- **Milestones:** denial baseline, uploaded digest, ingestion IDs, new thread, changed answer, source footer flag.
- **Stalls / hints:** Orient to indexed folders, explain waiting for completed ingestion, then compare new conversations. Old-thread caching is not success.
- **Defense:** Approve sources before indexing, partition contributor data, weight authority explicitly, and alert on policy changes from low-trust collections.
- **Diagnostics / reset:** Join DAV object, Airflow run, extracted text, point ID, and citations. Delete source, vectors, run, and attempt threads.

## kep-m02-d: A Source Within A Source

- **Lesson / reality:** Document splitting and metadata interpretation can create a false provenance identity not represented by intake.
- **Method / cause:** One outer PDF contains a complete nested source record that the splitter/LLM renders as a second Qdrant source.
- **Milestones:** one intake object, two retrieval identities, exact parent-child lineage, false card with flag.
- **Stalls / hints:** Orient to intake/card count mismatch, explain boundary semantics, then ensure all inner metadata fields are plausible.
- **Defense:** Preserve parser-enforced parent identity, reject nested provenance declarations, sign source metadata, and display immutable origin prominently.
- **Diagnostics / reset:** Compare object digest, extraction spans, child points, and rendered cards. Remove outer object and all descendants.

## kep-m02-a: The Credible Recommendation

- **Lesson / reality:** Trusted UI components can make model-influenced attacker content look like an approved enterprise action.
- **Method / cause:** Retrieved partner notes influence structured destination/action fields, not merely prose; TLS ownership is independently checked.
- **Milestones:** indexed note, fresh report, participant destination, concrete action, owned origin, audit-footer flag.
- **Stalls / hints:** Orient to the structured panel, explain contributor-note trust, then focus on fields rather than exact wording.
- **Defense:** Authorize structured actions separately, label source trust, constrain destinations, and require deterministic validation for recommendations.
- **Diagnostics / reset:** Inspect source digest, retrieval trace, structured JSON, renderer audit, and origin check. Remove source/report/thread attempts.

## kep-m02-b: Authority By Citation

- **Lesson / reality:** Bibliographic metadata can launder participant-controlled bytes into a trusted-looking citation.
- **Method / cause:** Tika and PDF metadata extraction retain manipulated authority fields while the source card still resolves to the participant digest.
- **Milestones:** uploaded PDF, extracted metadata, cited report, displayed authority, resolved digest, card flag.
- **Stalls / hints:** Orient to cards rather than prose, explain metadata survival, then verify the card resolves to exact bytes.
- **Defense:** Validate authority against trusted registries, sign provenance, display uploader/origin, and never infer trust from document metadata alone.
- **Diagnostics / reset:** Join upload, extraction, Qdrant payload, report, and resolved object. Remove vectors/report/thread.

## kep-m02-e: Accepted By Inspection

- **Lesson / reality:** A scanner's incomplete unsafe-global policy can allow malicious AI artifacts that execute during normal import.
- **Method / cause:** The participant adapts `GHSA-655q-fx9r-782v` to the pinned PickleScan release, then the real importer loads the allowed digest.
- **Milestones:** version/advisory discovery, allowed real scan, identical imported digest, bounded canary callback, patched rejection.
- **Stalls / hints:** Orient to the lockfile, explain callable-policy gaps, then require importer execution. A participant-supplied verdict never counts.
- **Defense:** Upgrade scanner, use multiple static analyzers, convert to non-executable formats, and isolate import with no secrets or egress.
- **Diagnostics / reset:** Inspect scanner command/output, digest, importer journal, and relay. Destroy artifact, verdict, importer, and callback attempt.

## kep-m02-f: Quiet Under Observation

- **Lesson / reality:** Dynamic analysis can be evaded when its environment is observably distinct from integration.
- **Method / cause:** The same digest combines multiple stable runtime properties and remains benign only under analysis.
- **Milestones:** two diagnostic reports, identical digest, benign analysis, integration canary callback, no hidden classification.
- **Stalls / hints:** Orient to published runtime facts, explain multi-signal activation, then verify digest identity. Reject filename or one-marker rules.
- **Defense:** Diversify/normalize sandboxes, compare behavior across contexts, remove integration secrets, and block model egress.
- **Diagnostics / reset:** Compare environment reports, worker journals, access attempts, and callback. Destroy both jobs and artifact attempt.
