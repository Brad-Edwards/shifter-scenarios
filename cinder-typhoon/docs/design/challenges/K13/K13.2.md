## Challenge description — player-facing

The current cloud notebook has had its useful customer note removed. Recover the previous object version that still contains it.

## Story purpose

Shows that changing the current object does not remove its history.

## Prerequisites and starting position

**Required access or evidence:** [G01 — K01.1](../K01/K01.1.md).

**Starting material:** The cloud workspace notebook, object references, export notes, and ordinary developer-visible workload records.

**Campaign references:** No separately named capability output.

## Completion and downstream use

Recover the distinct earlier version and its customer note. This is historical context, not current ARWC tenant binding.

## Difficulty and inspiration

A readable object-version trail with one relevant earlier record.

**Inspiration:** Original challenge for this campaign.

## Technical design


### Surface and normal behavior
The `fieldkest-workspaces` bucket has S3 versioning enabled. The key `notebooks/deploy-2026-09.json` has two versions: the current version (v2, with the customer note removed) and the prior version (the original seeded version that still contains the TEN-ARWC customer note). The prior version was retained by S3 versioning when the corrected version was uploaded.

The anonymous read ACL (from K13.1) includes List permission, which also covers `list-object-versions`. The participant can list and retrieve prior versions without credentials.

### Vulnerability and intended solution
S3 object versioning retains all prior versions. The customer note was removed by uploading a new object version, but the prior version is still retrievable by its S3 version ID.

The intended solution:
1. List versions of the notebook key: `aws s3api list-object-versions --bucket fieldkest-workspaces --prefix notebooks/deploy-2026-09.json --endpoint-url https://objects.keplerops.test --no-sign-request`
2. The XML response lists two versions with their VersionIds. The older version (earlier LastModified) is the one with the customer note.
3. Retrieve the prior version: `aws s3api get-object --bucket fieldkest-workspaces --key notebooks/deploy-2026-09.json --version-id <older_version_id> --endpoint-url https://objects.keplerops.test --no-sign-request output.json`
4. The file `output.json` contains `"customer_note": "Deployment for TEN-ARWC-019 cedar run customer..."`.
5. Extract `TEN-ARWC-019` as the legacy tenant identifier.

### Evidence and completion
The S3 GetObject response (with versionId) confirms the prior version's content and version ID. The content contains `TEN-ARWC-019` in the `customer_note` field.

### Boundaries and persistence

Historical context only. Participant-created service state persists for the life of the participant world and ordinary retries do not erase it. The action is limited to the exact records, identities, routes, and destination effects declared here; unrelated tenants and services remain denied. Infrastructure recovery and submission adjudication are outside this in-world contract.

### Author checks
Verify that list-object-versions returns two versions for the notebook key, that the older version content contains "TEN-ARWC-019" in customer_note, that the current version does NOT contain TEN-ARWC, and that both versions are retrievable without credentials.

## Hints

### Hint 1

The `fieldkest-workspaces` bucket has versioning enabled. Use `aws s3api list-object-versions` with `--prefix notebooks/deploy-2026-09.json` and `--no-sign-request` to list all versions. The result lists two versions — current and prior — with their VersionIds.

### Hint 2

The prior version (older LastModified) contains the customer note that was removed. Retrieve it with `aws s3api get-object --bucket fieldkest-workspaces --key notebooks/deploy-2026-09.json --version-id <version_id> --endpoint-url https://objects.keplerops.test --no-sign-request output.json`. The content has `customer_note` with TEN-ARWC-019.

### Hint 3

The `customer_note` in the prior version is: "Deployment for TEN-ARWC-019 cedar run customer — retain for support reconciliation". Extract `TEN-ARWC-019` as the legacy tenant ID. This is the K13.3 and K29/K30 starting point.
