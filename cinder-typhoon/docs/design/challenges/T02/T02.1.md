## Challenge description — player-facing

Identify the active rehearsal account and recover the account-bound case reference exposed by the identity desk.

## Story purpose

Provides a useful identity lead without password guessing.

## Prerequisites and starting position

**Required access or evidence:** the supplied training workspace.

**Starting material:** The rehearsal identity desk, candidate account notes, a public directory, recovery workflow, and assignment service.

**Campaign references:** No separately named capability output.

## Completion and downstream use

Recover the actual active account and its case reference. Submitting candidate names alone is insufficient. These are inputs to T02.3.

## Difficulty and inspiration

A small identity investigation with a short candidate set.

**Inspiration:** Original challenge for this campaign.

## Technical design

### Surface and normal behavior

`accounts.training:8080` publishes candidate notes and
`POST /api/recovery/lookup` with the exact JSON field `account`. The notes bound
the search to `mina.cho`, `rhea.moss`, and `owen.pike`. The realm contains an
inactive Mina record, active Rhea record, and no Owen record. Lookup is limited
to six requests per minute and records submitted handle, response class, status,
and UTC time.

### Vulnerability and intended solution

The endpoint returns 410 plus `inactive` for Mina, 404 plus `unknown` for Owen,
and 200 for Rhea with the account-bound fragment `CASE-7Q4M`. Malformed or
extra-field bodies return 400 and the rate limit returns 429. The intended
solution tests only the three supplied contextual candidates and retains the
active response; the lookup does not create a session.

### Evidence and completion

The normal lookup response contains the active subject and its linked case
reference. The desk retains the corresponding lookup audit. That response
itself supplies the information used in recovery; it authenticates nobody.

### Boundaries

The endpoint is limited to the small rehearsal account set and rate-bounded.
The lookup itself cannot change a password or create an authenticated session.
Repeated lookups preserve the account states and the existing case reference.

### Author checks

Verify the supplied lead narrows the candidates, response classes are stable,
only the active account yields the case fragment, bulk submission is bounded,
and a correct lookup records the expected subject.
