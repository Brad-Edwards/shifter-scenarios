## Technical design


### Surface and normal behavior

The archive service owns the sessions endpoint. The `identity.sessions` route in the archive service client document → `POST https://retained-archive.arwc.test/api/sessions`. After W06.2 attaches the controlled preview, the participant submits the oauth_transaction and preview_origin that match the browser attachment. The archive service validates the binding and creates nadia.corvane's real Metabase session via the native reporting system. The resulting session ID is a usable Metabase token limited to planning records.

Native bindings:

- Route: `identity.sessions` in the retained-archive service client document
- Credentials: W04.3 planner handover token (gate) + oauth_transaction from RENDER-CRR-882 + preview_origin from W06.2
- Final authority: real Metabase session ID for nadia.corvane (`reports.arwc.test/api/session`)
- Protected record: planning drawing context question accessible to nadia in Metabase

Evidence: archive service audit entry `planner-session-issued` with real Metabase session ID. Participant demonstrates authority by querying the protected planning record using the Metabase session against the native reporting system.

### Vulnerability and intended solution

The authored condition is **privileged-browser origin trust**. The review browser posts its planner session bootstrap to the attached preview for compatibility; origin is checked against mutable pending-preview state and yields a fifteen-minute planner session limited to planning records. The hand build must preserve every named version, encoding, bound, validation order, identity, and unaffected field; substituting a generic vulnerable service would change the task.

The required result is: Recover and demonstrate the planner session against the protected record. This supplies W07's application context; an exposed browser value without authority does not establish the result.

### Evidence and completion

The owning service writes an immutable audit for the accepted request and result. Caller-supplied output, a local copy, or knowledge of an identifier is not sufficient. Completion is evaluated from fresh service-owned evidence after the action. It cannot issue the identity, create the mutation, move a simulated actuator, or fabricate a downstream acceptance needed to prove itself.

Evidence sources are `features.a-corporate.a-identity`. A wrong identifier, stale revision, replayed one-time value, different checkpoint, or cross-tenant artifact is rejected.

### Boundaries and persistence

Supplies the planner application context required by W07. Tenant-scoped mutations, sessions that have not expired, generated artifacts, and audits persist across ordinary retries and later sessions. Initial immutable records remain unchanged unless the named route explicitly permits a field-level revision. Infrastructure recovery and submission adjudication are external to the SDL.

The behavior is limited to the named fictional objects and bounded service operation. It provides no general shell, arbitrary network target, unrelated district access, real process interface, or authority not expressly declared by the card.

### Author checks

Test wrong authority, wrong object or district, stale revision, replay, another tenant instance, and every declared constraint or unaffected record. Repeat the accepted action according to its idempotence rule and confirm ordinary retries preserve the result. For a joined result, verify each destination observed the same correlation and that removal of any independently owned source prevents completion.
