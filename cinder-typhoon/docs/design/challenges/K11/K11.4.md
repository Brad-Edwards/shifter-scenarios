## Technical design


### Surface and normal behavior
The service's `accept` operation runs the real binary (`fieldkest-policyc`) against a participant-supplied policy input and issues a PCACC receipt if the binary returns `accepted=true`. The operation is nonce-bound: the participant must first obtain a one-use nonce from `POST /nonces`, include it in the acceptance request, and the nonce is consumed on the first syntactically valid request — even if the policy input is later rejected by the binary.

Cinder's scenario: active tenant, connector API v3+, fieldkest-release-2026 signer lineage, and the compatibility exception the campaign narrative describes. The participant must supply all six fields: the four policy conditions (from K11.3) and two context fields (channel and tenant_class — not policy conditions but required by the input schema). The corpus shows `channel=preview` and `tenant_class=field-service` as the Cinder scenario context.

### Vulnerability and intended solution
The participant constructs a policy input that satisfies all four conditions recovered in K11.1–K11.3:
- `tenant_state = "active"` (from K11.3: set index 0)
- `connector_api = "3.0.0"` (from K11.3: const index 0, semver >= threshold)
- `signer_lineage = "fieldkest-release-2026"` (from K11.3: set index 1)
- `compatibility_exception = true` (from K11.3: const index 1)

Plus context: `channel = "preview"`, `tenant_class = "field-service"`.

The intended solution:
1. POST `{}` to `/nonces` → receive a fresh one-use nonce.
2. Submit `operation=accept` with the program model (from K11.1), `policy_input` containing all six fields plus the nonce, and `corpus_result_sha256` from K11.3.
3. The service runs the real binary against the input. The binary returns `accepted=true` and `evaluated_fields=["tenant_state","connector_api","signer_lineage","compatibility_exception"]`.
4. The service issues a PCACC receipt with `program_id=FKPC-POLICY-2026-09-R4`, `binary_sha256`, `condition_set_sha256`, and `evaluated_fields`.
5. A second submission with the same nonce is rejected with `stale_or_replayed_nonce`.

### Evidence and completion
A PCACC receipt (operation `accept`) is written to the source-tools audit log with `program_id`, `binary_sha256`, `condition_set_sha256`, and `evaluated_fields`. The receipt is fresh (uses a unique nonce) and cannot be replayed. It is the K11.4 and K11 completion evidence.

### Boundaries and persistence

Specialist payoff only. Participant-created service state persists for the life of the participant world and ordinary retries do not erase it. The action is limited to the exact records, identities, routes, and destination effects declared here; unrelated tenants and services remain denied. Infrastructure recovery and submission adjudication are outside this in-world contract.

### Author checks
Verify that a fresh nonce is required (stale nonce rejected), that the binary is actually executed (not bypassed), that a rejected input (wrong tenant_state) is rejected by the binary before the nonce is consumed (wait — nonce IS consumed before binary run, so a syntactically valid but policy-rejecting input wastes the nonce), and that the PCACC receipt includes the correct binary_sha256 and evaluated_fields.

## Hints

### Hint 1

GET a fresh one-use nonce first: `POST /api/policy-compilers/fieldkest-policyc/nonces` with body `{}`. The nonce expires after five minutes and is consumed on the first syntactically valid acceptance request. Obtain it immediately before submitting, not in advance. The request shape is in `api/accept-template.json`.

### Hint 2

Construct the `policy_input` with all six fields: the four conditions recovered in K11.3 (tenant_state, connector_api, signer_lineage, compatibility_exception — with the values from binary and corpus analysis), plus `channel="preview"` and `tenant_class="field-service"` as context. Add the fresh nonce and the `corpus_result_sha256` from K11.3. The binary rejects any input that fails even one condition.

### Hint 3

Submit `operation=accept` with the program model from K11.1, the policy_input, and the nonce. The service runs the real binary against the input. If accepted, the PCACC receipt includes `program_id=FKPC-POLICY-2026-09-R4`, `binary_sha256`, `condition_set_sha256`, and `evaluated_fields=["tenant_state","connector_api","signer_lineage","compatibility_exception"]`. A replay of the same nonce returns `stale_or_replayed_nonce`.
