## Challenge description—player-facing

The recovered staging material conceals another stage. Reconstruct the usable script and recover the instructions needed to understand what the earlier operator collected.

## Story purpose

Rewards sustained analysis with a specific operational lead.

## Prerequisites and starting position

**Required access or evidence:** [K03.1](K03.1.md).

**Starting material:** A retained staging bundle from an earlier Cinder attempt, its carrier document, and a short collection note.

**Campaign references:** No separately named capability output.

## Completion and downstream use

Recover the complete next-stage script and its actual collection instructions. Merely locating embedded text does not establish the reconstructed behavior.

Layered document and script analysis inspired directly by Game Invitation.

**Inspiration:** [Game Invitation (HTB Cyber Apocalypse 2024; Hard)](../../reference-catalog.md#c04). The inspiration is document and script reconstruction; the objective remains collection for Cinder.

## Technical design


### Surface and normal behavior
The staging artifact is a three-stage retained analysis bundle: the ODT attachment wraps a PowerShell stage, which carries a JavaScript collector stage, which reconstructs an integrity-bound object-storage manifest. Each script stage has its own digest and can be examined offline.

### Vulnerability and intended solution
This is a staged reverse-engineering exercise. The intended solution reconstructs the complete executable representation and interprets its declared collection instructions; locating a string fragment is insufficient.

### Evidence and completion
The recovered PowerShell and JavaScript bytes must match their retained digests, and the final manifest must bind one endpoint, bucket, object key, collection ID, endpoint ID, and object digest. That manifest is the sole input to K03.3; no local service validates or reveals the answer.

### Boundaries and persistence

Required by K03.3 Participant-created service state persists for the life of the participant world and ordinary retries do not erase it. The action is limited to the exact records, identities, routes, and destination effects declared here; unrelated tenants and services remain denied. Infrastructure recovery and submission adjudication are outside this in-world contract.

### Author checks
Test incomplete outer decoding, wrong stage digest, wrong XOR order, complete offline reconstruction, manifest/object consistency, and that no script execution is required.

## Hints

### Hint 1
The supplied decoder artifact describes only the outer encoding. Preserve the recovered bytes and verify the digest in the stage header before following what they contain.

### Hint 2
The recovered PowerShell carries another compressed script and its own digest. Preserve the encoding and integrity boundary while reconstructing it as data; neither retained stage needs to be executed.

### Hint 3
The JavaScript stage shows how its base64 bytes, repeating key, and zlib layer produce the collection manifest. Verify both script digests and recover every manifest field.
