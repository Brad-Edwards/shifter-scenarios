## Technical design


### Surface and normal behavior

`a-archive` and its `retained-archive` application own this card. The same `/api/observations` route that serves W16.1 also handles out-of-window probes. `execute_observation_program` processes LOAD instructions in this order: (1) read `SAMPLE_SLOTS[index]`, (2) add the data-dependent cycle cost `20 + 4 * bit_count(sample)`, (3) check if `index` is in `authorized_indices` (0–31). An unauthorized index breaks the loop and returns `late-authorization-rejection` with the accumulated cycle count but without the sample value or further instructions.

The signal-discrimination target slot is 159 (`SAMPLE_SLOTS[159] = 0xA5`, 4 set bits). A LOAD on slot 159 adds 36 cycles (20 + 4×4) to the 200-cycle baseline, producing cycles=236.

Native bindings:

- Route: `POST retained-archive.arwc.test/api/observations` (same as W16.1)
- Same sequencer/revision/request_id binding as W16.1
- `execute_observation_program` in `retained_archive.py`

The private service-loader contract is `content.arwc-a-archive.w16-2-an-observation-outside-the-window`.

### Vulnerability and intended solution

The authored condition is **late bounds authorization with observable cycle state**. LOAD reads the sample and accumulates the data-dependent cost before the authorization check. An unauthorized LOAD leaks the bit count of the slot value via the cycle count, without returning the byte.

The participant submits a program with LOAD on an out-of-window slot (index > 31). The service returns `late-authorization-rejection` with a non-null `boundary_index` and a cycle count that reflects the target slot's bit population.

Intended program: `LOAD slot 159, HALT` → bytes `01 9F 00 00 07 00 00 00` → base64 `AZ8AAAcAAAA=`.
Expected result: HTTP 201, `status=late-authorization-rejection`, `boundary_index=159`, `cycles=236`.

The boundary crossing sets `sequencer_boundary_observed=True`, unlocking W16.3.

The required result is: Produce evidence of the specified boundary crossing. An unexplained crash or ordinary in-window reading does not establish the result.

## Hints

### Hint 1

The LOAD instruction takes an 8-bit slot index but the authorization check comes after the sample is read and the cycle cost is added. Submit a program to `POST /api/observations` with LOAD on a slot index outside 0–31 and observe the response status and cycle count.

### Hint 2

The descriptor lists 32 authorized indices (0–31). Any LOAD with index ≥ 32 returns `late-authorization-rejection` with a non-null `boundary_index`. The cycle cost `20 + 4 × bit_count(sample)` is still accumulated before the authorization check, so the cycle count encodes information about the out-of-window slot.

### Hint 3

Target slot 159 for the designated boundary crossing: program bytes `01 9F 00 00 07 00 00 00` (LOAD slot 159, HALT), base64 `AZ8AAAcAAAA=`. The response will have `status=late-authorization-rejection`, `boundary_index=159`, and a cycle count that reflects the slot's bit population. Confirm the service-owned audit shows `sequencer_boundary_observed` is now set.
