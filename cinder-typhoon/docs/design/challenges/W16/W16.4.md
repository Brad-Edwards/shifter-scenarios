## Technical design


### Surface and normal behavior

`a-archive` and its `retained-archive` application own this card. The `/api/instrument-history/current` route handles the calibration submission, gated on `sequencer_signal_discriminated=True`. The protected 32-byte calibration record occupies `SAMPLE_SLOTS[160:192]` and consists of a 28-byte payload (`R8|OG2|GAIN=1.003|ZERO=0.012`) followed by its 4-byte CRC32C (big-endian). The service validates:

- `record_id = "CAL-CRR-OG2-R8"`
- `field_revision = "R8"`
- `calibration` (base64): 32 bytes, CRC32C of first 28 bytes matches last 4, and exact match to `SAMPLE_SLOTS[160:192]`

The participant recovers all 32 bytes through repeated `measure` programs via `/api/signal-experiments`. Each program holds at most 63 TEST instructions (64-instruction total limit including HALT). Testing all 32 slots with 9 probes each (p=0 baseline + 8 single-bit probes) requires 288 TEST instructions = 5 programs.

Native bindings:

- Route: `POST retained-archive.arwc.test/api/signal-experiments` (measure, repeated for all 32 slots)
- Route: `POST retained-archive.arwc.test/api/instrument-history/current` (calibration submission)
- `sequencer_calibration` and `execute_test_program` in `retained_archive.py`

The private service-loader contract is `content.arwc-a-archive.w16-4-what-the-instrument-remembers`.

### Vulnerability and intended solution

The authored condition is **constrained calibration recovery**. The TEST instruction probes any slot including 160-191 (the calibration slots) without an authorization check. Using 9 probes per slot (baseline + 8 single-bit), the participant recovers each byte's bit pattern and reconstructs all 32 bytes.

Intended approach:
1. For each slot s in 160–191, run TEST(s, p) for p ∈ {0, 1, 2, 4, 8, 16, 32, 64, 128}. (63 TEST per program × 5 programs covers 32 slots × 9 probes = 288 measurements.)
2. For each bit i: if `cycles(probe=2^i) < cycles(probe=0)`, bit i is set.
3. Verify CRC32C: `crc32c(recovered[:28]) == int.from_bytes(recovered[28:], "big")`.
4. POST `instrument-history/current` with `record_id=CAL-CRR-OG2-R8`, `field_revision=R8`, and `calibration=base64(recovered_32_bytes)`.

The required result is: Recover the complete correctly bound calibration record under the stated diagnostic constraints. It is an optional W33 input; ordinary commissioning records supply an easier alternative.

## Hints

### Hint 1

The calibration record occupies slots 160–191 (32 bytes). Use the same `measure` operation from W16.3 (`POST /api/signal-experiments`) with TEST instructions targeting slots 160–191. Each program allows at most 63 TEST instructions (the 64-instruction total limit includes HALT). Plan 5 programs of ≤63 TEST each to cover all 32 slots × 9 probes (p=0 and 8 single-bit probes).

### Hint 2

Apply the same bit-discrimination technique from W16.3 to each of the 32 calibration slots. For each slot, `cycle(probe=2^i) < cycle(probe=0)` means bit i is set. Reconstruct all 32 bytes and verify the CRC32C: the last 4 bytes must equal `crc32c(first_28_bytes)` encoded big-endian.

### Hint 3

Submit the recovered calibration to `POST /api/instrument-history/current` with `record_id="CAL-CRR-OG2-R8"`, `field_revision="R8"`, and `calibration=base64(recovered_32_bytes)`. Plus the standard sequencer/revision/request_id binding. A successful response returns `CAL-CRR-OG2-R8` with `revision=8` and the slot range `[160, 191]`.
