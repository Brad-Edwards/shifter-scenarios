## Technical design


### Surface and normal behavior

`a-archive` and its `retained-archive` application own this card. The archive service loads the instrument image `IMG-FIT-204-R6.bin` at startup and builds the 256-byte sample slot map: bytes 0–255 of the image form the base; the instrument specification then sets fixed reference test points (slot 4=0x00, slot 5=0x01, slot 6=0xFF); live OT historian readings for FIT-CRR-204A and FIT-CRR-204B overwrite slots 0 and 1; and the CALIBRATION record fills slots 160–191. The SEQUENCER descriptor SEQ-CRR-4 is returned from `GET retained-archive.arwc.test/api/sequencer-specs/current`. The ordinary trace SEQ-BASE-17 (program hex `0104000007000000`, LOAD slot 4 then HALT) returns `authorized-load` with cycles=228 when slot 4 is the zero reference.

Native bindings:

- Route: `GET retained-archive.arwc.test/api/sequencer-specs/current`
- Route: `POST retained-archive.arwc.test/api/sequencer-programs` with body `{"program_hex": "0104000007000000"}`
- Instrument image: `/run/arwc-instruments/IMG-FIT-204-R6.bin` (8192 bytes, `F204[` magic, FIT-CRR-204A config)
- OT historian: `https://read-data.arwc.test/api/operating-history` (live FIT-CRR-204A/B readings)

The private service-loader contract is `content.arwc-a-archive.w16-1-the-sequencer-s-vocabulary`.

### Vulnerability and intended solution

This card is an exact discovery, interpretation, and reconciliation task. The participant must:

1. Obtain the SEQ-CRR-4 descriptor from `GET /api/sequencer-specs/current` using their CORPORATE session.
2. Submit the ordinary trace program `0104000007000000` to `POST /api/sequencer-programs`.
3. Confirm the result is `authorized-load` with cycles=228.

The descriptor is sourced from the native archive service with the instrument image populated at startup. Finding the binary or its version string is not sufficient; the participant must call the service and produce a correctly bound execution result.

The required result is: Recover the descriptor and a correctly bound baseline observation. Finding the binary or its version string is insufficient.

Evidence sources are `features.a-corporate.a-archive`. A wrong identifier, stale revision, replayed one-time value, different checkpoint, or cross-tenant artifact is rejected.

## Hints

### Hint 1

Call `GET retained-archive.arwc.test/api/sequencer-specs/current` with your CORPORATE session to retrieve the SEQ-CRR-4 descriptor. It contains the opcode table, authorized index range, and the ordinary trace `SEQ-BASE-17` with its `program_hex`.

### Hint 2

Submit the ordinary trace to `POST retained-archive.arwc.test/api/observations`. The service expects `sequencer=SEQ-CRR-4`, `revision=4`, a unique `request_id`, and the `program` field as a base64-encoded binary (convert the `program_hex` bytes to base64). The descriptor must be observed first; the service returns 403 otherwise.

### Hint 3

The expected result is `authorized-load` with `cycles=228`. Verify the service-owned audit at `features.a-corporate.a-archive` shows `sequencer-program-submitted` with the correct cycle count. This baseline confirms the sequencer interface and reference slot encoding before attempting the boundary card (W16.2).
