## Challenge description — player-facing

Construct input that causes the inspection components to disagree about the request they are processing. Demonstrate the disagreement with a controlled downstream effect.

## Story purpose

Turns boundary analysis into an exploitable request capability.

## Prerequisites and starting position

**Required access or evidence:** [K07.1](K07.1.md).

**Starting material:** The registry inspector's normal account, request samples, component descriptions, and a constrained rehearsal interface.

**Campaign references:** No separately named capability output.

## Completion and downstream use

Produce a fresh, reproducible downstream action inconsistent with the front-end request interpretation. A malformed response or rejected request is insufficient.

## Difficulty and inspiration

Cross-component request-framing reasoning adapted from Percetron.

**Inspiration:** [Percetron (HTB Cyber Apocalypse 2024; Hard)](../../reference-catalog.md#c05). Retains Percetron's request-framing problem; W04 and W11 use different portions of the source.

## Technical design


### Surface and normal behavior
The inspector and assessment component parse a compact request envelope before producing a bounded test assessment.

### Vulnerability and intended solution
Their framing rules disagree at one deliberate length/normalization boundary. The intended solution constructs a valid outer request whose downstream interpretation differs, then verifies the designated harmless assessment change.

### Evidence and completion
Both component audit records, with their distinct interpreted request IDs and the expected test-only effect, form completion evidence.

### Boundaries and persistence

Parser-confusion primitive Participant-created service state persists for the life of the participant world and ordinary retries do not erase it. The action is limited to the exact records, identities, routes, and destination effects declared here; unrelated tenants and services remain denied. Infrastructure recovery and submission adjudication are outside this in-world contract.

### Author checks
Test ordinary agreement, intended parser disagreement, invalid envelope rejection, sentinel-only effect, both audit records.
