## Challenge description — player-facing

Use the framing capability to perform the inspector's protected package action and recover its restricted assessment.

## Story purpose

Gives the request exploit a useful package-intelligence conclusion.

## Prerequisites and starting position

**Required access or evidence:** [K07.2](K07.2.md).

**Starting material:** The K07.1 `inspection_id` and `assessor_correlation_id` from the K07.1 trace, the K07.2 body-framing smuggling primitive (CL = `front_following_length` < actual body), and the binary payload format for the K07.3 protected route: 2-byte big-endian `payload_len` + JSON body.

**Campaign references:** No separately named capability output.

## Completion and downstream use

Complete the protected assessment under the inspector's downstream authority. Repeating the framing demonstration without crossing the action boundary earns no further credit.

## Difficulty and inspiration

Requires composing the primitive with the protected action's binding and authorization constraints.

**Inspiration:** [Percetron (HTB Cyber Apocalypse 2024; Hard)](../../reference-catalog.md#c05). Retains Percetron's request-framing problem; W04 and W11 use different portions of the source.

## Technical design


### Surface and normal behavior
The assessment component has a protected package-inspection action tied to a restricted assessment record and accepts only its internal framed request form.

### Vulnerability and intended solution

K07.3 composes the K07.2 body-framing primitive with the K07.1 inspection authorization to reach a more protected assessor route:

- **Route**: `/assess/inspect-privileged` on the internal assessor (not externally accessible)
- **Authorization**: requires a valid K07.1 `inspection_id` (validated against the registry results)
- **Body format**: a binary-framed payload — 2-byte big-endian `payload_len` + inspection_id JSON

The intended solution:
1. Apply the K07.2 body-framing smuggling: set `front_following_length = 10` (CL to assessor) while the actual envelope is larger.
2. Craft the surplus bytes as `POST /assess/inspect-privileged` with `Content-Length = 37` and a binary-framed body: `\x00\x21{"inspection_id":"INSP-XXXXXXXX"}` (2 bytes payload_len + 33-byte JSON).
3. The assessor validates the `inspection_id` against the K07.1 registry results. Invalid or absent IDs return 403 without creating any state.
4. The assessor fetches the real `@keplerops/support-rehearsal` package from Verdaccio using the CI reader identity and writes `protected-assessment-{uuid}.json` to the shared results directory.
5. The participant queries `GET /api/protected-assessment/latest` to retrieve the protected assessment, which binds the K07.1 `inspection_id`, the K07.1 `assessor_correlation_id`, and the real Verdaccio private package data.

The Expert distinction from K07.2:
- K07.2: reach a simple privileged route (no authorization) → Verdaccio metadata
- K07.3: craft a binary-framed smuggled body, include the K07.1 inspection_id as an authorization credential, reach a doubly-protected route that requires both the smuggling capability AND the inspection context

### Evidence and completion
The component emits a protected-assessment read with request correlation and returns its immutable finding as operator evidence.

### Boundaries and persistence

Optional restricted finding Participant-created service state persists for the life of the participant world and ordinary retries do not erase it. The action is limited to the exact records, identities, routes, and destination effects declared here; unrelated tenants and services remain denied. Infrastructure recovery and submission adjudication are outside this in-world contract.

### Author checks
Verify direct protected access denial, required K07.2 evidence, intended read, unrelated action denial, correct audit correlation.

## Hints

### Hint 1

The K07.3 protected route (`/assess/inspect-privileged`) requires a valid K07.1 `inspection_id` as authorization. The smuggled POST body is binary-framed: 2 bytes of `payload_len` (big-endian) followed by a JSON object `{"inspection_id":"INSP-XXXXXXXX"}`. Invalid or non-existent inspection IDs return 403 without creating any state.

### Hint 2

Apply the same K07.2 body-framing primitive: set `front_following_length = 10` (CL to assessor = the 10-byte envelope header). The surplus bytes are the POST headers (with `Content-Length` = `payload_len_bytes` + JSON size) followed by the binary-framed body. No trailing bytes should remain after the smuggled body is consumed.

### Hint 3

After submitting the smuggling envelope, query `GET /api/protected-assessment/latest` to retrieve the protected assessment. It binds the K07.1 `inspection_id`, the K07.1 `assessor_correlation_id`, the real Verdaccio `@keplerops/support-rehearsal` package data, and the finding. Both the K07.1 trace and the protected assessment serve as the correlated audit evidence.
