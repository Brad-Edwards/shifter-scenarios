## Challenge description — player-facing

Recover the inspector's restricted transaction record and determine how a normal package request reaches its downstream component.

## Story purpose

Establishes concrete evidence for investigating the inspection boundary.

## Completion and downstream use

## Difficulty and inspiration

A bounded interface investigation with two observable components.

**Inspiration:** [Percetron (HTB Cyber Apocalypse 2024; Hard)](../../reference-catalog.md#c05). Retains Percetron's request-framing problem; W04 and W11 use different portions of the source.

## Technical design


### Surface and normal behavior
The FieldKest package inspector accepts a package request, records a restricted transaction trace, and forwards a normalized request to its assessment component.

### Vulnerability and intended solution
The trace-retention endpoint authorizes the caller's request but not the linked internal trace. The intended solution is contextual record recovery and request-flow reconstruction.

### Evidence and completion
The operator receives the trace ID, normalized request fields, and downstream component binding needed by K07.2.

### Boundaries and persistence

Input to K07.2 Participant-created service state persists for the life of the participant world and ordinary retries do not erase it. The action is limited to the exact records, identities, routes, and destination effects declared here; unrelated tenants and services remain denied. Infrastructure recovery and submission adjudication are outside this in-world contract.

### Author checks
Test normal inspection, trace access lead, exact request/component correlation, denial for unrelated traces.
