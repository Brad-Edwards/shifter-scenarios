## Challenge description — player-facing

The delivery team removed its local npm configuration from the current source tree. Recover usable publishing authority from the retained native history and establish its limits.

## Story purpose

Creates the ordinary package-delivery route's publication capability.

## Prerequisites and starting position

**Required access or evidence:** [G03 — K05.1](../K05/K05.1.md).

**Starting material:** The package import workflow, its documented input form, a rehearsal consumer, and the registry interfaces exposed by the workflow.

**Campaign references:** `A01`.

## Completion and downstream use

Recover the actual scoped publisher configuration from native Git history and demonstrate its authorization limits. It supports K06.3 but does not authorize the private package read in K06.2 or release administration.

## Difficulty and inspiration

Native precedent: [PortSwigger version-control disclosure](https://portswigger.net/web-security/information-disclosure/exploiting/lab-infoleak-in-version-control-history). Medium work combines historical recovery with distinct native authorization-scope proof; the upstream exercise is a mechanism reference, not a measured tier equivalence.

## Technical design


### Surface and normal behavior
The existing private Gitea connector repository contains the delivery-operations branch with real commits for the delivery workspace. Current source uses managed credentials, but an earlier committed native npm configuration remains in Git history.

### Vulnerability and intended solution
Follow the delivery branch history, recover the historical client configuration and identify its actual native publishing account. Establish its scope through ordinary Verdaccio requests; it publishes the connector but cannot read the private support package or administer releases.

### Evidence and completion
The recovered native configuration and Git commit establish the account provenance. Actual scoped native registry authorization permits the intended connector publication while denying the independent private package and release-administration boundaries.

### Boundaries and persistence

Supplies A01 Participant-created service state persists for the life of the participant world and ordinary retries do not erase it. The action is limited to the exact records, identities, routes, and destination effects declared here; unrelated tenants and services remain denied. Infrastructure recovery and submission adjudication are outside this in-world contract.

### Author checks
Verify native Git discovery/history and removed-current-file behavior, working scoped publisher authentication, private package denial, release-administration denial and persistence without changing main or retained tags.
