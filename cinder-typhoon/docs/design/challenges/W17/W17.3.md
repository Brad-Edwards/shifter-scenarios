## Technical design


### Surface and normal behavior

The installed Cairn Reach OT products own this card. The participant reads the engineering reference doc from their desktop, then confirms the five identities against the native catalog.

**Reference doc** (image-owned, starting material):
`~/CairnReach/Briefs/W17/engineering-reference.md` (reference `CRR-ENG-INST-204B-R1`)

Content: FIT-CRR-204B → `FlowBM3s` → `nsu=urn:arwc:crr:tags;s=CRR.FlowBM3s` → `flow_b_m3s` → `m3/s`

**Native catalog confirmation** (authoritative):
`ot_history.tag_catalog` in the PostgreSQL historian:
```sql
SELECT variable, series, node_id, unit
FROM ot_history.tag_catalog
WHERE series = 'flow_b_m3s';
```

Returns: `FlowBM3s | flow_b_m3s | nsu=urn:arwc:crr:tags;s=CRR.FlowBM3s | m3/s` ✓

**Live verification** (`ot_history.process_samples`):
Recent `FlowBM3s` samples confirm the point exists with StatusGood quality.

Native bindings:
- `a-engineering.a-engineering/filesystem:/home/fieldlink/CairnReach/Briefs/W17/engineering-reference.md`

- `a-engineering.a-historian/PostgreSQL:ot_history.tag_catalog`

### Vulnerability and intended solution

This is a bounded engineering-reference cross-check task. The participant reads the reference document, extracts the five identities, and confirms them against the native catalog. The reference doc does not supply a current value; the participant must verify the point exists in the catalog.

Five identities to recover and confirm:
1. Physical instrument: `FIT-CRR-204B`
2. IEC variable: `FlowBM3s`
3. OPC UA NodeId: `nsu=urn:arwc:crr:tags;s=CRR.FlowBM3s`
4. Historian series: `flow_b_m3s`
5. Unit: `m3/s`

The required result is: Recover the physical instrument, IEC variable, OPC UA NodeId, historian series, and unit, and confirm that the native catalog exposes the same point. This does not supply W18's complete outlet mapping.

### Evidence and completion

Completion compares the participant's observation with fresh, read-only product records. Product evidence is supplied by the range, never by the participant, and the completion path cannot write a tag, issue a command, change controller state, or create its own product evidence.

Evidence sources are `features.a-engineering.a-engineering`, `features.a-engineering.a-historian`. A wrong asset, point identity, unit, time interval, quality state, or inconsistent field relationship is rejected.

### Boundaries and persistence

The result remains local evidence unless a downstream workflow explicitly names it. The task is read-only and creates no process mutation to retain or reset. Ordinary historian retention continues independently. Infrastructure recovery and submission adjudication are external to the SDL.

The behavior is limited to the installed Cairn Reach products, the named asset, and the supplied participant material. It provides no alternate challenge service, simulated completion endpoint, or authority not already present in the OT environment.
