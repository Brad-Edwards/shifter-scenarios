## Challenge description — player-facing

Make the dispatch diagnostic helper reveal the internal delivery summary that its ordinary report leaves out.

## Story purpose

Provides an early application-exploitation payoff.

## Prerequisites and starting position

**Required access or evidence:** the supplied training workspace.

**Starting material:** The supplied training workspace, dispatch site, retired courier-client material, and a diagnostic helper.

**Campaign references:** No separately named capability output.

## Completion and downstream use

Recover the internal summary through an action in the helper's actual context. Echoing supplied text or returning an ordinary report is insufficient.

## Difficulty and inspiration

A single approachable application boundary with clear feedback.

**Inspiration:** Original challenge for this campaign.

## Technical design

### Surface and normal behavior

`workbench.training:8083` exposes
`GET /api/diagnostics/render?delivery_id=DL-204&view=...`. The default view is
`public/DL-204.json`; the separate existing internal record is
`internal/DL-204.json` with summary ID `DS-204-I`. The helper accepts only
delivery `DL-204`, reads JSON beneath `/var/lib/cinder-workbench/diagnostics`,
and records the raw view, normalized relative path, summary ID, status, and UTC
time.

### Vulnerability and intended solution

The helper first checks that the raw, not-yet-decoded `view` begins with
`public/`; it then percent-decodes exactly once and normalizes the result without
rechecking the public prefix. The intended value is
`public%2F..%2Finternal%2FDL-204.json`, which normalizes to the existing internal
record while remaining inside the fixed diagnostic root. Paths outside that
root are rejected. Values are never interpolated into a command or executed.

### Evidence and completion

The helper returns the existing internal summary for the selected delivery
and records that retrieval in its ordinary service audit. Echoed input and
the public report are not the internal record.

### Boundaries

The helper uses only its private rehearsal data directory. Its service context
has no outbound network access, persistent shell, or reusable system credential.
A report request does not recreate the workspace or erase earlier activity.

### Author checks

Check ordinary reporting, the intended bounded secondary action, invalid
selectors, confinement to the rehearsal data, and retained service audit.
