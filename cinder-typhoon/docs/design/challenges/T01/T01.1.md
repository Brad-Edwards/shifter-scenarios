## Challenge description — player-facing

The last training operator left an empty handover note and an unfinished delivery. Recover the missing handover from the supplied workspace.

## Story purpose

Gives a new player a quick evidence-recovery success with a recognizable purpose.

## Prerequisites and starting position

**Required access or evidence:** the supplied training workspace.

**Starting material:** The supplied training workspace, dispatch site, retired courier-client material, and a diagnostic helper.

**Campaign references:** No separately named capability output.

## Completion and downstream use

Recover the actual handover and its delivery reference. It provides story context but no required campaign credential.

## Difficulty and inspiration

A small artifact set with a clear missing-document lead.

**Inspiration:** Original challenge for this campaign.

## Technical design

### Surface and normal behavior

The supplied workspace contains an ordinary shared handover directory, a local
Git worktree, and a delivery tracker export. The outgoing operator replaced a
handover file with an empty template while retaining the worktree history and
the tracker record named by the note.

### Vulnerability and intended solution

This is an evidence-recovery exercise: the visible workspace does not represent
the complete local history. The intended solution class is inspection of normal
local artifacts and revision history, then correlation with the tracker rather
than filename guessing.

### Evidence and completion

Completion requires the historical handover contents and its matching delivery
reference. The scorer checks the fixture revision and tracker ID against the
player's isolated evidence record; no credential or standing authority results.

### Boundaries and reset

The worktree is read-only and contains only training fixtures. Reset restores
the checkout and removes the player's evidence event without changing the
shared commit graph.

### Author checks

Verify the visible note is empty, its prior content is recoverable through an
ordinary local path, the tracker reference resolves once, arbitrary filenames
do not score, and a reset returns the starting checkout.
