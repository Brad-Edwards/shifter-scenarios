## Challenge description — player-facing

The last training operator left an empty handover note and an unfinished delivery. Recover the missing handover from the supplied workspace.

## Story purpose

Gives a new player a quick evidence-recovery success with a recognizable purpose.

## Prerequisites and starting position

**Required access or evidence:** the supplied training workspace.

**Starting material:** The supplied training workspace, dispatch site, retired courier-client material, and a diagnostic helper.

**Campaign references:** No separately named capability output.

## Completion and downstream use

Recover the actual handover and its delivery reference. It provides story context but no required campaign credential.

## Difficulty and inspiration

A small artifact set with a clear missing-document lead.

**Inspiration:** Original challenge for this campaign.

## Technical design

### Surface and normal behavior

`workbench.training:8080` publishes the workspace index, the read-only
`handover.git` smart-HTTP repository, and `workspace/delivery-tracker.csv`.
The repository has exactly two deterministic commits. `handover-written`
contains a completed `handover.md` naming `DL-204` and courier `CR-17`;
`blank-template` is its child and replaces that file with the visible blank
template. The tracker contains exactly one `DL-204` row. Authors, committers,
UTC times, messages, modes, parents, paths, and bytes are fixed by
`repository-seed.json`.

### Vulnerability and intended solution

The current tree is intentionally incomplete while the ancestor object remains
reachable through ordinary Git history. The intended solution is to clone or
browse that repository, recover the ancestor `handover.md`, and correlate its
single delivery ID with the tracker. No hidden path or arbitrary filename guess
is required.

### Evidence and completion

The recovered handover carries the delivery reference matching the tracker.
Its bytes belong to an actual historical revision, not a file fabricated after
the fact. Recovery creates no credential or standing authority.

### Boundaries

The worktree is read-only and contains only training fixtures. The retained
commit graph and tracker remain unchanged by reads.

### Author checks

Verify the current note is empty, the historical bytes are genuinely
recoverable, the tracker reference resolves once, and ordinary reads preserve
both history and tracker data.
