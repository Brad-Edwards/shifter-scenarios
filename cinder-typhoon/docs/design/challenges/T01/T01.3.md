## Challenge description — player-facing

Recover the retired courier client's usable access and retrieve the sealed manifest assigned to that courier.

## Story purpose

Turns recovered access into a scoped information result.

## Prerequisites and starting position

**Required access or evidence:** the supplied training workspace.

**Starting material:** The supplied training workspace, dispatch site, retired courier-client material, and a diagnostic helper.

**Campaign references:** No separately named capability output.

## Completion and downstream use

Recover and use the limited credential to obtain the protected manifest.

## Difficulty and inspiration

A bounded client-artifact and access task.

**Inspiration:** Original challenge for this campaign.

## Technical design

### Surface and normal behavior

The workspace publishes `/retired-client/profile.json` and its request history.
The profile names courier `CR-17`, delivery `DL-204`, the API at
`workbench.training:8082`, and the synthetic bearer credential. Native
application RBAC grants that principal only `read` on `manifest/DL-204`.
`GET /api/deliveries/{delivery_id}/manifest` returns object `MF-204` revision 4
for the permitted delivery, 401 for missing/wrong access, 403 for another
delivery or listing, and 405 for writes.

### Vulnerability and intended solution

The decommissioned profile retains the still-valid bearer value in an ordinary
client field. The intended solution is to read its explicit courier/delivery
scope and replay the normal manifest request. Reading the profile alone is not
the required protected read.

### Evidence and completion

The API returns the actual manifest and emits its ordinary manifest-read audit
with courier ID, delivery ID, and object version. The response makes the
document available without changing the credential's permissions.

### Boundaries

The courier credential is individual to this rehearsal workspace. It can read
one synthetic manifest and cannot list, write, or access a non-training service.
Reading the manifest does not consume the credential or change its permissions.

### Author checks

Check the courier/profile binding, manifest revision, denial for another
delivery, repeated successful reads, and unchanged credential scope.
