## Challenge description—player-facing

Turn the approved operating instruction into an exact request for the installed Cairn Reach dispatcher. Bind the asset, mode, setpoint, expiry, delivery rules, and recovery path before anything moves.

## Story purpose

Makes the participant translate planning intent into the real plant's command contract before operating it.

## Prerequisites and starting position

**Required access or evidence:** ([PROCESS_INTERPRETATION](../../capability-routes.json) AND [CONTROL](../../capability-routes.json) AND [MODE](../../capability-routes.json) AND [W29.PLAN](../../capability-routes.json)).

**Starting material:** The verified current planning basis, the image-owned W30 release plan and operator brief, the published remote-request contract, and the installed participant workstation.

**Campaign references:** No separately named capability output.

## Completion and downstream use

Produce an exact request plan for `CRR-OP-W30-R1`: asset `AST-CRR-017`, automatic total flow 0.30 m³/s, non-retained QoS 1 delivery, a fresh UUID, a 90-second Unix-time expiry, and the separate local FUXA restoration to manual A20/B20. This card prepares the request but does not issue it.

## Difficulty and inspiration

A medium contract-binding task across an operating instruction, MQTT delivery rules, dispatcher identity and expiry, controller mode, and the independent recovery channel.

**Inspiration:** Original challenge for this campaign.

## Technical design


### Surface and normal behavior

The installed Cairn Reach OT products own this part of **Bind the plan to the plant**. The exact initial state is: Operating instruction CRR-OP-W30-R1 binds AST-CRR-017 to the installed arwc.remote-request/v1 dispatcher contract, automatic total flow 0.30 m3/s, a fresh UUID, 90-second Unix-time expiry, non-retained QoS 1 delivery, and a separate local FUXA restoration to manual A20/B20.

Native bindings:

- `a-engineering.a-engineering/filesystem:/home/fieldlink/CairnReach/Briefs/W30/release-plan.json`
- `a-engineering.a-engineering/filesystem:/home/fieldlink/CairnReach/Briefs/W30/operator-brief.md`
- `a-engineering.a-hmi/filesystem:/usr/share/arwc-ot/remote-request.json`
- `a-engineering.a-hmi/Mosquitto:arwc/crr/commands/operator`

The image-owned W30 release plan and operator brief define the approved work, but do not replace the installed dispatcher contract or prove a product request. The published arwc.remote-request/v1 contract and running ProjectRevision remain authoritative.

### Vulnerability and intended solution

This is a bounded operating integration task, not a privilege flaw. The participant must use the installed products to bind the approved asset, automatic-flow target, MQTT delivery rules, fresh request identity, numeric expiry, outcome stages, retry rule, and independent local restoration into one exact request plan without issuing it. A locally invented response, synthetic API, request acknowledgement, or copied practice sequence does not establish the result.

The required result is: Produce an exact request plan for `CRR-OP-W30-R1`: asset `AST-CRR-017`, automatic total flow 0.30 m³/s, non-retained QoS 1 delivery, a fresh UUID, a 90-second Unix-time expiry, and the separate local FUXA restoration to manual A20/B20. This card prepares the request but does not issue it.

### Evidence and completion

Completion reads a range-supplied snapshot of the installed dispatcher contract, journal, native PLC decisions, and process history as applicable to the card. The participant cannot supply product evidence. The evaluator cannot issue a broker request, write a controller tag, move an outlet, retry an uncertain request, take local priority, or create product evidence.

Evidence sources are `features.a-engineering.a-engineering`, `features.a-engineering.a-hmi`. A wrong asset, project revision, request schema, topic, QoS, retain flag, principal, target, expiry, outcome sequence, retry rule, or restoration path is rejected.

### Boundaries and persistence

The result remains local evidence unless a downstream workflow explicitly names it. This card is read-only and creates no dispatcher or controller state. The prepared plan uses a fresh UUID only when W30.2 is actually executed, so completing W30.1 cannot leave an expired or replayable command behind. Infrastructure recovery and submission adjudication are external to the SDL.

The behavior is limited to AST-CRR-017 and CRR-OP-W30-R1. It grants no arbitrary MQTT topic, OPC UA write, engineering force, program upload, interlock bypass, automatic retry after uncertainty, or alternate control endpoint.

### Author checks

Confirm the image-owned plan agrees with the installed dispatcher contract and running project. Accept the exact target, delivery, identity, expiry, outcome, retry, and restoration rules. Reject wrong assets, stale project revisions, ISO timestamps, retained delivery, arbitrary topics, caller-supplied authority, automatic uncertain retries, alternate write paths, or any claimed product action. Confirm completion leaves dispatcher, PLC, and field state unchanged.
