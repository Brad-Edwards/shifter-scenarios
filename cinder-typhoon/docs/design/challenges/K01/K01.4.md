## Challenge description — player-facing

The local FieldKest helper has an unfinished support-report job. Make it produce a fresh inspection summary from the developer's supplied sample, with that sample's asset and revision correctly represented.

## Story purpose

Gives a newcomer a visible application result before a larger compromise.

## Prerequisites and starting position

**Required access or evidence:** the supplied KeplerOps developer foothold.

**Starting material:** The developer's working directory, browser profile, saved client settings, and local FieldKest tools.

**Campaign references:** No separately named capability output.

## Completion and downstream use

Produce the sample's inspection summary through the local helper, preserving its asset and revision binding. This is an introductory interface task with a visible result, not a claimed privilege escalation.

## Difficulty and inspiration

A documented, limited application action with immediate feedback.

**Inspiration:** Original challenge for this campaign.

## Technical design

### Surface and normal behavior
The local FieldKest helper accepts a supplied sample and renders an inspection summary with asset and revision fields from the training fixture.

### Vulnerability and intended solution
This is a normal-interface orientation task: the sample's shape is documented in local examples and the helper validates its asset/revision binding.

### Evidence and completion
The helper stores a fresh report receipt containing the expected sample ID, asset, revision, and output digest; local file edits do not score.

### Boundaries and reset
It reads only a card-local fixture directory and cannot call Forge, support, packages, or ARWC; reset replaces its player-local reports.

### Author checks
Test documented sample success, malformed sample rejection, correct asset/revision preservation, receipt generation, no external request, and reset.
