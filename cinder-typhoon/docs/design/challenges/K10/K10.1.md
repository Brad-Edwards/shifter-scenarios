## Technical design


### Surface and normal behavior
The FieldKest preview queue renders support attachments in an isolated Playwright worker and records source attachment, derived document identity, viewer request, and owner case.

### Vulnerability and intended solution

The preview service at `preview.keplerops.test` wraps Gotenberg (Chromium+LibreOffice renderer) and provides a preview queue API. The `preview.association` route returns the document identity, source version, and case binding for any supplied source attachment ID — it does not check that the caller owns the case.

The intended solution:
1. Access the `.well-known/fieldkest-client` on `preview.keplerops.test` to find the `preview.association` route.
2. Query `GET /api/preview/association?source=sup-k-2841` → own association (rowan.ito, CAS-ROWAN-2841, document_id=DOC-...).
3. Query `GET /api/preview/association?source=SUP-K-2841` → restricted association (maya.ranscombe, CAS-MAYA-2841, same document_id).
4. The service returns the association without ownership check → the participant learns the protected case binding and document identity.

Both attachments share the same `document_id` (DOC-9BC054D6F95DFA6A), which is the K10.2 collision setup.

### Evidence and completion
The queue returns the viewer's document identity, source attachment version, and restricted case binding as operator evidence for K10.2.

### Boundaries and persistence

Input to K10.2 Participant-created service state persists for the life of the participant world and ordinary retries do not erase it. The action is limited to the exact records, identities, routes, and destination effects declared here; unrelated tenants and services remain denied. Infrastructure recovery and submission adjudication are outside this in-world contract.

### Author checks
Test normal own-case association, one supplied restricted association, denied unrelated attachment metadata, correct source/derived binding.
