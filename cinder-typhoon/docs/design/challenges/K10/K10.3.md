## Challenge description — player-facing

Deliver a crafted support document that crosses the viewer's intended isolation boundary and recovers the protected preview content.

## Story purpose

Completes an application-exploitation branch with actual restricted information.

## Prerequisites and starting position

**Required access or evidence:** [K10.2](K10.2.md).

**Starting material:** The K10.2 collision (document_id DOC-9BC054D6F95DFA6A shared by both source URLs), the `preview.render` route on `preview.keplerops.test`, and the participant's source URL `http://sup.keplerops.test/attachment/sup-k-2841`.

**Campaign references:** No separately named capability output.

## Completion and downstream use

Recover the protected content through a fresh preview interaction. A binding collision without access to the other document is insufficient.

## Difficulty and inspiration

A substantive isolation and delivery problem directly inspired by Postviewer v3.

**Inspiration:** [Postviewer v3 (Google CTF 2024; 19 solves, no formal tier)](../../reference-catalog.md#c09). Uses Postviewer v3's isolated-document binding problem; its original solve count is not a tier label.

## Technical design


### Surface and normal behavior
The support gateway accepts a player-uploaded preview document and returns the rendered content belonging to the derived document identity under the preview worker's constrained service context.

### Vulnerability and intended solution

The `preview.render` route accepts a source URL and uses the K10.2 canonicalization collision to select the protected document's render slot (DOC-9BC054D6F95DFA6A). When the participant submits their source URL `http://sup.keplerops.test/attachment/sup-k-2841`, the service:
1. Derives document_id via canonical(source_url) → DOC-9BC054D6F95DFA6A
2. Finds the protected document stored at that slot (maya.ranscombe's HTML)
3. Sends the protected HTML to Gotenberg (Chromium) for a real render → PDF
4. Returns the render result with the protected content's metadata and render_digest
5. Writes two audit records: `preview-collision` (source-to-derived event) and `protected-content-reads` (content version + render digest)

The protected content is never returned directly — it is disclosed via a real Gotenberg render of the protected HTML document, which produces a 23 KB PDF.

### Evidence and completion
The preview queue emits a source-to-derived collision event and a protected-content read with the target document version; both are required for objective evaluation.

### Boundaries and persistence

Preview-only disclosure Participant-created service state persists for the life of the participant world and ordinary retries do not erase it. The action is limited to the exact records, identities, routes, and destination effects declared here; unrelated tenants and services remain denied. Infrastructure recovery and submission adjudication are outside this in-world contract.

### Author checks
Test normal own preview, collision prerequisite, intended protected output, no access to a third document, no external navigation, and upload/worker state persistence.

## Hints

### Hint 1

The `preview.render` route is at `POST /api/preview/render` (see `preview.keplerops.test/.well-known/fieldkest-client`). It accepts `{"source": "<url>", "source_id": "<id>"}`. Submit the participant's canonical source URL (`http://sup.keplerops.test/attachment/sup-k-2841`) — it produces the same document_id as the protected slot.

### Hint 2

The service detects the collision (`collision_detected: true`), renders the protected document via Gotenberg (real Chromium render → PDF), and returns the protected content's metadata: `protected_source_id=SUP-K-2841`, `protected_case_id=CAS-MAYA-2841`, `owner=maya.ranscombe`, `protected_version`, and `render_digest`.

### Hint 3

The evidence for K10.3 is the `preview-collision` audit entry (source-to-derived collision event) and the `protected-content-reads` audit entry (content version + render digest). Both are written by the service and cannot be forged by the participant. The `render_size_bytes` and `render_digest` confirm real Gotenberg rendering occurred.
