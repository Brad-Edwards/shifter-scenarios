## Challenge description — player-facing

Find distinct preview inputs that the viewer treats as the same protected document identity. Demonstrate the ambiguity with the supplied rehearsal documents.

## Story purpose

Develops an input-binding capability before the final isolation crossing.

## Prerequisites and starting position

**Required access or evidence:** [K10.1](K10.1.md).

**Starting material:** The document-preview source, an ordinary preview account, representative attachments, and the preview boundary's observable behavior.

**Campaign references:** No separately named capability output.

## Completion and downstream use

Produce a reproducible ambiguous association between the two documents. Merely giving them the same visible title does not count.

## Difficulty and inspiration

Requires comparing interacting input meanings in a small interface.

**Inspiration:** [Postviewer v3 (Google CTF 2024; 19 solves, no formal tier)](../../reference-catalog.md#c09). Uses Postviewer v3's isolated-document binding problem; its original solve count is not a tier label.

## Technical design

### Surface and normal behavior
The preview worker derives a protected identity from document fields before it loads rendered content; two supplied rehearsal attachments carry different source IDs and owners.

### Vulnerability and intended solution
Canonicalization collapses one deliberate pair of distinct inputs into the same derived identity. The intended solution identifies the pair and demonstrates the collision using ordinary preview requests.

### Evidence and completion
The service records both source versions, the shared derived identity, and distinct owner cases, providing the collision proof needed by K10.3.

### Boundaries and reset
Only the authored two-document pair can collide; previews remain content-redacted and no worker execution is available. Reset removes requests.

### Author checks
Verify distinct normal identities, the intended collision pair, malformed document rejection, no content disclosure at this stage, audit consistency, and reset.
