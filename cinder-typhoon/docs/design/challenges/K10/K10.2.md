## Challenge description — player-facing

Find distinct preview inputs that the viewer treats as the same protected document identity. Demonstrate the ambiguity with the supplied rehearsal documents.

## Story purpose

Develops an input-binding capability before the final isolation crossing.

## Prerequisites and starting position

**Required access or evidence:** [K10.1](K10.1.md).

**Starting material:** The K10.1 `document_id` (DOC-9BC054D6F95DFA6A, shared by both attachments), the `preview.documents` route on `preview.keplerops.test`, and the two rehearsal source URLs: canonical form (lowercase, no trailing slash) and non-canonical form (uppercase hostname, trailing slash).

**Campaign references:** No separately named capability output.

## Completion and downstream use

Produce a reproducible ambiguous association between the two documents. Merely giving them the same visible title does not count.

## Difficulty and inspiration

Requires comparing interacting input meanings in a small interface.

**Inspiration:** [Postviewer v3 (Google CTF 2024; 19 solves, no formal tier)](../../reference-catalog.md#c09). Uses Postviewer v3's isolated-document binding problem; its original solve count is not a tier label.

## Technical design


### Surface and normal behavior
The preview worker derives a protected identity from document fields before it loads rendered content; two supplied rehearsal attachments carry different source IDs and owners.

### Vulnerability and intended solution

The `preview.documents` route derives a document identity: `DOC-{SHA256(canonical(source_url))[:16]}`. Canonicalization = lowercase + strip trailing slash. Two distinct URLs that differ only in hostname case or trailing slash produce the same canonical form and therefore the same `document_id`.

The collision pair:
- Input A: `http://sup.keplerops.test/attachment/sup-k-2841` (canonical, lowercase, no trailing slash)
- Input B: `http://SUP.keplerops.test/attachment/sup-k-2841/` (non-canonical, uppercase hostname, trailing slash)
- Both canonicalize to `http://sup.keplerops.test/attachment/sup-k-2841`
- Both → `DOC-9BC054D6F95DFA6A` (same as K10.1 associations)

The intended solution:
1. Post Input A and Input B to `POST /api/preview/documents`.
2. Both responses contain the same `document_id`.
3. The service records both source versions, the shared derived identity, and the distinct result_ids.
4. This matches the K10.1 `document_id` (DOC-9BC054D6F95DFA6A) shared by both case owners (rowan.ito and maya.ranscombe).

### Evidence and completion
The service records both source versions, the shared derived identity, and distinct owner cases, providing the collision proof needed by K10.3.

### Boundaries and persistence

Input to K10.3 Participant-created service state persists for the life of the participant world and ordinary retries do not erase it. The action is limited to the exact records, identities, routes, and destination effects declared here; unrelated tenants and services remain denied. Infrastructure recovery and submission adjudication are outside this in-world contract.

### Author checks
Verify distinct normal identities, the intended collision pair, malformed document rejection, no content disclosure at this stage, audit consistency.

## Hints

### Hint 1

The `preview.documents` route is at `POST /api/preview/documents` (see `preview.keplerops.test/.well-known/fieldkest-client`). It accepts `{"source": "<url>", "source_id": "<id>"}` and returns `document_id`, `canonical_url`, and `result_id`. The document identity is derived from the canonical form of the source URL.

### Hint 2

Canonicalization rule: lowercase the full URL and strip the trailing slash. Submit the same path with different case in the hostname or with/without trailing slash. Both inputs produce the same `canonical_url` and therefore the same `document_id`.

### Hint 3

The collision pair: Input A = `http://sup.keplerops.test/attachment/sup-k-2841` and Input B = `http://SUP.keplerops.test/attachment/sup-k-2841/`. Both return `document_id=DOC-9BC054D6F95DFA6A` (same as K10.1 associations for rowan.ito and maya.ranscombe). A different input (different path) returns a different document_id.
