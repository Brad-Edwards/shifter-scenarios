## Technical design


### Surface and normal behavior

The engineering workbench owns this card. The participant implements the 16-bit VM from the architecture description and runs the 4 ordinary reference cases from W22.1 to verify their implementation.

**VM Architecture** (from the design):
- 4 × 16-bit registers (r0–r3), zero flag, 256 bytes of zero-initialized memory
- 6-byte instructions: u16 opcode, u8 dst, u8 src, u16 immediate (all little-endian)
- Opcodes: MOVI=0x01, LOAD8=0x02, XOR=0x03, ADD=0x04, ROTL=0x05, STORE8=0x06, JNZ=0x07, HALT=0xFF
- Arithmetic wraps at 16 bits; LOAD8 zero-extends `memory[(reg[src]+imm)&0xFF]`; STORE8 writes `reg[src] & 0xFF`; ROTL uses `imm&15`; JNZ adds signed imm to PC (not taken if zero); 4096 instruction limit
- Each case result: `{"registers": [r0,r1,r2,r3], "memory_40_80_sha256": "...", "steps": N}`

**Service route**: `POST https://process-view.arwc.test/api/sealed-viewers/current/execute`
- Body: `{"cases": [result_0, result_1, result_2, result_3]}`
- Gates on `viewer_observed=True` (W22.1 done)
- Validates all 4 case results match the reference
- Sets `vm_reconstructed=True` for W22.3+
- Returns VIEW-VM-R5 with the full VM spec

**Case programs**: The W22.1 `ordinary_cases` field includes 4 programs (`program_b64` only—the expected results are NOT returned). The participant implements the VM from the architecture description (or by analyzing the sealed-viewer binary), runs each program, computes the results, and submits them. The service validates against its own internal reference.

Native bindings:
- `a-engineering.a-engineering/process-view:process-view.arwc.test/api/sealed-viewers/current/execute`

The private service-loader contract is `content.arwc-a-engineering.w22-2-the-machine-inside-the-viewer`.

## Hints

The W22.1 service response includes `ordinary_cases`—4 programs (each `program_b64` is base64-encoded 6-byte-aligned bytecode). The expected results are NOT included. Implement the 16-bit VM from the architecture description (or by analyzing the sealed-viewer binary): 4 registers, 256 bytes memory, 6-byte instructions (u16 opcode, u8 dst, u8 src, u16 imm little-endian), 4096 instruction cap.

Implement all 8 opcodes with correct semantics: MOVI stores immediate into dst; LOAD8 reads `memory[(reg[src]+imm)&0xFF]` zero-extended; XOR/ADD are register OP register XOR/ADD immediate with 16-bit wrap; ROTL uses `imm&15` for the count; STORE8 writes `reg[src]&0xFF` to `memory[(reg[dst]+imm)&0xFF]`; JNZ adds signed imm to PC only if zero flag is false; HALT stops.
