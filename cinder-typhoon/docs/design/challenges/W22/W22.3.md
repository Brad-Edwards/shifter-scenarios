## Challenge description—player-facing

Open the sealed engineering project and recover the commissioning decision omitted from the business report. Establish which project revision the decision concerns.

## Story purpose

Completes the protected-project investigation with the engineering finding that explains the missing warning in the business report.

**Required access or evidence:** [W22.2](W22.2.md).

**Starting material:** The protected project-viewer delivery, ordinary viewing examples, and the engineering package associated with the current project evidence.

**Campaign references:** No separately named capability output.

The opened package also supplies the retained review helper, captured commissioning session, and matching archive context for W22.4. The decision provides optional context for W34; it supplies neither live revision evidence nor control authority.

## Technical design


### Surface and normal behavior

`a-engineering` and its `engineering-workbench` application own this card. The participant runs the full viewer program (from W22.1 `program_b64`) through their reconstructed 16-bit VM (from W22.2), derives the AES-256-GCM key from the final VM state, decrypts the sealed project package, and submits the derived key to the service.

**Service route**: `POST https://process-view.arwc.test/api/sealed-projects/current`
- Requires CORPORATE Bearer token
- Gates on `vm_reconstructed=True` (W22.2 done)
- Body: `{"project_id": "CRR-SEALED-PKG-R7", "key_hex": "<64-hex-chars>"}`
- Service decrypts the sealed-project.bin using the submitted key and validates the plaintext
- Sets `sealed_project_opened=True`
- Returns 201 with: `record_id=DEC-CRR-OG2-R7`, `project`, `revision`, `decision`, `review_helper`, `review_helper_b64`, `review_helper_sha256`

**Key derivation** (from the VM design):
- Run `program_b64` from the W22.1 viewer delivery through the reconstructed 16-bit VM to completion
- Key = SHA-256(ASCII "CRR-SEALED-PKG-R7" + 0x00 byte + memory[0x40:0x80] + LE16(r0) + LE16(r1) + LE16(r2) + LE16(r3))
- Package decryption: 12-byte nonce (first 12 bytes of sealed-project.bin), ciphertext+tag (remaining bytes), AAD = UTF-8 "CRR-SEALED-PKG-R7"
- A wrong key or project binding returns 409 without partial plaintext

**Sealed package**: The `package_b64` field in the W22.1 service response. The participant decodes it and uses it offline to verify their key before submitting.

Native bindings:
- `a-engineering.a-engineering/process-view:process-view.arwc.test/api/sealed-projects/current`

The private service-loader contract is `content.arwc-a-engineering.w22-3-the-decision-inside-the-sealed-project`. It freezes accepted and denied requests, state transition, persistence, and evidence; it does not seed a successful result.

### Vulnerability and intended solution

The authored condition is **VM-derived AES-GCM project recovery**. Run the sealed program from entry zero, then derive the AES key as SHA-256 over ASCII CRR-SEALED-PKG-R7, a NUL byte, memory[0x40:0x80], and LE16 encodings of registers r0..r3. Decrypt AES-256-GCM using the package's 12-byte nonce, UTF-8 project ID CRR-SEALED-PKG-R7 as AAD, and the trailing 16-byte tag. A wrong VM result or package binding returns one authentication failure without revealing partial plaintext. The hand build must preserve every named version, encoding, bound, validation order, identity, and unaffected field; substituting a generic vulnerable service would change the task.

The required result is: Recover the project-bound key, the readable engineering material, and its commissioning decision as one achievement. The opened package also supplies the retained review helper, captured commissioning session, and matching archive context for W22.4. The decision provides optional context for W34; it supplies neither live revision evidence nor control authority.
