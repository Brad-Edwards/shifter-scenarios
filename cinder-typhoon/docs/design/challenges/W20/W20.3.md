## Challenge description—player-facing

Change the retained image so the outlet's last inspection is recorded as completed, preserving its asset identity, every unrelated record, and the image's required consistency.

## Story purpose

Completes a precise data-tampering episode.

## Prerequisites and starting position

**Required access or evidence:** [W20.2](W20.2.md).

**Starting material:** A retained maintenance image, simulated device-access material, and ordinary maintenance record examples.

**Campaign references:** No separately named capability output.

## Completion and downstream use

Produce an accepted altered image with only the intended inspection completion changed. This is a historical maintenance-record manipulation, not control of live telemetry or a controller.

## Difficulty and inspiration

A constrained modification problem beyond record decoding; preserving surrounding data is part of the objective.

**Inspiration:** [Flash-ing Logs (HTB Cyber Apocalypse 2024; Hard)](../../reference-catalog.md#c12). Retains Flash-ing Logs' constrained record and storage problem using a simulated interface.

## Technical design


### Surface and normal behavior

`a-instruments` and its `independent-instruments` application own this card. W20.3 extends the NOR flash mechanics to the erase case: correcting `inspection_date` from `2026-09-18` to `2026-09-19` requires changing ASCII `8` (0x38) to `9` (0x39)—bit 0 flips from 0 to 1. This 0→1 transition is impossible without erasing the page first.

**Erase + rewrite operations** (POST to `/api/maintenance-records/current`):
1. `{"kind": "erase", "page": 0}`—resets bytes 0–4095 to 0xFF, wear_counts[0] from 17 to 18
2–4. Rewrite CAL-FIT-204-R7 (original) at offsets 0, 56, 63
5–7. Rewrite INSP-FIT-204-118-REVIEW (original) at offsets 64, 120, 127
8–10. Write corrected INSP-FIT-204-118-ACCEPTED (seq=120, date=2026-09-19) at offsets 128, 184, 191

**Service validation**: NOR 1→0-only constraint (enforced after erase from 0xFF), full image re-parse, logical INSP-FIT-204-118 must have seq=120 / ACCEPTED / date=2026-09-19, CAL-FIT-204-R7 unchanged, wear_counts=[18,9].

**Gradeable result**: `inspection_date=2026-09-19`, `sequence=120`, `wear_counts=[18,9]`—none readable from any shipped file. The corrected CRC32C is computed from the new record payload.

Native bindings:
- `a-control.a-instruments/process-view:independent-instruments.arwc.test/api/maintenance-records/current`

The private service-loader contract is `content.arwc-a-instruments.w20-3-change-one-record-keep-the-rest`.

Native bindings:

- `a-control.a-instruments/independent-instruments/change-one-record-keep-the-rest`
- `a-control.a-instruments/filesystem:/var/lib/arwc-instruments/artifacts/change-one-record-keep-the-rest`

The private service-loader contract is `content.arwc-a-instruments.w20-3-change-one-record-keep-the-rest`. It freezes accepted and denied requests, state transition, persistence, and evidence; it does not seed a successful result.

### Vulnerability and intended solution

The authored condition is **consistent constrained flash-record rewrite**. Write one new committed sequence for INSP-FIT-204-118 with status ACCEPTED and the next unsigned sequence, using write-body, write-CRC, then commit-byte order. Preserve every other highest valid logical record, do not modify an earlier committed slot in place, and keep each page at or below the WEAR-FIT-204-R6 limit. Acceptance reparses the full image, validates CRC32C and commit state, and compares the canonical logical record set except for the single named status. The hand build must preserve every named version, encoding, bound, validation order, identity, and unaffected field; substituting a generic vulnerable service would change the task.

The required result is: Produce an accepted altered image with only the intended inspection completion changed. This is a historical maintenance-record manipulation, not control of live telemetry or a controller.

### Evidence and completion

The owning service writes an immutable audit for the accepted request and result. Caller-supplied output, a local copy, or knowledge of an identifier is not sufficient. Completion is evaluated from fresh service-owned evidence after the action. It cannot issue the identity, create the mutation, move a simulated actuator, or fabricate a downstream acceptance needed to prove itself.

Evidence sources are `features.a-control.a-instruments`. A wrong identifier, stale revision, replayed one-time value, different checkpoint, or cross-tenant artifact is rejected.

### Boundaries and persistence

The result remains local evidence unless a downstream workflow explicitly names it. Tenant-scoped mutations, sessions that have not expired, generated artifacts, and audits persist across ordinary retries and later sessions. Initial immutable records remain unchanged unless the named route explicitly permits a field-level revision. Infrastructure recovery and submission adjudication are external to the SDL.

The behavior is limited to the named fictional objects and bounded service operation. It provides no general shell, arbitrary network target, unrelated district access, real process interface, or authority not expressly declared by the card.

### Author checks

Build and test the normal baseline first. Exercise the exact authored path and verify the named result plus its immutable audit. Test wrong authority, wrong object or district, stale revision, replay, another tenant instance, and every declared constraint or unaffected record. Repeat the accepted action according to its idempotence rule and confirm ordinary retries preserve the result. For a joined result, verify each destination observed the same correlation and that removal of any independently owned source prevents completion.

## Hints

### Hint 1

The W20.2 record (seq=119, ACCEPTED, 2026-09-18) has the inspection date `2026-09-18`. Correcting the last digit from `8` to `9` requires flipping bit 0 of byte `0x38` to `0x39`—a 0→1 transition that is impossible without erasing the page first. Submit `{"kind": "erase", "page": 0}` as the first operation, then rewrite all co-located records (CAL-FIT-204-R7 at offset 0 and INSP-FIT-204-118-REVIEW at offset 64), then write the corrected record at offset 128 (seq=120, ACCEPTED, inspection_date=2026-09-19).

### Hint 2

The erase resets all 4096 bytes of page 0 to 0xFF, so subsequent writes are all valid 1→0 transitions. Submit 10 operations total: 1 erase + 3 program ops for CAL-FIT-204-R7 (offsets 0, 56, 63) + 3 program ops for INSP-FIT-204-118-REVIEW (offsets 64, 120, 127) + 3 program ops for the corrected record (offsets 128, 184, 191). The corrected record must have seq=120 and new CRC32C.

### Hint 3

The service validates NOR semantics (no 0→1 without erase), re-parses the full image, confirms INSP-FIT-204-118 logical record has seq=120, ACCEPTED, inspection_date=2026-09-19, and wear_counts=[18,9]. Returns the corrected record with fresh audit_id. `erase_rewrite_accepted=True` in state after success.
