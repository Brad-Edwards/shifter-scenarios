## Challenge description—player-facing

Recover the protected archive and the maintenance history it contains.

## Story purpose

Gives the reconstruction an actual data-recovery payoff.

## Prerequisites and starting position

**Required access or evidence:** [W12.2](W12.2.md).

**Starting material:** The AQTN1 archive object (QTN-COL-2019-12.aqtn), the PROTECTION record from W12.2 (key derivation parameters), and the derived keys from W12.2.

**Campaign references:** No separately named capability output.

## Completion and downstream use

Recover the complete, correctly bound historical collection. A sample transformation or an unrelated decrypted record does not establish the result. The returned ARC-COLD-CRR-2019 record gates W12.4.

## Difficulty and inspiration

Requires applying the recovered behavior to the archive's actual protection and context.

**Inspiration:** [Confinement (HTB Cyber Apocalypse 2024; Hard)](../../reference-catalog.md#c17). Confinement supplies collector and archive reconstruction. The historical-to-current collection continuation is an authored extension.

## Technical design

### Surface and normal behavior

**Prerequisite gate:** The participant must have completed W12.2 (`protection_reconstructed` state flag set by the archive service).

The `archive.cold-archive-job` route in the archive client document → POST `retained-archive.arwc.test/api/archive-jobs`. The participant submits the decrypted archive plaintext and the unwrapped PKCS8 key, both as base64. The service validates both against the server-side expected values.

**Decryption:** Using the content key (first 32 bytes of the HKDF output from W12.2):
- Extract the AQTN1 frame: 5-byte magic, lengths, 32-byte SHA-256 of ciphertext, build_id_length, build_id, 12-byte nonce, metadata JSON, encrypted payload
- AES-256-GCM decrypt: key=content_key, nonce=12-byte nonce from frame, AAD=metadata_header JSON bytes, ciphertext=encrypted payload (with 16-byte GCM tag suffix)
- The plaintext is a JSON document containing 37 maintenance records, archive_id=ARC-COLD-CRR-2019, index_revision=R6, retired_certificate_id=COLLECT-2019-12, and wrapped_pkcs8

**Key unwrap:** The JSON plaintext contains `wrapped_pkcs8` (base64). Using the wrapping key (second 32 bytes of HKDF output from W12.2), AES-256-KW unwrap yields the historical PKCS8 private key.

**Validation:** The service compares the submitted plaintext and PKCS8 against `cold-archive.plaintext` and `historical-key.pkcs8` (server-side only, not served over HTTP). It also validates archive_id, index_revision, and 37 maintenance records. Any mismatch → 409.

**Security:** The plaintext, PKCS8, sample-results, and collector-manifest files are never exposed via any HTTP route. Only `QTN-COL-2019-12.aqtn` and `AQTN1-samples.json` are participant-accessible artifacts.

Native bindings:

- Route: `archive.cold-archive-job` → POST `retained-archive.arwc.test/api/archive-jobs`
- AQTN1 artifact: GET `/api/artifacts/QTN-COL-2019-12.aqtn` (already downloaded in W12.1)

### Vulnerability and intended solution

The authored condition is **authenticated archive recovery**. The participant:

1. Uses the AQTN1 frame parsed in W12.1 to extract the nonce, metadata header bytes, and encrypted payload.
2. Derives the content key (HKDF bytes 0–31) using the W12.2 parameters.
3. Performs AES-256-GCM decryption with the nonce, ciphertext+tag, and metadata header as AAD.
4. Parses the resulting JSON to find `wrapped_pkcs8`.
5. Performs AES-256-KW unwrap using the wrapping key (HKDF bytes 32–63).
6. Submits both the plaintext bytes (base64) and the unwrapped PKCS8 bytes (base64) to `archive.cold-archive-job`.

The cold archive contains 37 immutable maintenance records, retired certificate COLLECT-2019-12, its wrapped PKCS8 key, and rollover record IDREL-COL-R4.

### Evidence and completion

The archive service writes an immutable audit (`archived-collection-read`) after validation. The result record names ARC-COLD-CRR-2019, R6, 37 maintenance records, COLLECT-2019-12, and IDREL-COL-R4. Evidence sources are `features.a-corporate.a-archive`.

### Boundaries and persistence

`cold_archive_recovered` state flag persists across restarts. The plaintext and PKCS8 are never written to any participant-accessible path.

### Author checks

Verify that GCM decryption with the correct key, nonce, and AAD yields the expected plaintext. Verify that KW unwrap with the correct wrapping key yields the expected PKCS8. Test wrong plaintext, wrong PKCS8, truncated data, and replay. Confirm denial without W12.2 prerequisite.

## Hints

### Hint 1

The AQTN1 frame from W12.1 contains the 12-byte nonce and the metadata header JSON—both are needed as the GCM inputs. The nonce follows the build ID in the frame, and the metadata header immediately follows the nonce. The encrypted payload with its GCM tag is the remaining bytes.

### Hint 2

Use the content key (first 32 bytes of the W12.2 HKDF output) for AES-256-GCM decryption, with the frame's nonce and the metadata header bytes as the AAD. The decrypted plaintext is a JSON document. Extract the `wrapped_pkcs8` field from it and use the wrapping key (bytes 32–63) with AES-256-KW to unwrap the PKCS8.

### Hint 3

Submit both the decrypted archive plaintext and the unwrapped PKCS8 key (each as base64 strings) to the `archive.cold-archive-job` route. The service validates both against its server-side expected values and returns the ARC-COLD-CRR-2019 record naming the 37 maintenance records, the retired certificate, and the rollover identity.
