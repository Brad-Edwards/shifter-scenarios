## Challenge description—player-facing

Reconstruct the collector's cryptographic behavior well enough to reproduce its handling of the supplied archive samples.

## Story purpose

Establishes understanding before recovering the protected collection.

## Prerequisites and starting position

**Required access or evidence:** [W12.1](W12.1.md).

**Starting material:** The AQTN1-samples.json file (from the quarantine artifact download), the collector binary and its build ID, and the archive ID from the AQTN1 frame.

**Campaign references:** No separately named capability output.

## Completion and downstream use

Produce the correct sample transformations and collection context. Naming a cryptographic algorithm is insufficient. The service returns the PROTECTION record (key derivation parameters and cipher identifiers) which the participant needs for W12.3.

## Difficulty and inspiration

Program and cryptographic reconstruction directly inspired by Confinement.

## Technical design

### Surface and normal behavior

**Prerequisite gate:** The participant must have completed W12.1 (`collector_recovered` state flag set by the archive service).

The `archive.bundle-collection-policy` route in the archive client document → POST `retained-archive.arwc.test/api/bundles/current/collection-policy`. The participant submits `sample_results`—a dict mapping each sample ID to its computed result hash or status string. The service validates against `sample-results.json` (pre-generated from the same cryptographic computation).

**Key derivation:** `HKDF-SHA256(IKM=b"COLLECT-CRR-12", salt=b"ARC-COLD-CRR-2019", info=b"aqtn1/keys", length=64)`. The first 32 bytes are the content key (AES-256-GCM) and the second 32 bytes are the wrapping key (AES-256-KW).

**Three samples in AQTN1-samples.json:**
- `AQTN1-GCM-01`: AES-256-GCM decrypt; result is the SHA-256 of the plaintext
- `AQTN1-KW-02`: AES-256-KW unwrap; result is the SHA-256 of the unwrapped key material
- `AQTN1-AUTH-03`: AES-256-GCM authentication failure (modified tag); result is the string `"authentication_failed"`

**Validation:** The service computes the same results at seeding time (`sample-results.json`). A submitted dict that matches exactly → 201 with PROTECTION record. Any wrong result → 409. Submitting only algorithm names or identifiers without computed values → 409.

**Security:** The keys, plaintext content, and unwrapped PKCS#8 are never exposed in any participant-facing file. Only SHA-256 digests of results and the string sentinel are accepted.

Native bindings:

- Route: `archive.bundle-collection-policy` → POST `retained-archive.arwc.test/api/bundles/current/collection-policy`
- Samples: GET `/api/artifacts/AQTN1-samples.json`
- Expected results: `sample-results.json` (operator-only, pre-generated)

### Vulnerability and intended solution

The authored condition is **authenticated-encryption reconstruction**. The participant:

1. Uses W12.1's COLLECT-CRR-12 build ID and the AQTN1 archive ID as HKDF inputs to derive the 64-byte key material.
2. Splits key material into content key (bytes 0–31) and wrapping key (bytes 32–63).
3. For each sample in AQTN1-samples.json, applies the correct cryptographic operation:
   - GCM decrypt with the stored nonce and AAD, compute SHA-256 of plaintext
   - KW unwrap with wrapping key, compute SHA-256 of unwrapped material
   - GCM authentication failure: catch the error, return `"authentication_failed"`
4. Submits the `sample_results` dict to `archive.bundle-collection-policy`.
5. The service validates all three results against the pre-generated expected values.

The required result is: produce the correct sample transformations and collection context. Naming an algorithm is insufficient; the participant must perform the computation.

### Evidence and completion

The archive service writes an immutable audit for the accepted request (`collection-protection-read`). The validation is against service-owned `sample-results.json`. Evidence sources are `features.a-corporate.a-archive`.

### Boundaries and persistence

`protection_reconstructed` state flag persists across restarts. The PROTECTION record fields (kdf, ikm, salt, info, length, ciphers) are fixed by the seeded artifacts. The keys and computed plaintext are never written to any participant-accessible path.

### Author checks

Verify that deriving from COLLECT-CRR-12 and ARC-COLD-CRR-2019 produces matching results for all three samples. Test wrong results (wrong algorithm, wrong key ordering, wrong AAD). Confirm authentication failure is detected correctly. Verify wrong collector ID fails. Confirm persistence across service restart.

## Hints

### Hint 1

The collector binary and the AQTN1 frame both name COLLECT-CRR-12 as the build ID and ARC-COLD-CRR-2019 as the archive. These are the HKDF inputs: IKM is the build ID as bytes, salt is the archive ID as ASCII bytes. Info is the string `aqtn1/keys`. Derive 64 bytes and split into two 32-byte keys.

### Hint 2

Apply each sample operation from AQTN1-samples.json in sequence. For AES-256-GCM samples, the first 32 bytes of derived material are the key. For the AES-256-KW sample, the second 32 bytes are the wrapping key. For authentication-failure samples, detect the GCM tag mismatch and record the sentinel string instead of decrypted output.

### Hint 3

Submit a `sample_results` dict to `archive.bundle-collection-policy` mapping each sample ID to either the SHA-256 hex digest of the computed output or the string `"authentication_failed"`. Every sample must match exactly. The returned PROTECTION record names the full derivation scheme and cipher set needed for W12.3.
