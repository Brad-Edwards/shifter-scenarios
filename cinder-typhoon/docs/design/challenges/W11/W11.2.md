## Technical design


### Surface and normal behavior

The `planning.relation-exchange` route in the planning_data client document → `GET https://suppliers.arwc.test/api/resource/Task` (ERPNext Task API). The participant applies the W11.1 query template (filters by subject `%4417%`) using Jules Orswick's supplier credentials from W01.1. The result includes the restricted task TASK-XXXX (ASC-CRR-4417) under project PROJ-0001 (WO-CRR-4417), which Jules can access via an over-broad DocShare despite not being part of the internal engineering project.

The initial state: Task "ASC-CRR-4417 — Asset-work association AST-CRR-017" is in ERPNext under PROJ-0001 (WO-CRR-4417), linked to asset AST-CRR-017, with Jules DocShare read access. An ordinary Jules task query returns only handback and inspection tasks (TASK-2026-00013, TASK-2026-00014). The extended W11.1-template query adds the filter `[['subject','like','%4417%']]` which includes ASC-CRR-4417.

Native bindings:

- Route: `planning.relation-exchange` in the planning_data client doc → `GET https://suppliers.arwc.test/api/resource/Task`
- Apply W11.1 query template: filters=`[["subject","like","%4417%"]]`, fields include name/subject/project/description
- Authentication: Jules Orswick ERPNext credentials (Basic auth or session cookie) from W01.1
- Result: TASK-XXXX with subject=ASC-CRR-4417, project=PROJ-0001 (WO-CRR-4417), asset=AST-CRR-017
- This task IS REL-ASC-CRR-4417-R3: the association record linking asset to work order

### Vulnerability and intended solution

The authored condition is **framed backend-protocol construction**. Relation proxy accepts Neo4j Bolt magic 60 60 b0 17, version 5.4 negotiation, HELLO, and one PackStream RUN/PULL exchange; RUN map carries asset AST-CRR-017 and a client-certificate OU that is inserted as the unparameterized relationship type, while the bounded backend permits only the supplied asset key and read clauses. The hand build must preserve every named version, encoding, bound, validation order, identity, and unaffected field; substituting a generic vulnerable service would change the task.

The required result is: Obtain the actual restricted backend response for the supplied relation. A connection or syntactically plausible message is insufficient.

### Evidence and completion

The owning service writes an immutable audit for the accepted request and result. Caller-supplied output, a local copy, or knowledge of an identifier is not sufficient. Completion is evaluated from fresh service-owned evidence after the action. It cannot issue the identity, create the mutation, move a simulated actuator, or fabricate a downstream acceptance needed to prove itself.

Evidence sources are `features.a-corporate.a-data`. A wrong identifier, stale revision, replayed one-time value, different checkpoint, or cross-tenant artifact is rejected.

### Boundaries and persistence

The result remains local evidence unless a downstream workflow explicitly names it. Tenant-scoped mutations, sessions that have not expired, generated artifacts, and audits persist across ordinary retries and later sessions. Initial immutable records remain unchanged unless the named route explicitly permits a field-level revision. Infrastructure recovery and submission adjudication are external to the SDL.

The behavior is limited to the named fictional objects and bounded service operation. It provides no general shell, arbitrary network target, unrelated district access, real process interface, or authority not expressly declared by the card.

### Author checks

Build and test the normal baseline first. Exercise the exact authored path and verify the named result plus its immutable audit. Test wrong authority, wrong object or district, stale revision, replay, another tenant instance, and every declared constraint or unaffected record. Repeat the accepted action according to its idempotence rule and confirm ordinary retries preserve the result. For a joined result, verify each destination observed the same correlation and that removal of any independently owned source prevents completion.
