## Technical design


### Surface and normal behavior

The `planning.live-feed` route in the planning_data client document → `GET https://read-data.arwc.test/api/operating-history` (the real integration-gateway operating-history endpoint). The participant uses Basic auth credentials obtained from `planning.integration-session` (POST planning-data.arwc.test/api/integration-sessions) after the W06.3 Metabase session. The integration gateway (a-data-bridge at 10.77.62.20) proxies the session and returns operating-reader credentials for the live feed. With these credentials, the participant calls the operating-history endpoint and receives a fresh OT process observation.

Native bindings:

- Route: `planning.live-feed` in the planning_data client doc → `GET https://read-data.arwc.test/api/operating-history`
- Credential source: `planning.integration-session` → POST `/api/integration-sessions` → integration gateway issues operating-reader credentials
- Authentication: Basic auth with operating-reader credentials from the integration session
- Real endpoint: `read-data.arwc.test/api/operating-history` proxied to the native integration gateway (a-data-bridge)

Stale FEED-OG2-R19 and unrelated feeds are rejected; only fresh observations from the integration gateway qualify.

Integration gateway maps INT-CRR-08 and report binding REC-CRR-DP3-17 to live read feed FEED-OG2-R21; stale FEED-OG2-R19 remains reachable but is rejected as current evidence. The result must come from the declared source and bindings, not from a duplicate clue or pre-completed record.

The required result is: Resolve the active data binding and demonstrate a scoped read from the intended process feed. This supplies the integration variant of OT_READ; stale exports and unrelated feeds do not count. Process quantities and state separation are governed by `arwc-process-model.md`, specifically `ALLOC-2026-DP3`, `REC-CRR-DP3-17`.

### Evidence and completion

The owning service writes an immutable audit for the accepted request and result. Caller-supplied output, a local copy, or knowledge of an identifier is not sufficient. Completion is evaluated from fresh service-owned evidence after the action. It cannot issue the identity, create the mutation, move a simulated actuator, or fabricate a downstream acceptance needed to prove itself.

Evidence sources are `features.a-dmz.a-data-bridge`. A wrong identifier, stale revision, replayed one-time value, different checkpoint, or cross-tenant artifact is rejected.

### Boundaries and persistence

Supplies the integration variant of OT_READ. Tenant-scoped mutations, sessions that have not expired, generated artifacts, and audits persist across ordinary retries and later sessions. Initial immutable records remain unchanged unless the named route explicitly permits a field-level revision. Infrastructure recovery and submission adjudication are external to the SDL.

The behavior is limited to the named fictional objects and bounded service operation. It provides no general shell, arbitrary network target, unrelated district access, real process interface, or authority not expressly declared by the card.
