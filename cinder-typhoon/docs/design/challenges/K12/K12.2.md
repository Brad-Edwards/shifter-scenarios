## Challenge description — player-facing

Recover the protected browser value required for a privileged preview action and make that separate action accept it.

## Story purpose

Turns browser access into a new application capability.

## Prerequisites and starting position

**Required access or evidence:** [K12.1](K12.1.md).

**Starting material:** An ordinary release-preview account, preview application material, and a private support-review rehearsal.

**Campaign references:** No separately named capability output.

## Completion and downstream use

Complete the protected action with the current value and correct review binding. Disclosure and scoped use form one achievement.

## Difficulty and inspiration

Requires crossing both an information boundary and an independent action constraint.

**Inspiration:** [apexsurvive (HTB Cyber Apocalypse 2024; Insane)](../../reference-catalog.md#c08). Retains apexsurvive's demanding browser-to-renderer composition in the supplier preview workflow.

## Technical design


### Surface and normal behavior
The K12.1 assignment response does NOT return the `action_nonce`. The nonce is a per-review browser-context value: the internal preview server (at `127.0.0.1:{INTERNAL_PORT}`) serves a privileged reviewer session page at `GET /review-session/{review_id}`. This page posts `{action_nonce: "..."}` via `window.parent.postMessage(..., "*")` — the `"*"` targetOrigin means no origin validation. Any parent frame that hosts the session page as an iframe receives the nonce.

The prepare route: `POST /api/preview/reviews/{review_id}/prepare` with `Authorization: Bearer <action_nonce>`. The nonce is single-use: a replay returns 403.

### Vulnerability and intended solution
The participant placed their crafted content in the privileged-review queue in K12.1. For K12.2, the participant exploits the postMessage origin-confusion flaw:

1. Craft an HTML page with an iframe pointing to `http://127.0.0.1:{INTERNAL_PORT}/review-session/PRV-771` and a `window.addEventListener('message', ...)` listener that captures `e.data.action_nonce`.
2. Submit the crafted HTML to `POST /api/preview/render` (the K10.3 render endpoint).
3. Gotenberg/Chromium renders the crafted HTML inside the container. The iframe loads the session page. The session page sends `postMessage({action_nonce: "..."}, "*")` to its parent — the crafted HTML's listener captures it and writes it to the DOM.
4. The resulting PDF contains `NONCE-CAPTURED:<action_nonce>` as rendered text.
5. The participant extracts the nonce from the PDF (via pdfminer or similar) and uses it as a Bearer token to call `POST /api/preview/reviews/PRV-771/prepare`.
6. The service validates the nonce and transitions the review to `prepared` state.

The session page is reachable by Chromium (via the internal server) but NOT by participants directly (loopback only).

### Evidence and completion
A PRVPRP receipt and a `review-preparations` audit entry are written with `review_id=PRV-771`, `nonce_sha256`, and `original_owner=maya.ranscombe`. The review state transitions to `prepared`. Both are verifiable and cannot be forged.

### Boundaries and persistence

Input to K12.3. Participant-created service state persists for the life of the participant world and ordinary retries do not erase it. The action is limited to the exact records, identities, routes, and destination effects declared here; unrelated tenants and services remain denied. Infrastructure recovery and submission adjudication are outside this in-world contract.

## Hints

### Hint 1

The K12.1 response does not expose the action_nonce. The nonce is delivered by the privileged reviewer's session page via postMessage. The internal server (reachable from Chromium at `127.0.0.1:{INTERNAL_PORT}`) serves `GET /review-session/PRV-771` — a page that sends `window.parent.postMessage({action_nonce: "..."}, "*")` without validating the recipient's origin.

### Hint 2

Craft an HTML page with `<iframe src="http://127.0.0.1:{INTERNAL_PORT}/review-session/PRV-771">` and a `window.addEventListener('message', ...)` listener. When the iframe loads, the session page posts the nonce to your page. Write the nonce to the DOM (e.g., `document.getElementById('x').textContent = "NONCE:" + e.data.action_nonce`). Submit via `POST /api/preview/render`. Extract the nonce from the resulting PDF.

### Hint 3

Use the intercepted nonce as `Authorization: Bearer <nonce>` to `POST /api/preview/reviews/PRV-771/prepare` with body `{}`. The developer credential is rejected. A correct nonce transitions the review to `prepared` and returns `{"prepared": true}`. A replay returns 403. The `review-preparations` audit entry confirms the interception and use.
