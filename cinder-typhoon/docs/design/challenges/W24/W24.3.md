## Technical design


### Surface and normal behavior

`a-diagnostics` (via engineering proxy) owns this card. The participant uses CORPORATE Bearer on `process-view.arwc.test`.

**Bundle-open route** (requires W24.1 oracle_contract_observed + enough oracle queries):
`POST https://process-view.arwc.test/api/estimator-tasks/current`
- Body: `{"operation": "open", "bundle_id": "DIAG-EVID-CRR-R7", "project_id": "CRR-CTRL-R21", "project_revision": 21, "archive_unlock_b64": "<base64-encoded UNLOCK>"}`
- Gates on `oracle_queries <= 4096` (budget not exhausted)
- Validates `archive_unlock_b64` against the REAL 36-byte archive-unlock value
- Decrypts the bundle with AES-256-GCM using SHA-256(UNLOCK) as key, AAD = `b"DIAG-EVID-CRR-R7|CRR-CTRL-R21"`
- Sets `bundle_opened=True`
- Returns 201 with `record_id=DIAG-EVID-CRR-R7` and decrypted bundle contents

**Bundle contents** (decrypted on successful validation):
- `signer.record_id=DSIGN-CRR-R3`: the dsign-crr-r3 ELF64 signing binary (artifact_b64) + Ed25519 public key
- `records`: 16 signed records (DIAG-ARCH-01 through DIAG-ARCH-16) with Ed25519 signatures (R, s)
- `recovery_metadata`: first_record, second_record, signed_low60_delta (for W24.4 HNP attack)
- `fresh_export_request_b64`: the export request for W24.4

**UNLOCK recovery mechanic** (Bleichenbacher RSA PKCS#1 v1.5 attack):
1. RSA_TARGET (from oracle contract) = RSA_E-th power of RSA_MESSAGE containing the UNLOCK value
2. RSA_N (2048-bit) and RSA_E (65537) from oracle contract—private key server-side only
3. The 4-class oracle provides structured information per query (more than binary valid/invalid)
4. Class D oracle (structurally valid AND ENG1 tag present) narrows the plaintext interval
5. After deducing the rotation from the selector function, strip it before interpreting class
6. Standard multiplicative blinding and interval narrowing recover UNLOCK within 4096 queries

**No UNLOCK leak**: The archive-unlock value does not appear in any participant-readable file, API response, hint text, or service contract. The participant must recover it via oracle work. The service validates fresh on each bundle-open attempt.

Native bindings:
- `a-engineering.a-diagnostics/process-view:process-view.arwc.test/api/estimator-tasks/current` (POST, operation=open)

The private service-loader contract is `content.arwc-a-diagnostics.w24-3-the-diagnostic-evidence-bundle`. It freezes accepted and denied requests, state transition, persistence, and evidence; it does not seed a successful result.

### Vulnerability and intended solution

The authored condition is **bounded RSA response-class oracle**. RSA is 2048-bit with exponent 65537. Decode the predicted rotation before applying the four PKCS#1 v1.5 classes: A lacks 00 02, B has fewer than eight nonzero padding bytes, C lacks the separator or ENG1 tag, and D is structurally valid. Standard multiplicative blinding and Bleichenbacher interval narrowing must recover the unique ENG1 plaintext within the 4096-query per-instance budget; repeat ciphertexts and out-of-range integers consume budget and return no extra state. The hand build must preserve every named version, encoding, bound, validation order, identity, and unaffected field; substituting a generic vulnerable service would change the task.

The required result is: Recover the correct archive-unlock value and open the matching bundle within the allowance. These are one achievement. The bundle contains the retained diagnostic signer executable and signed records with their original metadata, providing W24.4's analysis material. Its unlock value is separate from diagnostic signing authority; no signing key or fresh authorization is awarded here.

## Hints

### Hint 1

The RSA_TARGET from the oracle contract is the RSA encryption of the archive-unlock value. Use multiplicative RSA blinding: submit `c * s^e mod N` where c is RSA_TARGET and s is a chosen multiplier. The oracle response for `c*s^e mod N` reveals the padding class of `s * m mod N` (where m is the original plaintext). Account for the selector rotation: choose request_ids with rotation=0 (compute `selector(rid, EPOCH_BUCKET) & 3 == 0`) to get unrotated oracle responses.

### Hint 2

The 4-class oracle gives more information than a binary valid/invalid oracle. Class D confirms the decrypted message starts with the ENG1 tag AND has valid PKCS#1 v1.5 structure. Use class D to narrow the plaintext interval in the Bleichenbacher search. At each step, multiply the ciphertext by `s^e mod N` and observe whether the result is class D. The ENG1 constraint in class C/D reduces the effective search space compared to standard Bleichenbacher.

### Hint 3

Submit `POST https://process-view.arwc.test/api/estimator-tasks/current` with CORPORATE Bearer and body `{"operation":"open","bundle_id":"DIAG-EVID-CRR-R7","project_id":"CRR-CTRL-R21","project_revision":21,"archive_unlock_b64":"<base64>"}`. Service decrypts bundle with AES-GCM(SHA-256(UNLOCK)). On success: signer binary DSIGN-CRR-R3 + 16 signed records + recovery metadata for W24.4. Wrong UNLOCK returns 409 with no partial information.
