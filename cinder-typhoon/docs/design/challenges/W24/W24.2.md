## Technical design


### Surface and normal behavior

`a-diagnostics` (via engineering proxy) owns this card. The participant uses CORPORATE Bearer on `process-view.arwc.test`.

**Oracle query route** (from W24.1, selector_predicted=True required):
`POST https://process-view.arwc.test/api/estimator-tasks/current`
- Body: `{"operation": "oracle", "ciphertext": "<512-hex>", "request_id": "<16-hex>", "epoch_bucket": 1770000042}`
- The oracle performs REAL RSA-2048 PKCS#1 v1.5 decryption of the submitted ciphertext
- Classifies the decrypted plaintext: A (bad prefix), B (<8 nonzero padding bytes), C (bad separator/tag), D (valid)
- Applies xorshift128+ rotation: `observed = shift(raw_class, selector(request_id, EPOCH_BUCKET) & 3)`
- Returns: `{"observed_class": "A"/"B"/"C"/"D", "queries_used": N, "queries_remaining": M}`
- Rejects duplicate ciphertexts (SHA-256 deduplication), exhausted allowance, wrong epoch_bucket

**Oracle constraints**:
- `epoch_bucket` MUST equal the server's current EPOCH_BUCKET (from oracle contract)
- `request_id` = 16-hex-character string (the participant chooses)
- `ciphertext` = 512-hex-character RSA-2048 ciphertext (the participant supplies or crafts)
- Maximum 4096 total queries; replayed ciphertext digests are rejected

**Selector function** (xorshift128+, same as W24.1):
```
s0 = (request_id ^ 0x9e3779b97f4a7c15) & MASK64
s1 = (epoch_bucket ^ 0xbf58476d1ce4e5b9) & MASK64
x, y = s0, s1
x = (x ^ (x << 23)) & MASK64
s1 = (x ^ y ^ (x >> 17) ^ (y >> 26)) & MASK64
output = (s1 + y) & MASK64; rotation = output & 3
```

**Work item**: For each oracle query the participant submits, they should PREDICT the `observed_class` BEFORE submitting. The prediction = `shift(raw_class, rotation)` where `raw_class` is known from the ciphertext's PKCS#1 v1.5 structure and `rotation` comes from the selector. The oracle confirms or refutes.

**Key observation**: The RSA target ciphertext `RSA_TARGET` from the oracle contract corresponds to the UNLOCK plaintext needed to open the diagnostic bundle. Querying RSA_TARGET reveals its `observed_class`; knowing the rotation reveals its `raw_class`. With enough oracle queries of modified ciphertexts, the plaintext can be recovered (W24.3).

Native bindings:

### Vulnerability and intended solution

The authored condition is **xorshift128+ response-selector prediction**. Initialize s0=request_id_low64 XOR 0x9e3779b97f4a7c15 and s1=epoch_bucket XOR 0xbf58476d1ce4e5b9. For each xorshift128+ step set x=s0, y=s1, s0=y, then x=x XOR (x<<23), s1=x XOR y XOR (x>>17) XOR (y>>26), and output=(s1+y), with every value and shift truncated to 64 bits. The externally observed response code is (padding_class_ordinal + (next_output & 3)) mod 4, where A,B,C,D have ordinals 0..3. Supplied request IDs and bucket boundaries freeze parsing, transition, addition, and rotation of the four classes. The hand build must preserve every named version, encoding, bound, validation order, identity, and unaffected field; substituting a generic vulnerable service would change the task.

The required result is: Demonstrate correct selection predictions under the stated conditions. Replaying a known sequence does not establish the result.

## Hints

Call `POST https://process-view.arwc.test/api/estimator-tasks/current` with CORPORATE Bearer and body `{"operation":"oracle","ciphertext":"<512-hex>","request_id":"<16-hex>","epoch_bucket":1770000042}`. ### Hint 2

Before submitting each query, predict the `observed_class`: `observed = shift(raw_class, rotation)` where `rotation = selector(request_id, epoch_bucket) & 3` (xorshift128+ from W24.1). For a class-D ciphertext and rotation=2, predicted `observed_class = B`. Verify that the oracle confirms your prediction. Use unique ciphertexts or unique request_ids for each query to avoid deduplication rejection.

### Hint 3

The `target_ciphertext` in the oracle contract is the RSA encryption of the UNLOCK plaintext needed to open the diagnostic evidence bundle. Submit it to the oracle (with any valid request_id and epoch_bucket) to observe its class. With a sufficient number of oracle queries and RSA PKCS#1 v1.5 structure knowledge, the UNLOCK value can be recovered for W24.3.
