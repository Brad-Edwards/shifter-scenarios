## Challenge description — player-facing

Distinguish the obsolete field-service reference from the active process-data service and identify the current read contract.

## Story purpose

Makes the player resolve product history before relying on an endpoint.

## Prerequisites and starting position

**Required access or evidence:** W13.SESSION (contractor session from W13.4), W14.1 (field bag with service manifest).

**Starting material:** The field bag from W14.1 containing the service manifest, and the `field.instrument` route in the field-gateway client document.

**Campaign references:** No separately named capability output.

## Completion and downstream use

Recover the active service and revision binding. The service manifest shows `field-read-legacy.arwc.test` as retired (fieldbag/v1) and `process-read.arwc.test` as active (process-read/v2, cbor, inspection-scoped). The revision is 21.

## Difficulty and inspiration

A bounded revision and service-identity join.

**Inspiration:** Original challenge for this campaign.

## Technical design

### Surface and normal behavior

**Nextcloud source:** The service manifest is embedded in the FIELD-BAG-CRR-4417-R3.json Nextcloud document (from W14.1). The contractor portal uses `state["field_bag"]["service_manifest"]` for the `field.instrument` route.

**Route:** `field.instrument` → GET `field-gateway.arwc.test/api/instruments/current` (proxied through the contractor portal with the correct Host header).

**Legacy endpoint:** `field-read-legacy.arwc.test` returns HTTP 410 for all requests — it is genuinely retired, not a canned pointer.

**Manifest fields:**
- `record_id`: FIELD-SERVICES-R21
- `revision`: 21
- Services:
  - `{"host": "field-read-legacy.arwc.test", "protocol": "fieldbag/v1", "status": "retired"}`
  - `{"host": "process-read.arwc.test", "protocol": "process-read/v2", "status": "active", "encoding": "application/cbor", "authentication": "inspection-scoped"}`

**Gate:** Contractor session required. Without a valid contractor session, the instruments route returns HTTP 403.

Native bindings:

- Route: `field.instrument` → GET `field-gateway.arwc.test/api/instruments/current` (via contractor portal)
- Manifest source: Nextcloud `FIELD-BAG-CRR-4417-R3.json` service_manifest field
- Legacy endpoint: `field-read-legacy.arwc.test` → HTTP 410 (retired)

### Vulnerability and intended solution

This is an exact discovery and service-reconciliation task. The participant:
1. Tries `field-read-legacy.arwc.test` → receives 410 (genuinely retired)
2. Calls `field.instrument` with the contractor session → receives the live manifest
3. Identifies `process-read.arwc.test` as the active process-read/v2 service at revision 21

The active service requires CBOR encoding and inspection-scoped authentication (W14.3).

### Evidence and completion

The contractor portal writes an audit entry when the instruments route is called. Evidence sources are `features.a-maintenance.a-contractors`.

### Boundaries and persistence

`manifest_observed` state flag persists across restarts. The manifest is sourced from the same Nextcloud field bag as W14.1.

### Author checks

Verify instruments returns correct manifest with retired/active services. Verify legacy endpoint returns 410. Verify wrong session returns 403. Verify manifest is from Nextcloud (not canned constant).

## Hints

The field-read-legacy.arwc.test endpoint referenced in the W14.1 field bag is retired — it returns HTTP 410 for all requests. Use the field.instrument route in the field-gateway client document instead.

### Hint 2
