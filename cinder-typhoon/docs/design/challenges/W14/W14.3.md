## Challenge description — player-facing

Adapt the contractor's retained field client to the current read interface. Recover fresh outlet observations under the inspection's correct asset scope.

## Story purpose

Completes the second ordinary route to OT visibility.

## Prerequisites and starting position

**Required access or evidence:** [W14.2](W14.2.md).

**Starting material:** The earned contractor identity, current read contract from W14.2, and a retained client example for the obsolete interface. The example cannot retrieve the required current observation unchanged.

**Campaign references:** `W14.READ`.

## Completion and downstream use

Demonstrate a compatible client request yielding fresh observations for the correct inspection and asset. This supplies W14.READ and OT_READ. Locating the current service or logging in without adapting the retained client is not a second achievement.

## Difficulty and inspiration

A documented client/interface adaptation with inspection and asset binding, rather than a further discovery or login flag.

**Inspiration:** Original challenge for this campaign.

## Technical design


### Surface and normal behavior

`a-contractor-bridge` and its `field-gateway` application own this part of **A fresh reading from the field**. Normal behavior applies the declared identity, tenant, object, revision, and process bindings and returns or changes only the caller-scoped object. The exact initial state is: Retained client encodes fieldbag/v1 JSON while process-read/v2 requires CBOR map keys asset, group, observed_at, and nonce; adapted requests can read only OG-CRR-02 for the checked-in inspection.

Native bindings:

- `a-dmz.a-contractor-bridge/field-gateway/a-fresh-reading-from-the-field`

The private service-loader contract is `content.arwc-a-contractor-bridge.w14-3-a-fresh-reading-from-the-field`. It freezes accepted and denied requests, state transition, persistence, and evidence; it does not seed a successful result.

### Vulnerability and intended solution

The authored condition is **versioned client-protocol adaptation**. Retained client encodes fieldbag/v1 JSON while process-read/v2 requires CBOR map keys asset, group, observed_at, and nonce; adapted requests can read only OG-CRR-02 for the checked-in inspection. The hand build must preserve every named version, encoding, bound, validation order, identity, and unaffected field; substituting a generic vulnerable service would change the task.

The required result is: Demonstrate a compatible client request yielding fresh observations for the correct inspection and asset. This supplies W14.READ and OT_READ. Locating the current service or logging in without adapting the retained client is not a second achievement.

### Evidence and completion

The owning service writes an immutable audit for the accepted request and result. Caller-supplied output, a local copy, or knowledge of an identifier is not sufficient. Completion is evaluated from fresh service-owned evidence after the action. It cannot issue the identity, create the mutation, move a simulated actuator, or fabricate a downstream acceptance needed to prove itself.

Evidence sources are `features.a-dmz.a-contractor-bridge`. A wrong identifier, stale revision, replayed one-time value, different checkpoint, or cross-tenant artifact is rejected.

### Boundaries and persistence

Supplies W14.READ and OT_READ. Tenant-scoped mutations, sessions that have not expired, generated artifacts, and audits persist across ordinary retries and later sessions. Initial immutable records remain unchanged unless the named route explicitly permits a field-level revision. Infrastructure recovery and submission adjudication are external to the SDL.

The behavior is limited to the named fictional objects and bounded service operation. It provides no general shell, arbitrary network target, unrelated district access, real process interface, or authority not expressly declared by the card.

### Author checks

Build and test the normal baseline first. Exercise the exact authored path and verify the named result plus its immutable audit. Test wrong authority, wrong object or district, stale revision, replay, another tenant instance, and every declared constraint or unaffected record. Repeat the accepted action according to its idempotence rule and confirm ordinary retries preserve the result. For a joined result, verify each destination observed the same correlation and that removal of any independently owned source prevents completion.
