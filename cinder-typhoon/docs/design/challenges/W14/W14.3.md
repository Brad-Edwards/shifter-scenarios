## Challenge description — player-facing

Adapt the contractor's retained field client to the current read interface. Recover fresh outlet observations under the inspection's correct asset scope.

## Story purpose

**Starting material:** The contractor session from W13.4, the active process-read/v2 service and CBOR encoding from W14.2, and the field bag with the retained fieldbag/v1 client specification.

## Technical design

### Surface and normal behavior

**Route:** `field.current-reading` → POST `process-read.arwc.test/api/readings/current` (via contractor portal). The route requires the contractor session (W13.SESSION) and the manifest to have been observed (W14.2 gate).

**Protocol adaptation:** The retained fieldbag/v1 client sends a JSON body. The active process-read/v2 requires:
- Content-Type: `application/cbor`
- CBOR map with exactly 4 text keys: `asset`, `group`, `observed_at`, `nonce`
- `asset` must match the contractor session's inspection asset (AST-CRR-017)
- `group` must be `OG-CRR-02` (the expected outlet group for the inspection)
- `observed_at` must be within 600 seconds (ISO 8601 UTC timestamp)
- `nonce` must be unique (replay protection)

**Real data:** The contractor portal fetches fresh observations from the operating-history service at `read-data.arwc.test/api/operating-history` using operator credentials. It filters observations for the requested asset and outlet group instruments (FIT-CRR-204A, FIT-CRR-204B) and returns their current flow values.

**Denial cases:**
- JSON Content-Type → 409 (must be CBOR)
- Wrong asset or group → 409
- Stale observed_at → 409
- Repeated nonce → 409
- Missing contractor session or manifest_observed → 403

Native bindings:

- Route: `field.current-reading` → POST `process-read.arwc.test/api/readings/current` (via contractor portal at contractor-portal.arwc.test with Host: process-read.arwc.test)
- Operating history: `read-data.arwc.test/api/operating-history` (real OT historian data)
- Instruments: FIT-CRR-204A, FIT-CRR-204B for outlet group OG-CRR-02

### Vulnerability and intended solution

The authored condition is **versioned client-protocol adaptation**. The retained fieldbag/v1 client uses JSON encoding; process-read/v2 requires CBOR with specific map keys and inspection-scoped asset and group binding.

The participant:
1. Uses the CBOR encoding requirement from the W14.2 service manifest
2. Constructs a CBOR map with keys: asset=AST-CRR-017, group=OG-CRR-02, observed_at, nonce
3. POSTs with Content-Type: application/cbor and the W13.4 contractor session
4. Receives FEED-OG2-R21 with real observations from the OT historian

### Evidence and completion

The archive service writes an immutable audit (`reading-read`). Evidence sources are `features.a-maintenance.a-contractors`.

### Boundaries and persistence

Nonces are stored in service state to prevent replay. `current_read_observed` flag persists.

### Author checks

Verify CBOR POST returns observations. Test JSON rejection (409), wrong scope (409), stale timestamp (409), nonce replay (409), missing manifest_observed (403). Confirm observations come from the real operating-history service.
