## Challenge description — player-facing

Open the supplied native controller project and commissioning note. Identify the
project, main program, scheduled task, declared revision, and runtime target.

## Story purpose

Introduces a controls engineer's real project structure before asking the
participant to reason about its running counterpart.

## Prerequisites and starting position

**Required access or evidence:** [OT_READ](../../capability-routes.json).

**Starting material:** The actual `arwc-site` OpenPLC project, the Cairn Reach
project handover, and commissioning note CRR-PLC-COM-364 on the participant
engineering workstation.

**Campaign references:** No separately named capability output.

## Completion and downstream use

Identify the saved project's actual structure, declared ProjectRevision, task
interval, and configured Runtime v4 target. This establishes the saved-project
side of the W21 comparison; it does not establish what is running.

## Difficulty and inspiration

A bounded orientation task with one supplied project and one note. The
participant must use the real OpenPLC project structure rather than a synthetic
record, but every required value is directly inspectable. This keeps the
original Easy difficulty.

**Research basis:** OpenPLC Editor projects contain IEC 61131-3 programs and
device configuration, and the Editor turns that project into the Runtime v4
program package. See the official [Editor integration
workflow](https://github.com/Autonomy-Logic/openplc-runtime/blob/main/docs/EDITOR_INTEGRATION.md)
and [Runtime v4 compilation
flow](https://github.com/Autonomy-Logic/openplc-runtime/blob/main/docs/COMPILATION_FLOW.md).

## Technical design


### Surface and normal behavior

The installed Cairn Reach OT products own this part of **The project and the note**. The exact initial state is: Image-owned handover CRR-PLC-COM-364 identifies native project arwc-site, main FBD program, `T#100ms` task, ProjectRevision 364, and OpenPLC Runtime v4 target 172.29.63.20; the participant must confirm those claims in the supplied native project.

Native bindings:

- `a-engineering.a-engineering/filesystem:/home/fieldlink/CairnReach/controller`
- `a-engineering.a-engineering/filesystem:/home/fieldlink/CairnReach/Briefs/W21`
- `a-engineering.a-engineering/OpenPLC-Editor:project-structure-and-device-configuration`

The image-owned W21 handover and commissioning note are starting material only. The supplied OpenPLC project's own FBD, resource task, and Device Configuration remain authoritative; no private service-loader route duplicates them.

### Vulnerability and intended solution

This is a bounded operating observation and interpretation task, not a privilege flaw. The participant must use the installed products to identify the saved native project from its actual program, scheduled task, declared ProjectRevision, and Runtime v4 device configuration. A copied value, inferred default, or synthetic API response does not establish the result.

The required result is: Identify the saved project's actual structure, declared ProjectRevision, task interval, and configured Runtime v4 target. This establishes the saved-project side of the W21 comparison; it does not establish what is running.

### Evidence and completion

Completion compares the participant's observation with fresh, read-only product records. Product evidence is supplied by the range, never by the participant, and the completion path cannot write a tag, issue a command, change controller state, or create its own product evidence.

Evidence sources are `features.a-engineering.a-engineering`. A wrong project structure, task interval, declared revision, runtime target, or address is rejected.

### Boundaries and persistence

The result remains local evidence unless a downstream workflow explicitly names it. The task is read-only and creates no process mutation to retain or reset. Ordinary historian retention continues independently. Infrastructure recovery and submission adjudication are external to the SDL.

The behavior is limited to the installed Cairn Reach products, the named asset, and the supplied participant material. It provides no alternate challenge service, simulated completion endpoint, or authority not already present in the OT environment.

### Author checks

Verify the healthy baseline through the participant workstation. Complete the card using only the declared native products and image-owned starting material. Confirm that a matching post-action product snapshot accepts the observation, while a wrong asset, stale observation, mismatched native identity, participant-supplied product evidence, or missing required product source prevents completion. Confirm the flow does not upload, start, stop, force, or otherwise change controller state and reset leaves no challenge-created process state.

## Hints

### Hint 1

Start in `~/CairnReach/Briefs/W21/`, then open
`~/CairnReach/controller` in OpenPLC Editor. The note tells you which project
claims must be checked; it is not proof of the running program.

### Hint 2

Review the main FBD, the scheduled resource task, and Device Configuration.
Keep the project name, program name, language, interval, revision, target, and
runtime address together.

### Hint 3

`ProjectRevision` is declared in the project logic. Device Configuration owns
the Runtime v4 target and address. Do not compile, upload, start, stop, or force
anything for this card.
