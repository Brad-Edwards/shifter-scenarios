## Challenge description — player-facing

Reconcile one outlet flow point across its Modbus register, OpenPLC address, raw type and scale, PLC value, OPC UA identity, and historian series.

## Story purpose

Teaches the real boundary between wire address, controller variable, engineering value, and historian identity.

## Prerequisites and starting position

**Required access or evidence:** [OT_READ](../../capability-routes.json).

**Starting material:** The verified CRR-IO-R364 register from W18.1, the native OPC UA browser, and the historian tag catalog.

**Campaign references:** No separately named capability output.

## Completion and downstream use

Produce the complete `FIT-CRR-204B` binding from Modbus function and PDU offset through `%IW5`, `FlowBRaw`, scaling, `FlowBM3s`, the stable OPC UA NodeId, and `flow_b_m3s`. Each native source must agree.

## Difficulty and inspiration

One named point and a supplied register keep the search bounded. Correctly separating zero-based Modbus addressing, IEC addressing, raw scaling, and stable native identity preserves the Easy allocation.

**Inspiration:** Original challenge for this campaign.

**Technical grounding:** [Modbus Application Protocol V1.1b3](https://www.modbus.org/modbus-specifications) and the [Telegraf OPC UA input](https://github.com/influxdata/telegraf/tree/master/plugins/inputs/opcua).

## Technical design


### Surface and normal behavior

The installed Cairn Reach OT products own this card. Using the CRR-IO-R364 register from W18.1, the participant maps FIT-CRR-204B through all seven layers, confirming each with a native source.

**Complete FIT-CRR-204B binding (all from register and catalog):**

| Layer | Value | Source |
| ----- | ----- | ------ |
| Physical instrument | FIT-CRR-204B | tag-register.csv |
| Modbus function | FC4 (input registers) | tag-register.csv |
| PDU offset (zero-based) | 5 | tag-register.csv |
| OpenPLC IEC address | %IW5 | tag-register.csv |
| Raw variable | FlowBRaw (UINT) | tag-register.csv |
| Scale | 10000 counts/m³/s | tag-register.csv |
| Engineering variable | FlowBM3s | tag-register.csv |
| OPC UA NodeId | `nsu=urn:arwc:crr:tags;s=CRR.FlowBM3s` | OPC UA browser / FUXA |
| Historian series | flow_b_m3s | ot_history.tag_catalog |
| Unit | m³/s | ot_history.tag_catalog |

**Key distinction ("scale kept elsewhere"):** The raw Modbus value (FlowBRaw, UINT, in counts) is NOT the engineering value. The scale factor (10000 counts/m³/s) is in the register definition, not in the OPC UA tag name or the historian series. A raw value of 1000 counts = 0.100 m³/s.

**Catalog confirmation** (`ot_history.tag_catalog`):
```sql
SELECT variable, series, node_id, unit
FROM ot_history.tag_catalog
WHERE variable = 'FlowBM3s';
```
Returns: `FlowBM3s | flow_b_m3s | nsu=urn:arwc:crr:tags;s=CRR.FlowBM3s | m3/s` ✓

### Vulnerability and intended solution

This is a bounded cross-layer reconciliation task. The seven-layer chain is supplied by the register (Modbus → IEC → raw → scale → engineering) and confirmed by the catalog (OPC UA → historian). The key challenge is distinguishing PDU offset (5) from IEC address (%IW5), and raw counts from engineering units (10000 counts/m³/s).

The required result is: Produce the complete `FIT-CRR-204B` binding from Modbus function and PDU offset through `%IW5`, `FlowBRaw`, scaling, `FlowBM3s`, the stable OPC UA NodeId, and `flow_b_m3s`. Each native source must agree.

### Evidence and completion

Completion compares the participant's observation with fresh, read-only product records. Product evidence is supplied by the range, never by the participant, and the completion path cannot write a tag, issue a command, change controller state, or create its own product evidence.

Evidence sources are `features.a-engineering.a-engineering`, `features.a-engineering.a-historian`. A wrong register digest, project revision, point identity, scale, time, quality, or outlet mapping is rejected.

### Boundaries and persistence

The result remains local evidence unless a downstream workflow explicitly names it. The task is read-only and creates no process mutation to retain or reset. Ordinary historian retention continues independently. Infrastructure recovery and submission adjudication are external to the SDL.

The behavior is limited to the installed Cairn Reach products, the named asset, and the supplied participant material. It provides no alternate challenge service, simulated completion endpoint, or authority not already present in the OT environment.
