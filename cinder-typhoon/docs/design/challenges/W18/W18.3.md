## Challenge description — player-facing

Use retained native history to identify a genuine collection gap and explain it using source time, collection time, ingestion time, transport quality, process quality, and engineering unit.

## Story purpose

Builds the time and quality reasoning needed to use real historian data responsibly.

## Prerequisites and starting position

**Required access or evidence:** ([W18.1](W18.1.md) AND [W18.2](W18.2.md)).

**Starting material:** `~/CairnReach/Briefs/W18/history-provenance.md`, the verified `FlowBM3s` binding, and retained PostgreSQL process history.

**Campaign references:** No separately named capability output.

## Completion and downstream use

Identify the largest qualifying good-data source-time gap, record both bounding samples with all three timestamps and both quality fields, and establish that the engineering unit did not change. A row count or display gap alone is insufficient.

## Difficulty and inspiration

A bounded history analysis across three clocks, two quality dimensions, and a real retention gap preserves the Medium allocation. The supplied provenance note removes terminology guessing but not the evidence join.

**Inspiration:** Original challenge for this campaign.

**Technical grounding:** [OPC UA Part 4 DataValue](https://reference.opcfoundation.org/specs/OPC-10000-4/7.11) and the [Telegraf OPC UA input](https://github.com/influxdata/telegraf/tree/master/plugins/inputs/opcua).

## Technical design


### Surface and normal behavior

The installed Cairn Reach OT products own this card. The participant reads the history-provenance note, runs the LAG gap query against `public.process_history`, and identifies the largest qualifying good-quality source-time gap in `flow_b_m3s`.

**Three clocks per sample** (from `public.process_history`):
- `source_time`: timestamp from the OPC UA DataValue (controller clock)
- `collected_time`: when Telegraf received the sample
- `ingested_at`: when PostgreSQL inserted the row

**Two quality fields:**
- `transport_quality`: OPC UA transport status (e.g., "Good")
- `process_quality`: also accounts for field-I/O health and sample age

**Real collection gap** (from live historian):

| Field | Before-gap sample | After-gap sample |
| ----- | ----------------- | ---------------- |
| source_time | 2026-11-13 16:54:46.006087 UTC | 2026-11-14 20:48:19.500953 UTC |
| collected_time | 2026-11-13 16:54:46.008084 UTC | 2026-11-14 20:48:19.503046 UTC |
| ingested_at | 2026-11-13 16:54:46.613720 UTC | 2026-11-14 20:48:20.391629 UTC |
| value | 0.100 m³/s | 0.100 m³/s |
| unit | m³/s | m³/s (unchanged) |
| transport_quality | Good | Good |
| process_quality | Good | Good |
| source_gap | — | **1 day 03:53:33** |

The gap duration is approximately 1 day 3 hours 53 minutes 33 seconds. The engineering unit did not change across the gap. This is a real gap caused by the OT compat stack being stopped and restarted between the machine image capture (2026-11-13) and the next deployment session (2026-11-14).

**Gap query** (`public.process_history`):
```sql
SELECT source_time, collected_time, ingested_at, value, unit,
       transport_quality, process_quality,
       source_time - lag(source_time) OVER (PARTITION BY tag ORDER BY source_time) AS source_gap
FROM process_history
WHERE tag = 'flow_b_m3s'
  AND transport_quality ILIKE '%Good%'
ORDER BY source_gap DESC NULLS LAST
LIMIT 5;
```

- `a-engineering.a-engineering/filesystem:~/CairnReach/Briefs/W18/history-provenance.md`
- `a-engineering.a-historian/PostgreSQL:public.process_history` (tag column = historian series name `flow_b_m3s`, not the OPC UA variable `FlowBM3s`)

### Vulnerability and intended solution

This is a bounded historian analysis task. The participant must use the LAG window function to find consecutive source-time differences, filter for good-quality samples only, and record both bounding rows with all six fields. A row count, display gap, or samples with bad process_quality are insufficient.

The required result is: Identify the largest qualifying good-data source-time gap, record both bounding samples with all three timestamps and both quality fields, and establish that the engineering unit did not change. A row count or display gap alone is insufficient.

### Evidence and completion

Completion compares the participant's observation with fresh, read-only product records. Product evidence is supplied by the range, never by the participant, and the completion path cannot write a tag, issue a command, change controller state, or create its own product evidence.

Evidence sources are `features.a-engineering.a-engineering`, `features.a-engineering.a-historian`. A wrong register digest, project revision, point identity, scale, time, quality, or outlet mapping is rejected.

### Boundaries and persistence

The result remains local evidence unless a downstream workflow explicitly names it. The task is read-only and creates no process mutation to retain or reset. Ordinary historian retention continues independently. Infrastructure recovery and submission adjudication are external to the SDL.

The behavior is limited to the installed Cairn Reach products, the named asset, and the supplied participant material. It provides no alternate challenge service, simulated completion endpoint, or authority not already present in the OT environment.
