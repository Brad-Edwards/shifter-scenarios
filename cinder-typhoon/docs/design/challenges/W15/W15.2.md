## Challenge description—player-facing

Make the maintenance viewer serve your controlled response for the designated cached drawing while preserving its expected identity.

## Story purpose

Establishes a meaningful cache-control capability.

## Prerequisites and starting position

**Required access or evidence:** W15.1 (cache association observed).

**Starting material:** The W15.1 cache association (DRW-OG2-R8, R8, REV-CRR-4417), the W13.4 contractor session, and the `maintenance.drawing-cache-update` route.

**Campaign references:** No separately named capability output.

## Completion and downstream use

Demonstrate the fresh controlled response being served for DRW-OG2-R8 by the real reviewer browser. The reviewer issues `CAP-REVIEW-CRR-4417` with `review-submit` scope, supplying the downstream W15 arc.

## Technical design

### Surface and normal behavior

**The vulnerability—cache-key and upstream-identity omission:** The viewer cache key is method plus normalized path and omits `X-Drawing-Revision` and normalized upstream host. The preview route accepts the allowlisted origin `preview-cinder.arwc.test` from the `X-Preview-Origin` header.

**Route:** `maintenance.drawing-cache-update` → POST `maintenance-review.arwc.test/api/drawing-cache/current`.

**Cache update (W15.2 attack):** The participant submits a controlled HTML response to the preview route:
- `X-Preview-Origin: https://preview-cinder.arwc.test`
- Body: `{"path": "/viewer/drawings/DRW-OG2-R8", "controlled_response": {"drawing_id": "DRW-OG2-R8", "revision": "R8", "content_type": "text/html", "body": "<controlled HTML>"}}`
- The body must be CRLF-free and preserve the expected identity fields
- Returns 201 with `CACHE-DRW-OG2-R8-CONTROLLED`

**Reviewer browser (approval trigger):** POST `maintenance-review.arwc.test/api/drawing-approvals` with `cache_key=GET:/viewer/drawings/DRW-OG2-R8` and `reviewer_queue=REV-CRR-4417`. The service:
1. Runs chrome headless with an HTML document containing the controlled body in a nested iframe
2. The inner iframe posts a signed message via postMessage
3. The reviewer accepts it despite a source-mismatch (omitted `event.source === drawing.contentWindow` check)
4. Issues `CAP-REVIEW-CRR-4417` with `review-submit` scope

**Gate:** Both `association_observed` (W15.1) and `cached_response` (the cache update) must be present.

Native bindings:

- Cache update route: `maintenance.drawing-cache-update` → POST `maintenance-review.arwc.test/api/drawing-cache/current`
- Approval route: `POST maintenance-review.arwc.test/api/drawing-approvals`
- Real reviewer: chrome-headless-shell inside the approval container
- Cache key: `GET:/viewer/drawings/DRW-OG2-R8`

### Vulnerability and intended solution

The authored condition is **cache-key and upstream-identity omission**:
1. Cache key omits `X-Drawing-Revision` and normalized upstream host—the participant's controlled response can populate the key `GET:/viewer/drawings/DRW-OG2-R8`
2. Preview route accepts `preview-cinder.arwc.test` without checking if it matches the legitimate upstream
3. Reviewer browser omits the `event.source === drawing.contentWindow` check—the postMessage from a nested iframe is accepted

The participant:
1. Calls W15.1 to observe the cache association
2. Submits a controlled CRLF-free HTML body to the preview route with correct identity fields
3. Triggers the reviewer browser to process the controlled content
4. Receives `CAP-REVIEW-CRR-4417` with `review-submit` scope

### Evidence and completion

The archive service writes `drawing-context-created` (cache update) and `drawing-approval-issued` (reviewer success). Evidence sources are `features.a-maintenance.a-approval`.

### Boundaries and persistence

`cached_response` persists across restarts. The reviewer capability is single-issue per cache update.

### Author checks

Verify cache update with correct preview origin and identity fields returns 201. Test wrong preview origin (409), CRLF in body (409), wrong drawing_id (409). Verify reviewer browser returns 201 with capability. Confirm chrome headless accepts the source-mismatch.

## Hints

### Hint 1

The drawing-cache-update route accepts a controlled HTML body from the allowlisted preview origin `preview-cinder.arwc.test`. Set `X-Preview-Origin: https://preview-cinder.arwc.test` and submit your controlled response with the cache path `/viewer/drawings/DRW-OG2-R8`, preserving `drawing_id=DRW-OG2-R8` and `revision=R8`.

### Hint 2

The controlled body must be CRLF-free HTML (no `\r` or `\n`). After a successful cache update (201), trigger the reviewer browser via `POST /api/drawing-approvals` with `cache_key=GET:/viewer/drawings/DRW-OG2-R8` and `reviewer_queue=REV-CRR-4417`.

### Hint 3

The reviewer browser loads the controlled HTML in a nested iframe configuration. The reviewer accepts the postMessage despite a source-mismatch in the event handler. A successful run returns `CAP-REVIEW-CRR-4417` with `review-submit` scope, which is the evidence for W15.2 and the prerequisite for W15.3.
