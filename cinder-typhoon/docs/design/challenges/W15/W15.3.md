## Challenge description—player-facing

Use the controlled drawing delivery to obtain the reviewer's private maintenance-review submission capability.

## Story purpose

Connects cache control to an actual browser/application effect.

## Prerequisites and starting position

**Required access or evidence:** W15.2 (cached_response in state—cache update complete).

**Starting material:** The W15.2 cached controlled response, the W13.4 contractor session, and the `maintenance.drawing-approvals` route.

**Campaign references:** No separately named capability output.

## Completion and downstream use

Demonstrate that Chromium 128's reviewer browser accepted the controlled drawing's postMessage submission due to the omitted `event.source` check. Returns `CAP-REVIEW-CRR-4417` with `source_check: "omitted"` and `browser: "Chromium 128"`. This capability (review-submit scope) is the prerequisite for W15.4.

## Difficulty and inspiration

A separate browser/session transition after cache control.

**Inspiration:** [OmniWatch (HTB Business CTF 2024; directory Medium / writeup Hard)](../../reference-catalog.md#c24).

## Technical design

### Surface and normal behavior

**Route:** POST `maintenance-review.arwc.test/api/drawing-approvals` with `cache_key=GET:/viewer/drawings/DRW-OG2-R8` and `reviewer_queue=REV-CRR-4417`.

**The reviewer browser:** The service runs real `chrome-headless-shell` (Chromium 128) inside the approval container. Chrome loads the reviewer HTML which embeds the controlled drawing (from W15.2 cache) in an outer drawing iframe. A service-built inner iframe sends the signed `postMessage`. The reviewer JavaScript accepts the postMessage from the inner iframe despite the omitted `event.source === drawing.contentWindow` check (`source_check: "omitted"`).

**Gate:** `cached_response` must be present in state (W15.2 cache update completed).

**Result:** `CAP-REVIEW-CRR-4417` with `scope: ["review-submit"]`, `browser: "Chromium 128"`, `source_check: "omitted"`. This capability is single-issue per cache update.

Native bindings:

- Route: POST `maintenance-review.arwc.test/api/drawing-approvals`
- Real reviewer: chrome-headless-shell in the approval container
- Capability: `CAP-REVIEW-CRR-4417`, audience=maintenance-approval, scope=review-submit

### Vulnerability and intended solution

The authored condition is **reviewer postMessage source omission**. The reviewer bot opens the controlled cached drawing in Chromium 128 and accepts a signed postMessage review submission without checking `event.source`. The source-mismatch flaw (the check is present in the reviewer HTML but evaluates the condition in reverse, logging `accepted-source-mismatch`) allows the submission to proceed.

The participant:
1. Completed W15.2 cache update (controlled HTML in state)
2. Calls POST `/api/drawing-approvals` with the cache key and reviewer queue
3. The service runs Chromium 128 with the reviewer HTML
4. The inner iframe posts the signed message → reviewer accepts with `source_check: "omitted"`
5. Service issues `CAP-REVIEW-CRR-4417`

### Evidence and completion

The archive service writes an immutable audit (`drawing-approved`). The returned record includes `browser: "Chromium 128"` and `source_check: "omitted"`. Evidence sources are `features.a-maintenance.a-approval`.

### Boundaries and persistence

`review_capability` persists across restarts. Single-issue per cache update.

### Author checks

Verify POST to drawing-approvals after cache update returns 201 with CAP-REVIEW-CRR-4417, source_check=omitted, browser=Chromium 128. Test wrong cache_key (403). Confirm chrome headless ran. Verify the capability token is usable in W15.4.
