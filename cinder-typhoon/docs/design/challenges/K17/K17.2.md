## Challenge description — player-facing

The support account's recovery process exposes a separate opportunity. Establish the alternate support identity and recover its private recovery note.

## Story purpose

Adds a distinct identity compromise beyond the retained session.

## Prerequisites and starting position

**Required access or evidence:** [B01 — K17.1](K17.1.md).

**Starting material:** The repository's support-client material, retained session artifacts, and ordinary support-account workflows.

**Campaign references:** No separately named capability output.

## Completion and downstream use

Demonstrate the alternate recovered identity and its private note. Reusing B01 or changing its local session label does not count.

## Difficulty and inspiration

A bounded recovery-workflow flaw with clear account evidence.

**Inspiration:** Original challenge for this campaign.

## Technical design


### Surface and normal behavior
`fieldlink-support` (osTicket) owns this operation. The alternate identity is `talia.mornac` (View only role). The K17.2 Reviewer Recovery Reference note (a staff-only internal note on SUP-2841, authored by maya.ranscombe) contains a leaked osTicket password reset token for talia.mornac. The token is stored in the osTicket `ost_config` table under the `pwreset` namespace — the real osTicket recovery mechanism. The recovery note (B17-REVIEW-2841) is a private internal note assigned to talia.mornac, also on SUP-2841.

### Vulnerability and intended solution
The recovery flaw: osTicket's password reset tokens are stored in the database without protection against staff-to-staff leakage. maya.ranscombe's K17.1 internal note (readable via the K17.1 session) contains talia.mornac's reset token. The participant:
1. Reads the K17.2 Reviewer Recovery Reference note via the K17.1 session → finds reset token.
2. Visits `/scp/pwreset.php?token=<token>` → osTicket recognizes the token and allows login/reset.
3. Authenticates as talia.mornac → new OSTSESSID (distinct from K17.1 session).
4. Reads talia's private recovery note (B17-REVIEW-2841) on SUP-2841 — staff-only.

### Evidence and completion
A distinct OSTSESSID for talia.mornac (not the same as K17.1 session) and the private recovery note content (account talia.mornac-review, recovery ref B17-REVIEW-2841). The note is staff-only — the ticket submitter cannot see it.

### Boundaries and persistence

Optional identity. Participant-created service state persists for the life of the participant world and ordinary retries do not erase it. The action is limited to the exact records, identities, routes, and destination effects declared here; unrelated tenants and services remain denied. Infrastructure recovery and submission adjudication are outside this in-world contract.

### Author checks
Verify that the K17.2 Reviewer Recovery Reference note exists on SUP-2841 and contains the reset token, that the token maps to talia.mornac's staff ID in `ost_config.pwreset`, that the token-based reset URL gives access to talia's reset form, that the new OSTSESSID is distinct from K17.1, and that the private recovery note (B17-REVIEW-2841) is staff-only.
