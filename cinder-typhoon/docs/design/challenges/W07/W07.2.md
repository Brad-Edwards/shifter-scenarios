## Technical design


### Surface and normal behavior

The native surface is the QRY-RESERVE-R7 Metabase native SQL question at `planning.query-run` route (`POST https://reports.arwc.test/api/card/<id>/query`). The question uses a `{{report_name}}` text template variable in a double-quoted identifier:

```sql
SELECT * FROM "{{report_name}}" WHERE reported_ml > 0
```

Normal operation: `report_name = reserve_report_current` → returns RPT-CRR-DP3-R7 (reported_ml=13.40 > 0, filtered by WHERE). The ordinary result does not expose `district_allocation_adjustment`.

The `district_allocation_adjustment` view in `corporate-db` contains ADJ-CRR-DP3-17 (reported_ml=-1.000, same column shape as `reserve_report_current`). `planning_reader` has SELECT on it, but no Metabase route exposes it directly. It is only reachable via quoted-identifier injection through the template variable.

Metabase text template variables are substituted literally into the SQL (no quoting), enabling identifier injection. A closing double-quote in the value terminates the identifier early. UNION is not blocked (only semicolons are). The WHERE reported_ml > 0 applies only to the first SELECT; the UNION part is unrestricted.

Native bindings:

- Route: `planning.query-run` in the planning_data client doc → `POST https://reports.arwc.test/api/card/<id>/query`
- Question: QRY-RESERVE-R7 with `{{report_name}}` text template tag
- Target: `public.district_allocation_adjustment` view in corporate-db (record ADJ-CRR-DP3-17)
- PostgreSQL: `planning_reader` has SELECT on `district_allocation_adjustment`; no direct Metabase route

### Vulnerability and intended solution

The authored condition is **quoted-identifier SQL construction**. Query service constructs SELECT * FROM quoted report_name and rejects semicolons but permits a closing quote plus UNION; protected view district_allocation_adjustment contains ADJ-CRR-DP3-17. The hand build must preserve every named version, encoding, bound, validation order, identity, and unaffected field; substituting a generic vulnerable service would change the task.

The required result is: Recover the actual adjustment ledger with its district and reporting-period binding. Running an already permitted report or merely describing the interface restriction is insufficient.

### Evidence and completion

The owning service writes an immutable audit for the accepted request and result. Caller-supplied output, a local copy, or knowledge of an identifier is not sufficient. Completion is evaluated from fresh service-owned evidence after the action. It cannot issue the identity, create the mutation, move a simulated actuator, or fabricate a downstream acceptance needed to prove itself.

Evidence sources are `features.a-corporate.a-data--query`. A wrong identifier, stale revision, replayed one-time value, different checkpoint, or cross-tenant artifact is rejected.

### Boundaries and persistence

The result remains local evidence unless a downstream workflow explicitly names it. Tenant-scoped mutations, sessions that have not expired, generated artifacts, and audits persist across ordinary retries and later sessions. Initial immutable records remain unchanged unless the named route explicitly permits a field-level revision. Infrastructure recovery and submission adjudication are external to the SDL.

The behavior is limited to the named fictional objects and bounded service operation. It provides no general shell, arbitrary network target, unrelated district access, real process interface, or authority not expressly declared by the card.

### Author checks

Build and test the normal baseline first. Exercise the exact authored path and verify the named result plus its immutable audit. Test wrong authority, wrong object or district, stale revision, replay, another tenant instance, and every declared constraint or unaffected record. Repeat the accepted action according to its idempotence rule and confirm ordinary retries preserve the result. For a joined result, verify each destination observed the same correlation and that removal of any independently owned source prevents completion.

## Hints

### Hint 1

The earned query definition from W07.1 shows the SQL template and the identifier-quoting rule. The published client document exposes the query-run operation—use that ordinary contract. Send the ordinary request first and read the actual WHERE behavior before attempting the injection.

### Hint 2

The double-quoted identifier boundary in the template is the entry point. A closing quote in the parameter value terminates the identifier early. What comes after the quote is then interpreted as SQL, not as an identifier. UNION is permitted; semicolons are not.

### Hint 3

Construct an identifier injection that adds a UNION branch to reach the protected adjustment view alongside the reserve view. The ordinary WHERE restricts only the first SELECT; the UNION part is unrestricted. Confirm that the protected record ADJ-CRR-DP3-17 appears in the query result—then verify denial without a valid planner session and that the ordinary report_name alone is insufficient.
