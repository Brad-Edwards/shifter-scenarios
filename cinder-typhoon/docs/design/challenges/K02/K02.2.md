## Challenge description — player-facing

The test importer is supposed to accept only job inputs. Make it expose the separate review note that the ordinary test view withholds.

## Story purpose

Introduces a small application boundary through an everyday developer workflow.

## Prerequisites and starting position

**Required access or evidence:** the supplied KeplerOps developer foothold.

**Starting material:** The failing report job, a sample output, the fixture reference, and the developer's normal test interface.

**Campaign references:** No separately named capability output.

## Completion and downstream use

Recover the restricted review note and the test job's input contract through the importer. These supply evidence for K02.3; the read does not itself grant job-editing or execution authority.

## Difficulty and inspiration

One approachable input boundary with readable application feedback.

**Inspiration:** Original challenge for this campaign.

## Technical design


### Surface and normal behavior
The FieldKest test importer accepts a documented job-input archive and returns a test report; its repository contains a separate restricted review-note object.

### Vulnerability and intended solution
An importer field is resolved outside the declared job-input namespace before access control. The intended solution is to construct a valid input that demonstrates the boundary and recovers the note plus its input contract.

### Evidence and completion
The importer logs the resolved object ID and job contract; the expected restricted note is attached as operator evidence without giving job-edit rights.

### Boundaries and persistence

Input for K02.3 Participant-created service state persists for the life of the participant world and ordinary retries do not erase it. The action is limited to the exact records, identities, routes, and destination effects declared here; unrelated tenants and services remain denied. Infrastructure recovery and submission adjudication are outside this in-world contract.

### Author checks
Test normal import, intended cross-namespace read, rejection outside allowlist, no job configuration mutation, exact object audit.
