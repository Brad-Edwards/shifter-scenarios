## Challenge description — player-facing

The report test has been failing since its reference fixture disappeared. Recover the fixture from the development artifacts so the intended report is visible again.

## Story purpose

Exposes the legitimate baseline behind a report Cinder will change.

## Prerequisites and starting position

**Required access or evidence:** the supplied KeplerOps developer foothold.

**Starting material:** The failing report job, a sample output, the fixture reference, and the developer's normal test interface.

**Campaign references:** No separately named capability output.

## Completion and downstream use

Recover the missing fixture and identify its matching test revision. This supplies the baseline for K02.3.

## Difficulty and inspiration

A narrow artifact-discovery task with an explicit reference.

**Inspiration:** Original challenge for this campaign.

## Technical design


### Surface and normal behavior
Gitea project history, local build artifacts, and a test-job record describe a deleted report fixture and its matching test revision.

### Vulnerability and intended solution
The fixture was removed from the current checkout but retained in real source or artifact history. The intended solution is evidence-led recovery and revision correlation.

### Evidence and completion
Objective evaluation verifies the fixture digest, historical revision, and test binding, then makes the baseline available to K02.3.

### Boundaries and persistence

Baseline for K02.3 Participant-created service state persists for the life of the participant world and ordinary retries do not erase it. The action is limited to the exact records, identities, routes, and destination effects declared here; unrelated tenants and services remain denied. Infrastructure recovery and submission adjudication are outside this in-world contract.

### Author checks
Verify head lacks the fixture, one provenance path finds it, an unrelated historical file fails, the test revision matches.
