## Technical design

### Surface and normal behavior

The exception queue holds the encrypted dossier for REL-EXC-2841. The completion route at `/api/internal/release-exceptions/REL-EXC-2841/complete` accepts only the restricted worker identity, the correct routine name, and the correct generation. The endpoint returns the ciphertext of the dossier, not the plaintext.

### Vulnerability and intended solution

The intended solution calls the completion route with the worker identity (bearer=worker_session), routine=recover_exception_queue, and generation=process_generation. The endpoint returns two fields:

- `encrypted_record`: hex-encoded ciphertext of the dossier JSON
- `key_relation`: the formula for deriving the decryption key

The decryption key is derived from the K04.3 HMAC:
1. `k43_hmac` = HMAC-SHA256(worker_session, "queue-ready")  — the HMAC computed in K04.3
2. `derived_key` = SHA256(k43_hmac || b":dossier-key")  — 32 bytes
3. Decrypt using SHA256 counter-mode XOR: for each 32-byte block i, `keystream = SHA256(derived_key || big_endian_uint32(i))`, then `plaintext_block = ciphertext_block XOR keystream[:len(block)]`

The participant must have computed or retained the K04.3 HMAC; it is not disclosed anywhere in the descriptor or response.

### Evidence and completion

The decrypted dossier JSON contains `service_identity` and `dossier` fields. These are the elite completion evidence for K04.4 and the alternative K29 dossier lead.

### Boundaries and persistence

Alternative K29 lead.  Participant-created service state persists for the life of the participant world; ordinary retries do not erase it.  The action is limited to the exact records, identities, routes, and destination effects declared here; unrelated tenants and services remain denied.  Infrastructure recovery and submission adjudication are outside this in-world contract.

### Author checks

Test: pre-write_ready completion denial; wrong routine rejection; wrong generation rejection; correct call returns encrypted_record with key_relation; decryption with correct K04.3 HMAC yields valid dossier JSON; decryption with wrong key yields garbage; plaintext dossier not in any API response.

## Hints

### Hint 1

Call the completion_route from the K04.2 descriptor with bearer=worker_session, body `{"routine":"recover_exception_queue","generation":<process_generation>}`. The response includes encrypted_record and key_relation; write_ready must be True first.

### Hint 2

The key_relation field names the derivation formula. First compute the K04.3 HMAC: HMAC-SHA256(worker_session, b"queue-ready"). Then derive the decryption key: SHA256(k43_hmac_bytes + b":dossier-key").

### Hint 3

Decrypt in 32-byte blocks. For block i (starting at 0): keystream = SHA256(derived_key + struct.pack(">I", i)). XOR each byte of the ciphertext block with the corresponding keystream byte to recover the plaintext. The result is a JSON object containing service_identity and dossier.
