## Challenge description — player-facing

Use the compromised indexing behavior to recover protected runtime information that an ordinary bundle cannot see.

## Story purpose

Turns a narrow fault into a new information capability.

## Prerequisites and starting position

**Required access or evidence:** [K04.1](K04.1.md).

**Starting material:** The native support-bundle indexer, source or analysis material, a local reproducer, and normal bundle examples.

**Campaign references:** No separately named capability output.

## Completion and downstream use

Recover the protected runtime evidence needed to reason about the actual process state. This is a separate disclosure capability, not another reward for the first corruption.

## Difficulty and inspiration

Requires reliable disclosure under the source challenge's restrictive native model.

**Inspiration:** [Gloater (HTB Cyber Apocalypse 2024; Insane)](../../reference-catalog.md#c03). Retains Gloater's constrained native-exploitation progression in a support-bundle service.

## Technical design

### Surface and normal behavior
The indexer process holds a protected runtime descriptor and release-queue metadata outside the ordinary bundle index. K04.1's controlled primitive applies only to the designated object graph.

### Vulnerability and intended solution
The next stage requires using that primitive to create a bounded disclosure, then interpreting the disclosed process layout and runtime record. It is an expert reasoning task, not a generic file-read endpoint.

### Evidence and completion
Completion returns the expected runtime descriptor with process generation, protected object marker, and integrity relation checked by the daemon.

### Boundaries and reset
Only a synthetic runtime window is discloseable and it is regenerated per player; the service cannot reveal operating-system, deployment, or other-player data.

### Author checks
Verify K04.1 alone cannot read the descriptor, partial/incorrect disclosures fail, intended runtime evidence is consistent, normal requests remain functional, and reset changes private layout safely.
