## Challenge description — player-facing

Use the compromised indexing behavior to recover protected runtime information that an ordinary bundle cannot see.

## Story purpose

Turns a narrow fault into a new information capability.

## Prerequisites and starting position

**Required access or evidence:** [K04.1](K04.1.md). The K04.1 index_id and the mutated sentinel state are both required.

**Starting material:** The K04.1 controlled mutation, the native support-bundle indexer, the .fki archive format documentation in the supplied indexer-client.json, and the offline reproducer binary.

**Campaign references:** No separately named capability output.

## Completion and downstream use

Recover the protected runtime evidence from the native index record created during K04.1. This is a separate disclosure capability, not another reward for the first corruption.

## Difficulty and inspiration

Expert-tier recovery: the extended index fields are only present when the service's internal state matches the mutated condition established by K04.1. Ordinary index reads return the basic record.

**Inspiration:** [Gloater (HTB Cyber Apocalypse 2024; Insane)](../../reference-catalog.md#c03). Retains Gloater's constrained native-exploitation progression in a support-bundle service.

## Technical design


### Surface and normal behavior
The indexer exposes a GET route for individual index records. Under normal conditions the route returns the basic indexed bundle metadata.

### Vulnerability and intended solution
When the indexer's internal sentinel state has been mutated by K04.1, re-querying the specific index record from that mutation returns an extended response that includes a fresh worker session token and the exception record metadata. This session token was generated at K04.1 mutation time and is not visible before K04.1 or through any other route. The intended solution re-queries the K04.1 index_id after the mutation and reads the extended fields.

### Evidence and completion
The extended index record supplies the worker session, process generation, state route, and integrity relation needed for K04.3. The worker session is fresh — generated at K04.1 time, not pre-configured.

### Boundaries and persistence

Supplies layout/state evidence only Participant-created service state persists for the life of the participant world and ordinary retries do not erase it. The action is limited to the exact records, identities, routes, and destination effects declared here; unrelated tenants and services remain denied. Infrastructure recovery and submission adjudication are outside this in-world contract.

### Author checks
Verify that querying any index_id before K04.1 returns only basic fields; querying the K04.1 index_id after mutation returns the extended fields; querying a different index_id after mutation returns only basic fields; the worker_session changes on each range reset.

## Hints

### Hint 1
The K04.1 response supplies an index_id. After the controlled mutation, re-query that specific record from the native indexer GET route — the mutated internal state changes what it reveals.

### Hint 2
Only the index record from the K04.1 mutation itself gains the extended fields; other index records and unauthenticated or pre-mutation reads return the ordinary result. The extended record supplies the session authority for K04.3.

### Hint 3
Record the worker_session, process_generation, and state_route from the extended index record exactly. The worker_session is a fresh value generated at mutation time and is the bearer credential for K04.3's protected write.
