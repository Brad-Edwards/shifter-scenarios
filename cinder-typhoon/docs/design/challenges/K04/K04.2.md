## Challenge description — player-facing

Use the compromised indexing behavior to recover protected runtime information that an ordinary bundle cannot see.

## Story purpose

Turns a narrow fault into a new information capability.

## Prerequisites and starting position

**Required access or evidence:** [K04.1](K04.1.md).

**Starting material:** The K04.1 controlled mutation, the native support-bundle indexer, the .fki archive format documentation in the supplied indexer-client.json, and the offline reproducer binary.

**Campaign references:** No separately named capability output.

## Completion and downstream use

Recover the protected runtime evidence needed to reason about the actual process state. This is a separate disclosure capability, not another reward for the first corruption.

## Difficulty and inspiration

Requires reliable disclosure under the source challenge's restrictive native model.

**Inspiration:** [Gloater (HTB Cyber Apocalypse 2024; Insane)](../../reference-catalog.md#c03). Retains Gloater's constrained native-exploitation progression in a support-bundle service.

## Technical design


### Surface and normal behavior
The indexer process holds a protected runtime descriptor and release-queue metadata outside the ordinary bundle index. K04.1's controlled primitive applies only to the designated object graph.

### Vulnerability and intended solution
The next stage requires using that primitive to create a bounded disclosure, then interpreting the disclosed process layout and runtime record. It is an expert reasoning task, not a generic file-read endpoint.

### Evidence and completion
Completion returns the expected runtime descriptor with process generation, protected object marker, and integrity relation checked by the daemon.

### Boundaries and persistence

Supplies layout/state evidence only Participant-created service state persists for the life of the participant world and ordinary retries do not erase it. The action is limited to the exact records, identities, routes, and destination effects declared here; unrelated tenants and services remain denied. Infrastructure recovery and submission adjudication are outside this in-world contract.

### Author checks
Verify K04.1 alone cannot read the descriptor, partial/incorrect disclosures fail, intended runtime evidence is consistent, normal requests remain functional.

## Hints

### Hint 1
The indexer does not expose all its operations in the client reference. The K04.1 mutation changes the service's internal state in a way that unlocks a second code path. Send an index request with an operation field after the mutation is in place.

### Hint 2
The disclosed runtime record is available only when the service has already recorded a sentinel mutation. Supplying the mutated sentinel value as a request field along with the operation name gates the disclosure.

### Hint 3
The descriptor response supplies the process generation, the integrity relation formula, and the worker lease needed for the next stage. Record all three fields exactly; they bind K04.3's protected-state write.
