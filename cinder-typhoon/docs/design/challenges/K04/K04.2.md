## Challenge description — player-facing

Use the compromised indexing behavior to recover protected runtime information that an ordinary bundle cannot see.

## Story purpose

Turns a narrow fault into a new information capability.

## Prerequisites and starting position

**Required access or evidence:** [K04.1](K04.1.md). The K04.1 controlled mutation is the prerequisite: it causes the service to write the runtime descriptor into the shared arena at bytes 80-511.

**Starting material:** The K04.1 controlled mutation, the native support-bundle indexer, the .fki archive format documentation in the supplied indexer-client.json, and the offline reproducer binary.

**Campaign references:** No separately named capability output.

## Completion and downstream use

Recover the protected runtime descriptor written to the shared arena by K04.1. The descriptor supplies the worker session and state evidence needed for K04.3.

## Difficulty and inspiration

Expert-tier recovery through extended binary read: the participant must analyze the binary to find the arena layout (sentinel at bytes 64-79; descriptor at bytes 80-511; total arena size 512 bytes), determine the alloc_entries value that makes the bounds check permit datalen=512, and parse the runtime descriptor from the hex output. The descriptor region is populated only after K04.1 and is not disclosed by any service route.

**Inspiration:** [Gloater (HTB Cyber Apocalypse 2024; Insane)](../../reference-catalog.md#c03). Retains Gloater's constrained native-exploitation progression in a support-bundle service.

## Technical design


### Surface and normal behavior
The binary reads the shared arena (`arena.shm`, 512 bytes) before each bundle write, copies the entry data into the persistent file, and returns `data_hex` of the pre-write read up to `datalen` bytes. For a normal bundle (ie ≤ 8, datalen ≤ 64), `data_hex` covers only the body region. After K04.1 the service writes the runtime descriptor into bytes 80-511 of the arena.

### Vulnerability and intended solution
The bounds check compares `datalen` against `sizeof(struct index_arena) + alloc_entries`, where `sizeof(struct index_arena) = 80` (body[64] plus sentinel[16]). A bundle with `ie=64` (datalen=512) and `alloc_entries=432` satisfies the check (`512 ≤ 80 + 432`) and extends the read to cover bytes 80-511. After K04.1, those bytes contain the runtime descriptor. The binary returns them as part of `data_hex` with no additional conditional: the disclosure is a consequence of the extended read reaching the descriptor region.

### Evidence and completion
Completion returns `data_hex` of 512 bytes (1024 hex chars). Parsing hex chars 160-1023 as JSON yields the runtime descriptor containing `worker_session`, `process_generation`, `state_route`, `completion_route`, and `integrity_relation` needed for K04.3.

### Boundaries and persistence

Supplies layout/state evidence only. Participant-created service state persists for the life of the participant world and ordinary retries do not erase it. The action is limited to the exact records, identities, routes, and destination effects declared here; unrelated tenants and services remain denied. Infrastructure recovery and submission adjudication are outside this in-world contract.

### Author checks
Verify that before K04.1 the descriptor region is all zeros; after K04.1 it contains the runtime descriptor; a bundle with insufficient alloc_entries to reach datalen=512 is rejected (exit code 66); a normal ie=8 bundle returns only body-region data_hex; the worker_session in the descriptor matches the INDEXER_WORKER_TOKEN credential and changes on range reset.

## Hints

### Hint 1
The binary returns a `data_hex` field covering the bytes read from the shared arena before each write. After K04.1 the arena carries the runtime descriptor at bytes 80-511, populated by the service at mutation time.

### Hint 2
The bounds check uses `sizeof(struct index_arena) = 80` as its base, not the total arena size. For `datalen=512` (ie=64) the check passes when `alloc_entries >= 432`. Analyze the binary to confirm the arena constants before constructing the K04.2 bundle.

### Hint 3
Parse `data_hex` hex chars 160-1023 (arena bytes 80-511) as JSON to recover the runtime descriptor. It contains the `worker_session` bearer, `process_generation`, `state_route`, and `integrity_relation` required for K04.3.
