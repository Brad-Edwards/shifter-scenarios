## Challenge description — player-facing

The support indexer treats uploaded bundles as routine work. Construct a bundle that causes a controlled change beyond the object it should be allowed to affect.

## Story purpose

Begins an optional deep investigation from the initial workstation.

## Prerequisites and starting position

**Required access or evidence:** the supplied KeplerOps developer foothold.

**Starting material:** The native support-bundle indexer, source or analysis material, a local reproducer, and normal bundle examples.

**Campaign references:** No separately named capability output.

## Completion and downstream use

Demonstrate reproducible, controlled corruption across the indexer's object boundary. A crash alone is insufficient; this is the foundation for the later capabilities.

## Difficulty and inspiration

Constrained native fault analysis with a useful effect, rather than unconstrained input crashing.

**Inspiration:** [Gloater (HTB Cyber Apocalypse 2024; Insane)](../../reference-catalog.md#c03). Retains Gloater's constrained native-exploitation progression in a support-bundle service.

## Technical design

### Surface and normal behavior
The source-available support indexer accepts signed archive bundles, indexes their entries, and maintains an in-memory object graph for the release-exception queue.

### Vulnerability and intended solution
A deliberately flawed deserializer confuses attacker-controlled entry metadata with an internal object length. The intended solution is a reproducible, constrained object-boundary corruption that preserves service liveness; a crash is not a solution.

### Evidence and completion
The daemon records a controlled mutation of the designated sentinel object and a successful subsequent normal index operation.

### Boundaries and reset
The native daemon runs against per-player memory and fixture data with no useful host interfaces, filesystem write, or network reachability; reset restarts its private state.

### Author checks
Test valid indexing, nonpersistent crash rejection, intended sentinel-only mutation, continued normal indexing, no out-of-fixture data exposure, and reset.
