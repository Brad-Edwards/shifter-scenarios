## Challenge description — player-facing

The indexer still restricts what your corrupted object can influence. Establish a controlled write capability under those restrictions and demonstrate it against the designated protected state.

## Story purpose

Provides a substantive elite milestone before final execution.

## Prerequisites and starting position

**Required access or evidence:** [K04.2](K04.2.md).

**Starting material:** The K04.2 runtime descriptor (worker_session, process_generation, state_route, integrity_relation) recovered from the binary arena over-read.

**Campaign references:** No separately named capability output.

## Completion and downstream use

Demonstrate the scoped write capability while the indexer remains usable. The prior disclosure or another crash does not satisfy this achievement.

## Difficulty and inspiration

Retains the demanding allocator-control transition from Gloater; public solutions still require adaptation to this instance.

**Inspiration:** [Gloater (HTB Cyber Apocalypse 2024; Insane)](../../reference-catalog.md#c03). Retains Gloater's constrained native-exploitation progression in a support-bundle service.

## Technical design


### Surface and normal behavior
The daemon exposes a protected release-exception state object whose fields are validated against the runtime descriptor and ordinary index transactions.

### Vulnerability and intended solution
The intended solution uses the worker_session bearer and integrity_relation from the K04.2 descriptor to authenticate a PATCH to the internal state route. The integrity check requires computing sha256(process_generation:queue-ready) and presenting it alongside the target state value. This is an elite exploitation exercise: the participant must chain all three prior primitives (K04.1 mutation, K04.2 arena over-read, K04.3 state write) with correctly derived values, not arbitrary memory control.

### Evidence and completion
The service accepts completion only when the target state changes to the specified value, its integrity relation remains valid, and a normal indexing transaction still succeeds.

### Boundaries and persistence

Supplies scoped write primitive Participant-created service state persists for the life of the participant world and ordinary retries do not erase it. The action is limited to the exact records, identities, routes, and destination effects declared here; unrelated tenants and services remain denied. Infrastructure recovery and submission adjudication are outside this in-world contract.

### Author checks
Test direct state mutation denial, disclosure prerequisite, intended bounded write, integrity failure rejection, service liveness after success, and private-state persistence.

## Hints

### Hint 1
Use the state_route and worker_session from the K04.2 runtime descriptor. The worker_session is the bearer credential for the PATCH request to the state route.

### Hint 2
The integrity_relation field in the K04.2 descriptor names the formula. Compute the integrity value from the process_generation and the target state string, then include it in the PATCH body alongside the state value.

### Hint 3
A subsequent normal bundle index must still succeed. The service checks state=queue-ready, the computed integrity, and sentinel=mutated; it rejects wrong-integrity or pre-K04.1 requests and stays alive after a correct write.
