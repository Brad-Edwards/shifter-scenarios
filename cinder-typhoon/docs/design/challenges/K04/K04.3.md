## Challenge description — player-facing

The indexer still restricts what your corrupted object can influence. Establish a controlled write capability under those restrictions and demonstrate it against the designated protected state.

## Story purpose

Provides a substantive elite milestone before final execution.

## Prerequisites and starting position

**Required access or evidence:** [K04.2](K04.2.md).

**Starting material:** The native support-bundle indexer, source or analysis material, a local reproducer, and normal bundle examples.

**Campaign references:** No separately named capability output.

## Completion and downstream use

Demonstrate the scoped write capability while the indexer remains usable. The prior disclosure or another crash does not satisfy this achievement.

## Difficulty and inspiration

Retains the demanding allocator-control transition from Gloater; public solutions still require adaptation to this instance.

**Inspiration:** [Gloater (HTB Cyber Apocalypse 2024; Insane)](../../reference-catalog.md#c03). Retains Gloater's constrained native-exploitation progression in a support-bundle service.

## Technical design

### Surface and normal behavior
The daemon exposes a protected release-exception state object whose fields are validated against the runtime descriptor and ordinary index transactions.

### Vulnerability and intended solution
The intended solution develops a scoped write primitive from the earlier disclosure and applies it only to the designated state with its required integrity relationship. This is an elite exploitation exercise with a stable authored target, not arbitrary memory control.

### Evidence and completion
The service accepts completion only when the target state changes to the specified value, its integrity relation remains valid, and a normal indexing transaction still succeeds.

### Boundaries and reset
Writable memory is restricted to private card objects; any unsafe transition terminates only the player daemon and never affects another service. Reset restores a fresh state image.

### Author checks
Test direct state mutation denial, disclosure prerequisite, intended bounded write, integrity failure rejection, service liveness after success, and private-state reset.
