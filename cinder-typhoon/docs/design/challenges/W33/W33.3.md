### Vulnerability and intended solution

This is a bounded operations-planning and commissioning task, not a privilege flaw. The participant must use the installed products to commission all twelve reviewed release values sequentially through the authenticated dispatcher, prove every native result, then restore manual A20/B20 through local FUXA priority. A synthetic forecast, private rehearsal, locally invented response, or copied request receipt does not establish the result.

The required result is: Demonstrate twelve ordered durable dispatcher receipts, native PLC acceptances, and measured completions for the reviewed schedule, followed by a later local HMI acceptance and measured manual A20/B20 baseline.

### Evidence and completion

Completion reads a range-supplied snapshot of the native dispatcher journal, PLC decisions, process history, and corporate planning records applicable to the card. The participant cannot supply product evidence. The evaluator cannot issue a broker request, write a controller tag, move an outlet, retry an uncertain request, take local priority, or create product evidence.

Evidence sources are `features.a-engineering.a-engineering`, `features.a-engineering.a-hmi`, `features.a-engineering.a-historian`, `features.a-control.a-reservoir`, `features.a-control.a-instruments`. A wrong asset, instruction, calibration request, source time, process quality, gain, schedule constraint, request identity, transition order, PLC sequence, measured result, handback, corporate record, unit, or measured-versus-projected interpretation is rejected.

### Boundaries and persistence

The result remains local evidence unless a downstream workflow explicitly names it. The dispatcher, OpenPLC command history, and historian retain the twelve commissioning steps as ordinary product records. Completion requires a later accepted local HMI request and measured return to manual A20/B20, approximately 0.10 m3/s per outlet and 0.20 m3/s total, healthy I/O, valid permissives, no motion, and clear travel faults. The one-hour effect remains a projection. Infrastructure recovery and submission adjudication are external to the SDL.

The behavior is limited to AST-CRR-017 and CRR-OP-W33-R1. It grants no arbitrary MQTT topic, OPC UA write, engineering force, program upload, interlock bypass, automatic retry after uncertainty, alternate control endpoint, or new scheduler authority.

### Author checks

Begin from the qualified manual A20/B20 baseline and an authentic completed W30 record. Verify calibration against native dispatcher and historian time, then accept multiple feasible schedules rather than one fixed answer. For commissioning, require twelve fresh sequential requests, the exact successful dispatcher path, matching native PLC acceptances, settled good-quality feedback, and a later local handback. Recompute every projection from product history and the current corporate rows. Reject infeasible schedules, missing or reordered stages, duplicate identities, rejection, uncertainty, bad quality, participant-supplied product evidence, invented measurements, stale planning records, confused measured/projected claims, or failure to restore. Reset must return the same qualified baseline without replaying a dispatcher request or changing product identities and trust material.
