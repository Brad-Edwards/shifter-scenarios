## Challenge description — player-facing

Inspect the supplied training package without installing it. Recover the extra action installation would trigger, including the data involved and its destination.

## Story purpose

Foreshadows the fictional supply-chain compromise behind the campaign.

## Prerequisites and starting position

**Required access or evidence:** the supplied training workspace.

**Starting material:** The training repository, retained build diagnostics, a sample package, and the rehearsal publication/consumer interfaces.

**Campaign references:** No separately named capability output.

## Completion and downstream use

Recover the package's actual extra behavior with its source and destination binding. A suspicious filename or a generic warning is insufficient.

## Difficulty and inspiration

A small readable package-analysis task.

**Inspiration:** Original challenge for this campaign.

## Technical design

### Surface and normal behavior

The Developer desk publishes an unpacked npm-compatible package with
`package.json`, lockfile v3, `scripts/register-rehearsal.js`, and
`fixtures/rehearsal-source.json`. The manifest maps `postinstall` to that
script. Its code reads
`/opt/cinder-sample/fixtures/rehearsal-source.json` (record `SRC-204`) and sends
the JSON to `http://developer.training:8084/api/rehearsal/ingest`.

### Vulnerability and intended solution

The intended solution reads the manifest and script to recover the lifecycle,
source, and destination binding. The package is served only as static files;
the environment never runs an installer or that script, and the named ingest
route returns 405 to direct calls. Opening or downloading any file has no
lifecycle effect.

### Evidence and completion

The retained package revision identifies a lifecycle action, a source record,
and a destination. These are facts of the package contents, not a generic
warning or filename.

### Boundaries

The package is presented as content only; its lifecycle action is never invoked
by the supplied environment. The data names refer only to synthetic training
records. Inspection does not install the package or modify those records.

### Author checks

Check that ordinary package metadata remains useful, static inspection
identifies the complete action and its source/destination, and neither opening
nor inspecting the package invokes its lifecycle action.
