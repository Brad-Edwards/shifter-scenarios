## Challenge description — player-facing

Recover the missing delivery fixture named in the training package's review note and identify the behavior it covered.

## Story purpose

Introduces development history as useful evidence.

## Prerequisites and starting position

**Required access or evidence:** the supplied training workspace.

**Starting material:** The training repository, retained build diagnostics, a sample package, and the rehearsal publication/consumer interfaces.

**Campaign references:** No separately named capability output.

## Completion and downstream use

Recover the actual fixture and expected delivery outcome. A revision identifier alone does not count.

## Difficulty and inspiration

A small repository investigation with an explicit missing artifact.

**Inspiration:** Original challenge for this campaign.

## Technical design

### Surface and normal behavior

`developer.training:8081` exposes a read-only Forge view and Git smart HTTP for
`cinder/delivery-formatter`. Deterministic commit `fixture-added` contains
`test/fixtures/DL-204.json`; child `fixture-removed` deletes it and adds
`REVIEW.md`, which names the missing path. The ancestor fixture binds the fixed
DL-204 input to summary `DL-204 | Cinder receiving desk | 3 parcels`. Exact
authors, UTC times, messages, parent, paths, modes, deletions, and bytes are in
`repository-seed.json`.

### Vulnerability and intended solution

The head checkout lacks the named file while its ancestor object remains
reachable through ordinary history. The intended solution follows `REVIEW.md`,
recovers that one ancestor file, and compares it with the independently
published `/consumer-contract.md`. No hidden route or path guess is needed.

### Evidence and completion

The recovered fixture has a content hash and historical commit identifying
an actual ancestor artifact. Its expected delivery outcome agrees with the
separately available current consumer contract. Recovering it is not required
to obtain that contract.

### Boundaries

The repository is read-only for this task and contains only training source.
History is immutable. Recovering a historical object does not change the branch,
the consumer, or the registry.

### Author checks

Confirm the head checkout lacks the fixture, the review note gives a fair lead,
the parent history contains one matching artifact, an unrelated commit fails,
and the expected outcome agrees with the consumer fixture.
