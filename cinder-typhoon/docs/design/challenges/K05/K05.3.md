## Challenge description — player-facing

The release manifest and customer selection record disagree. Reconcile them against the actual native package and identify the exact selected-version discrepancy and matching consumer identity.

## Story purpose

Turns release metadata into an operationally useful finding.

## Prerequisites and starting position

**Required access or evidence:** [G03 — K05.1](K05.1.md).

**Starting material:** The release record `REL-FLK-7.4.2-09` from the `packages.release` route, the tenant record for `TEN-ARWC-047` (customer context from K01.2), Verdaccio metadata for `@keplerops/fieldlink-connector`, and the `packages.reconcile` route.

**Campaign references:** No separately named capability output.

## Completion and downstream use

Produce a correctly bound comparison of package, version, and consumer revision. It must identify the actual disagreement, not just differing text.

## Difficulty and inspiration

Native mechanisms: [npm package specifications](https://docs.npmjs.com/cli/v11/using-npm/package-spec/) and [Verdaccio package ACLs](https://www.verdaccio.org/docs/packages/). The existing Easy/Medium tier follows the bounded discovery or multi-record/behavior correlation required above.

## Technical design


### Surface and normal behavior
The FieldLink delivery application retains independent release and tenant package records. Verdaccio supplies the real package manifest and tarball; the normal reconciliation operation compares the business records without impersonating registry storage.

### Vulnerability and intended solution

The intended solution POSTs `{"tenant_record_id": "TEN-ARWC-047", "release_id": "REL-FLK-7.4.2-09"}` to the `packages.reconcile` route. The service compares four fields between the two records. Three match — package, `declared_range` (`^7.4.0`), and `consumer_revision` (`arwc-connector-consumer@19f43d2`). Only `resolved_version` disagrees: the tenant record pins `7.4.1` while the release record declares `7.4.2`. A wrong record pair returns 422. The participant also downloads the 7.4.1 tarball from Verdaccio (via its `dist.tarball` URL) and computes the archive digest to bind the disagreeing version to actual native package bytes.

### Evidence and completion
The comparison identifies the selected-version disagreement and matching consumer revision, bound to both business record IDs and the native package archive digest.

### Boundaries and persistence

Input to K05.4 Participant-created service state persists for the life of the participant world and ordinary retries do not erase it. The action is limited to the exact records, identities, routes, and destination effects declared here; unrelated tenants and services remain denied. Infrastructure recovery and submission adjudication are outside this in-world contract.

### Author checks
Verify matching fields, the sole selected-version difference and matching consumer revision, native archive integrity, wrong record-pair rejection and repeatable reads without release mutation.

## Hints

### Hint 1

POST `{"tenant_record_id": "TEN-ARWC-047", "release_id": "REL-FLK-7.4.2-09"}` to the `packages.reconcile` route. Use the same developer credentials as the other routes. Wrong record pairs return 422. The release record `REL-FLK-7.4.2-09` is readable from `packages.release`; the tenant ID comes from the support ticket customer context recovered in K01.2.

### Hint 2

The reconcile result's `comparison` object covers four fields. Only `resolved_version` disagrees: the tenant record has `7.4.1`, the release record has `7.4.2`. The other three fields (`package`, `declared_range`, `consumer_revision`) match across both records. The `comparison_digest` binds the full result to both business record IDs.

### Hint 3

Bind the disagreeing version to the actual native archive: fetch the Verdaccio metadata for `@keplerops/fieldlink-connector`, find the `7.4.1` version object's `dist.tarball` URL, download the tarball, and compute its SHA256. This binds the archive digest to the tenant's selected version and completes the evidence.
