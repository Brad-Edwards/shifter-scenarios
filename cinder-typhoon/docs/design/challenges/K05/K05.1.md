## Challenge description — player-facing

Find the package interface used by the ARWC connector and make its documented example produce a valid result.

## Story purpose

Establishes the package contract needed by either ordinary delivery route.

## Prerequisites and starting position

**Required access or evidence:** [G01 — K01.1](../K01/K01.1.md).

**Starting material:** The readable FieldKest package workspace, interface examples, release records, and an ordinary consumer-check facility.

**Campaign references:** `G03`.

## Completion and downstream use

Identify the consumed package and exercise its expected interface. This supplies G03 without requiring the other K05 challenges.

## Difficulty and inspiration

One documented example and a clearly named consumer interface.

**Inspiration:** Original challenge for this campaign.

## Technical design

### Surface and normal behavior
The FieldKest Gitea project documents the connector's package interface and supplies a fixture consumer with a valid example request.

### Vulnerability and intended solution
This is an orientation task: inspect the earned source and run the documented interface against the fixture consumer to identify the consumed package.

### Evidence and completion
The consumer records a valid request, package name, resolved version range, and expected baseline result, awarding `G03`.

### Boundaries and reset
The fixture consumer is player-local, read-only outside its request log, and cannot publish or contact ARWC; reset clears requests.

### Author checks
Test documented example success, malformed interface failure, correct package/version recording, no registry authority, and reset.
