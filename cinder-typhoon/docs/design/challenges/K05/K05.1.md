## Challenge description — player-facing

## Story purpose

## Difficulty and inspiration

Native mechanisms: [npm package specifications](https://docs.npmjs.com/cli/v11/using-npm/package-spec/) and [Verdaccio package ACLs](https://www.verdaccio.org/docs/packages/). The existing Easy/Medium tier follows the bounded discovery or multi-record/behavior correlation required above.

## Technical design


### Surface and normal behavior
Verdaccio exposes the actual npm manifest and package tarball. The installed Node module exports consume(request), reads its package metadata and local limits file, and the separate FieldLink delivery application invokes it in the existing isolated worker.

### Vulnerability and intended solution

The intended solution reads the Verdaccio package metadata for `@keplerops/fieldlink-connector`. The registry README documents the `fieldkest.connector/v3` interface. The participant constructs a valid request with `schema`, `tenant_id`, `asset_id`, and optionally `measurements`, then POSTs it to the `packages.consumer-check` route. The service runs `npm pack @keplerops/fieldlink-connector@^7.4.0` to fetch the tarball from Verdaccio, then passes the archive and request to the installed isolated runner. The result must come from the real installed module; missing required fields or wrong schema return 422.

### Evidence and completion
The fresh check result binds the actual package version and archive digest to the input tenant, asset, consumer revision and executed module output.

### Boundaries and persistence

Supplies G03 Participant-created service state persists for the life of the participant world and ordinary retries do not erase it. The action is limited to the exact records, identities, routes, and destination effects declared here; unrelated tenants and services remain denied. Infrastructure recovery and submission adjudication are outside this in-world contract.

### Author checks
Verify native package metadata and tarball access, one valid consumer request, missing required input failure, actual local module/file behavior and matching version/digests.

## Hints

### Hint 1

Fetch the Verdaccio metadata for `@keplerops/fieldlink-connector` from the client-document `packages.metadata` route. The package README documents the `fieldkest.connector/v3` interface and the required request fields.

### Hint 2

Construct a consumer request with `schema`, `tenant_id`, and `asset_id`. An optional `measurements` object with `callback_latency_ms` and `sample_count` enriches the result. Missing required fields return 422 from the `packages.consumer-check` route.

### Hint 3

POST the request to `packages.consumer-check`. The 201 result includes `check_id`, `resolved_version`, `consumer_revision`, `package_sha256`, the original request, and the actual module output from the installed connector. These fields bind the package version and archive digest to the executed result.
