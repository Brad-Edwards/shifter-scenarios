## Challenge description — player-facing

Prove which dependency npm actually selects for the declared range and what the real installed consumer executes. Use package and module evidence rather than the release label.

## Story purpose

Distinguishes publisher intention from consumer behavior.

## Prerequisites and starting position

**Required access or evidence:** [K05.3](K05.3.md).

**Starting material:** The readable FieldKest package workspace, interface examples, release records, and an ordinary consumer-check facility.

**Campaign references:** No separately named capability output.

## Completion and downstream use

Make the intended check consumer identify its selected dependency through a fresh result. This is optional selection intelligence; K26 retains its own production delivery problem.

## Difficulty and inspiration

Native mechanisms: [npm package specifications](https://docs.npmjs.com/cli/v11/using-npm/package-spec/) and [Verdaccio package ACLs](https://www.verdaccio.org/docs/packages/). The existing Easy/Medium tier follows the bounded discovery or multi-record/behavior correlation required above.

## Technical design


### Surface and normal behavior
Native npm selects a real published package for the declared range. The isolated FieldLink check installs its actual tarball offline, loads the module and ordinary local files, and returns the resulting package version and behavior.

### Vulnerability and intended solution
Relate standard npm version-selection rules to the available native versions, then confirm the selected archive and module behavior with the normal consumer. Compare the module output and archive integrity with the reconciliation evidence.

### Evidence and completion
The native npm selection, exact archive digest, installed module version, preserved request bindings and actual consumer output identify the dependency that ran.

### Boundaries and persistence

Optional selection intelligence Participant-created service state persists for the life of the participant world and ordinary retries do not erase it. The action is limited to the exact records, identities, routes, and destination effects declared here; unrelated tenants and services remain denied. Infrastructure recovery and submission adjudication are outside this in-world contract.

### Author checks
Verify highest matching stable-version selection, standard no-matching-version failure, native tarball integrity, actual module/local-file behavior and a fresh consumer result.
