## Challenge description — player-facing

Construct a model of the verifier's collision constraints that also accounts for the engineering program's required form.

## Story purpose

Connects integrity analysis to the semantics a usable program must preserve.

## Prerequisites and starting position

**Required access or evidence:** [W27.1](W27.1.md).

**Starting material:** The legacy engineering-program verifier, approved diagnostic examples, and the isolated planning consumer it protects.

**Campaign references:** No separately named capability output.

## Completion and downstream use

Demonstrate the model on the specified distinguishing program cases. An unconstrained collision claim or checksum implementation alone does not count.

## Difficulty and inspiration

Requires combining the integrity model with meaningful program-format constraints.

**Inspiration:** [ROT128 (HTB Cyber Apocalypse 2024; Insane)](../../reference-catalog.md#c15). Retains ROT128's custom-integrity analysis and meaningful altered-program objective.
