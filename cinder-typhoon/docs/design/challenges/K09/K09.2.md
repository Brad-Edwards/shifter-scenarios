## Challenge description — player-facing

A completed job recorded an artifact that the current results page does not list. Recover that omitted artifact and its build revision.

## Story purpose

Provides a distinct build artifact rather than another string from the log.

## Prerequisites and starting position

**Required access or evidence:** [G01 — K01.1](../K01/K01.1.md).

**Starting material:** The developer's build history, ordinary job interface, artifact references, and a sample FieldKest build.

**Campaign references:** No separately named capability output.

## Completion and downstream use

Recover the missing artifact from its separate publication surface. It contains the test-job evidence used later in this operation.

## Difficulty and inspiration

A bounded artifact-discovery task with readable build metadata.

**Inspiration:** Original challenge for this campaign.

## Technical design


### Surface and normal behavior
The CI run's immutable metadata names an artifact whose current results-page index is incomplete; the artifact archive retains build revision and provenance.

### Vulnerability and intended solution
The artifact index filters one completed output incorrectly. The intended solution follows normal build metadata to recover the omitted artifact and confirm its exact revision.

### Evidence and completion
Artifact retrieval records the run, object version, and build revision, enabling K09.3's input path.

### Boundaries and persistence

Input to K09.3 Participant-created service state persists for the life of the participant world and ordinary retries do not erase it. The action is limited to the exact records, identities, routes, and destination effects declared here; unrelated tenants and services remain denied. Infrastructure recovery and submission adjudication are outside this in-world contract.

### Author checks
Test index omission, metadata lead, one matching artifact, wrong-run artifact rejection, provenance consistency.
