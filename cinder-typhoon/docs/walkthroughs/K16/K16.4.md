# K16.4 Walkthrough: Still there after the handover

Precondition: the K14.2 export role token (`$ROLE`) and the K16.1-K16.3 steps.
`next_assignment` is `field-operator-b` (from the K16.1 schedule response).

## Step 0: open a participant shell

```
gcloud compute ssh <range-vm> --project prod-mgau4w --zone us-central1-a --tunnel-through-iap
sudo docker exec -it --user rowan cinder-keplerops-k-dev bash
```

## Step 1: get the export role token

```
CA=~/.local/share/keplerops/ca.crt
DEV=$(sed -E 's#https://([^@]+)@.*#\1#' ~/.config/git/credentials)
WORKLOAD=$(curl -sS --cacert $CA -u "$DEV" \
  -H 'Content-Type: application/json' -d '{}' \
  https://cloud-api.keplerops.test/api/workspaces/current/token-exchange \
  | grep -o '"access_token":"[^"]*"' | cut -d'"' -f4)
ROLE=$(curl -sS --cacert $CA -H "Authorization: Bearer $WORKLOAD" \
  -H 'Content-Type: application/json' -d '{}' \
  https://cloud-api.keplerops.test/api/token-exchange/support-export-editor \
  | grep -o '"access_token":"[^"]*"' | cut -d'"' -f4)
```

## Step 2: set the assignment to the next operator

```
curl -sS --cacert $CA -X PATCH -H "Authorization: Bearer $ROLE" \
  -H 'Content-Type: application/json' \
  --data-binary '{"assignment":"field-operator-b"}' \
  https://workloads.keplerops.test/api/schedules/SCHED-2841
```

Output: `{"assignment":"field-operator-b","revision":2,"schedule_id":"SCHED-2841"}`

## Step 3: trigger a run to confirm the assignment persists (K16.4 acceptance check)

```
curl -sS --cacert $CA -X POST -H "Authorization: Bearer $ROLE" \
  -H 'Content-Type: application/json' --data-binary '{}' \
  https://workloads.keplerops.test/api/schedules/SCHED-2841/runs
```
