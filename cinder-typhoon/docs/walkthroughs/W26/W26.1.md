Prerequisites: W13.4 (contractor check-in writes the session token) and W15.4 (the signed
maintenance approval must be written to the approval-evidence volume before the renderer
accepts it).

## Step 0 — open the participant shell

```bash
gcloud compute ssh <range-vm> --project prod-mgau4w --zone us-central1-a --tunnel-through-iap
sudo docker exec --user fieldlink --workdir /var/lib/fieldlink-connector cinder-arwc-connector bash -l
```

## Step 1 — load the contractor session token (from W13.4)

The contractor check-in (W13.4) saves the bearer token to `receipts/contractor-session`.
If you receive 403 "maintenance renderer session required", re-run W13.4 to refresh the token.

```bash
CONTRACTOR_TOKEN=$(cat receipts/contractor-session)
```

## Step 2 — read the renderer profile (W26.1 acceptance check)

```bash
curl -s --cacert /tmp/arwc-ca.crt \
  -H "Authorization: Bearer $CONTRACTOR_TOKEN" \
  -H "X-ARWC-Tenant: arwc" \
  https://maintenance-renderer.arwc.test/api/renderers/current
```

```json
{"audit_id":"<uuid>","record":{"record_id":"RENDER-MAINT-CRR-R9","revision":9,"approval":"APR-CRR-4417-R6","inspection":"INSP-CRR-2026-09-18","reviewer_role":"maintenance-reviewer","worker":"svc-maint-render","status":"current"},"flag":"FLAG{73be7a91c87cd444}"}
```

Gate: 403 "current signed maintenance approval required" means W15.4 has not been run on this
range yet (run W15.1 → W15.2 → W15.3 → W15.4 first). 403 "maintenance renderer session
required" means the contractor token is missing or stale (re-run W13.4).
