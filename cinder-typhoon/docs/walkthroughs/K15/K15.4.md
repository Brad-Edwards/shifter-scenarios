# K15.4 Walkthrough: The right customer's collection

Precondition: the K14.2 export SA token (`$EXPORT_TOKEN`), the K15.3 destination
change, and the tenant, connector revision, and partition from the K15.2
definition.

## Step 0: open a participant shell

```
gcloud compute ssh <range-vm> --project prod-mgau4w --zone us-central1-a --tunnel-through-iap
sudo docker exec -it --user rowan cinder-keplerops-k-dev bash
```

## Step 1: get the export SA token

```
CA=~/.local/share/keplerops/ca.crt
DEV=$(sed -E 's#https://([^@]+)@.*#\1#' ~/.config/git/credentials)
WORKLOAD=$(curl -sS --cacert $CA -u "$DEV" \
  -H 'Content-Type: application/json' -d '{}' \
  https://cloud-api.keplerops.test/api/workspaces/current/token-exchange \
  | grep -o '"access_token":"[^"]*"' | cut -d'"' -f4)
EXPORT_TOKEN=$(curl -sS --cacert $CA -H "Authorization: Bearer $WORKLOAD" \
  -H 'Content-Type: application/json' -d '{}' \
  https://cloud-api.keplerops.test/api/token-exchange/fieldkest-export-access \
  | grep -o '"access_token":"[^"]*"' | cut -d'"' -f4)
```

## Step 2: run the export for the correct tenant partition (K15.4 acceptance check)

The run validates the tenant, connector revision, and partition against the
PostgreSQL partition bindings, then writes the collection to SeaweedFS.

```
curl -sS --cacert $CA -X POST -H "Authorization: Bearer $EXPORT_TOKEN" \
  -H 'Content-Type: application/json' \
  --data-binary '{"tenant":"TEN-ARWC-019","connector_revision":"FLK-7.4.2","partitions":["PART-ARWC-01"]}' \
  https://cloud-api.keplerops.test/api/exports/EXP-2841/runs
```

Output:

```json
{"collection_key":"PART-ARWC-01-rev17.json","connector_revision":"FLK-7.4.2","destination":"fieldkest-exports/EXP-2841-rowan","export_id":"EXP-2841","flag":"FLAG{203073cbbcb4ce62}","partitions":["PART-ARWC-01"],"revision":17,"schema":"fieldkest.export-run/v1","tenant":"TEN-ARWC-019"}
```

The `revision` increments on each run; the flag is stable.
