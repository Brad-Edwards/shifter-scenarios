Requires W30.1 (request plan confirmed). This card is a complete remote operate-and-handback across MQTT, the OpenPLC controller, the OT historian, and the FUXA HMI. Completion reads the dispatcher journal and native command history; it never issues the request, moves an outlet, or restores the plant for you. The participant brief is `build/arwc-ot/challenges/W30/participant/operator-brief.md`.

Intended path (confirm the baseline A20/B20 first):

1. In the FUXA HMI (Site controls) enable remote selection, without changing the baseline. Do not write PLC nodes directly.
2. Publish exactly one fresh, non-retained QoS 1 request as the `operator` principal on `arwc/crr/commands/operator` (mosquitto, TLS, CA `/run/pki/ca.pem` inside the OT stack). The payload is the `arwc.remote-request/v1` contract:
   ```json
   {"id":"<fresh uuid4>","asset":"AST-CRR-017","mode":"automatic",
    "position_a_pct":20.0,"position_b_pct":20.0,"total_flow_m3s":0.30,
    "expires_at":<unix epoch seconds now+90>}
   ```
   The dispatcher stages the four OPC UA settings, commits the next PLC sequence, and the controller accepts it. Settled feedback is ~0.15 m3/s per outlet, ~0.30 m3/s total, remote ownership (Owner=2), both permissives valid, neither outlet moving.
3. Hand the site back through ONE complete local FUXA request: manual mode, outlet A 20 percent, outlet B 20 percent, total flow ~0.20 m3/s, remote selection disabled. Local HMI priority produces a later accepted HMI sequence (Owner=HMI).
4. Read the evidence and submit it to the workbench. The dispatcher journal `public.dispatch_history` (by your request UUID) gives the ordered states (`received, dispatch_intent, dispatched, plc_accepted, completed`), the PLC `remote_sequence`, and the received/completed times. `public.command_history` gives the dispatcher command at `remote_sequence` and the later HMI restore command at `restore_sequence`. Read both from the OT engineering container (`cinder-arwc-ot-engineering`, `psql`).

```python
import json, ssl, urllib.request, pathlib
ctx = ssl.create_default_context(cafile="/tmp/arwc-ca.crt")
proc = pathlib.Path("receipts/process-session").read_text().strip()
h = {"Authorization": "Bearer " + proc, "X-ARWC-Tenant": "arwc", "Content-Type": "application/json"}

# Fill these from dispatch_history (your request UUID) and command_history:
body = {
    "asset": "AST-CRR-017",
    "request_id": "<your request uuid>",
    "remote_sequence": <PLC sequence from dispatch_history>,
    "received_at": "<dispatch_history received time, ISO 8601>",
    "completed_at": "<dispatch_history completed time, ISO 8601>",
    "restore_sequence": <HMI sequence from command_history>,
    "restore_accepted_at": "<HMI restore time, ISO 8601>",
    "final_observed_at": "<a time at or after restore, ISO 8601>",
    "interval_start": "<at or before received_at>",
    "interval_end": "<at or after final_observed_at>",
    "interpretation": "durable_receipt_plc_acceptance_measured_completion_local_handback",
}
d = json.loads(urllib.request.urlopen(
    urllib.request.Request("https://process-view.arwc.test/api/remote-operations/current",
        data=json.dumps(body).encode(), headers=h, method="POST"), context=ctx).read())
print("flag:", d["flag"])   # FLAG{c22198847dd20ce6}
```

The workbench checks the ordered dispatcher states, that all journal sequences agree, that the claimed received/completed/restore times match the journals within 2 s, that the settled flows are ~0.15 m3/s per outlet, and that the interval ordering `interval_start <= received < completed < restore_accepted <= final <= interval_end` holds. A copied practice sequence, a direct PLC write, or a missing local handback is rejected.

Flag: `FLAG{c22198847dd20ce6}` in the top-level `flag` field.
