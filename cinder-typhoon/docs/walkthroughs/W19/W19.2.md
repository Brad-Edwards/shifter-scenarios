## Prerequisite

W19.1 recovered the diagnostic binary and its rolling hash. The algorithm starts
at `0x6D2B79F5`. For each input byte it rotates `state XOR byte` left by 5 bits in
32 bits. Then it adds `0x9E3779B9` in 32 bits.

## Compute the rolling hash of the wrap record

Apply the recovered algorithm to the record name `WRAP-FFFFFFFF-OG2`. The `OG2`
suffix is the Cairn Reach outlet tag used in these record IDs.

```bash
PROCESS=$(cat receipts/process-session)
ROLLING=$(python3 - <<'PY'
mask = (1 << 32) - 1
value = 0x6D2B79F5
for byte in b"WRAP-FFFFFFFF-OG2":
    state = (value ^ byte) & mask
    value = ((state << 5) | (state >> 27)) & mask
    value = (value + 0x9E3779B9) & mask
print(f"{value:08x}")
PY
)
echo "$ROLLING"   # e8c29ec8
```

## Submit the interpretation

The service rejects a wrong `rolling32`. It accepts the computed value.

```bash
# Wrong rolling32 -> 409:
curl -s --cacert /tmp/arwc-ca.crt -H "Authorization: Bearer $PROCESS" -H "X-ARWC-Tenant: arwc" \
  -H "Content-Type: application/json" \
  -d '{"record":"WRAP-FFFFFFFF-OG2","rolling32":"00000000"}' -X POST \
  https://process-view.arwc.test/api/signature-records/current/interpretation
# -> 409

# Correct rolling32 -> 201:
curl -s --cacert /tmp/arwc-ca.crt -H "Authorization: Bearer $PROCESS" -H "X-ARWC-Tenant: arwc" \
  -H "Content-Type: application/json" \
  -d "{\"record\":\"WRAP-FFFFFFFF-OG2\",\"rolling32\":\"$ROLLING\"}" -X POST \
  https://process-view.arwc.test/api/signature-records/current/interpretation
```

```json

```

The response `record.execution` is `i386-compatibility`. The flag is in the
