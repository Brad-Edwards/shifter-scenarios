## Prerequisite

After W19.2. Uses the rolling and verifier hashes recovered in W19.1.

## Build and submit the signature program

Submit all five decisions. Each decision carries the record, its `rolling32`
(8 hex digits) and its `verifier64` (16 hex digits). The migration record is the
deciding record; the other four support it. A short program (missing the
migration record) is rejected with 409.

```bash
PROCESS=$(cat receipts/process-session)
BODY=$(python3 - <<'PY'
import json
def rotl(x, r, bits):
    mask = (1 << bits) - 1
    x &= mask
    return ((x << r) | (x >> (bits - r))) & mask
def rolling(rec):
    mask = (1 << 32) - 1
    v = 0x6D2B79F5
    for b in rec.encode():
        v = (rotl((v ^ b) & mask, 5, 32) + 0x9E3779B9) & mask
    return v
def verifier(rec):
    mask = (1 << 64) - 1
    v = rolling(rec)
    return rotl(0x243F6A8885A308D3 ^ ((v * 0x100000001B3) & mask), 9, 64) ^ v
records = ["OUTLET_A:800", "OUTLET_B:1200", "LEGACY:4294967295", "CRR:204", "MIG-OG2-R19-R21"]
decisions = [{"record": r, "rolling32": f"{rolling(r):08x}", "verifier64": f"{verifier(r):016x}"} for r in records]
print(json.dumps({"decisions": decisions}))
PY
)
curl -sk --cacert /tmp/arwc-ca.crt -H "Authorization: Bearer $PROCESS" -H "X-ARWC-Tenant: arwc" \
  -H "Content-Type: application/json" -d "$BODY" -X POST \
  https://process-view.arwc.test/api/signature-programs/current
```

```json
{"audit_id":"...","flag":"FLAG{9babf5077ba75607}","record":{"decision":"valid","record_id":"MIG-OG2-R19-R21",...}}
```

The response `record.decision` is `valid` and `record.record_id` is the migration
record. The flag is in the top-level `flag` field.
