Requires W33.2 (approved operating schedule). The site must be at the qualified manual A20/B20 baseline before you begin.

## Step 1 — Enable remote selection in FUXA

FUXA runs at `http://172.29.63.21:1881` on the OT supervisory network. Sign in as `operator` with the FUXA operator credential and enable remote selection:

```bash
TOKEN=$(curl -s http://172.29.63.21:1881/api/signin \
  -H 'Content-Type: application/json' \
  -d '{"username":"operator","password":"<fuxa_operator_password>"}' \
  | python3 -c "import sys,json; print(json.load(sys.stdin)['data']['token'])")

curl -s http://172.29.63.21:1881/api/setTagValue \
  -H 'Content-Type: application/json' \
  -H "Authorization: Bearer $TOKEN" \
  -d '{"device":"crr-plc","tag":"HmiRemoteEnabled","value":true}'
```

The FUXA operator credential is at `CairnReach/Connections/README.md` on the OT engineering workstation.

## Step 2 — Copy the schedule file to the OT engineering workstation

Ensure your W33.2 schedule JSON is available on the workstation. If you created it in Step 3 of W33.2 it is already there at `/home/fieldlink/CairnReach/Briefs/W33/my-schedule.json`.

## Step 3 — Run the commissioning schedule

From the OT engineering workstation:

```bash
cd /home/fieldlink/CairnReach/Briefs/W33
python3 run-schedule.py my-schedule.json --receipt /home/fieldlink/w33-receipt.json
# Enter the MQTT operator password when prompted
# (from /home/fieldlink/CairnReach/Connections/README.md)
```

The script sends one request per interval and prints progress. It stops if any request is rejected, expired, superseded, or uncertain. If a step fails, inspect `dispatch_history` and do not retry automatically.

The receipt file records each request UUID and outcome. Keep it — you need the twelve request IDs for W33.4.

```bash
cat /home/fieldlink/w33-receipt.json | python3 -c \
  "import json,sys; r=json.load(sys.stdin); [print(x['interval'], x['request']['id']) for x in r['requests']]"
```

## Step 4 — Restore the site through local FUXA priority

After all twelve steps print `completed`, restore the manual A20/B20 baseline through FUXA:

```bash
# Using the same $TOKEN from Step 1 (or sign in again):
for tag_value in '{"device":"crr-plc","tag":"HmiAutoMode","value":false}' \
                 '{"device":"crr-plc","tag":"HmiTargetPct","value":20}' \
                 '{"device":"crr-plc","tag":"HmiTargetBPct","value":20}' \
                 '{"device":"crr-plc","tag":"HmiRemoteEnabled","value":false}'; do
  curl -s http://172.29.63.21:1881/api/setTagValue \
    -H 'Content-Type: application/json' \
    -H "Authorization: Bearer $TOKEN" \
    -d "$tag_value"
done
# Then increment HmiSequence to submit the HMI request (use the same method as W25)
```

Confirm in the OT historian that the later local HMI acceptance appears with Owner=1, A20/B20, ~0.10 m³/s per outlet, 0.20 m³/s total, IoHealthy=1, permissives clear, no motion, no faults.

## Step 5 — Collect submission values from the historian

From the OT engineering workstation:

```sql
-- Get the restore HMI sequence
SELECT channel, sequence, source_time FROM public.command_history
WHERE asset='AST-CRR-017' AND channel='HMI'
ORDER BY source_time DESC LIMIT 1;

-- Get a final_observed_at after the HMI restore
SELECT ph.source_time FROM public.process_history ph
JOIN public.historian_tag_catalog c ON c.series = ph.tag
WHERE ph.asset='AST-CRR-017' AND c.variable='HmiAccepted'
ORDER BY ph.source_time DESC LIMIT 1;
```

Also record `started_at` (first dispatch receipt) and `completed_at` (last dispatch completion) from the receipt file.

## Step 6 — Submit the commissioning record

From the IT connector shell:

```python
import json, ssl, urllib.request, pathlib

ctx = ssl.create_default_context(cafile="/tmp/arwc-ca.crt")
proc = pathlib.Path("receipts/process-session").read_text().strip()
h = {"Authorization": "Bearer " + proc, "X-ARWC-Tenant": "arwc", "Content-Type": "application/json"}

receipt = json.loads(pathlib.Path("/home/fieldlink/w33-receipt.json").read_text())
# (Access the receipt from the connector shell or copy it over)

body = {
    "asset": "AST-CRR-017",
    "forecast": {<same forecast dict as W33.1 and W33.2>},
    "schedule": {<same schedule dict as W33.2>},
    "request_ids": [r["request"]["id"] for r in receipt["requests"]],
    "started_at": "<ISO 8601 of first request received_at>",
    "completed_at": "<ISO 8601 of last request completed_at>",
    "restore_sequence": <HMI sequence from Step 5>,
    "restore_accepted_at": "<ISO 8601 from Step 5>",
    "final_observed_at": "<ISO 8601 from Step 5>",
    "interpretation": "measured_twelve_step_commissioning_run_with_local_handback",
}
d = json.loads(urllib.request.urlopen(
    urllib.request.Request(
        "https://process-view.arwc.test/api/commissioning-runs/current",
        data=json.dumps(body).encode(), headers=h, method="POST"), context=ctx).read())
print("completed_steps:", d["record"]["completed_steps"])
print("flag:", d["flag"])   # FLAG{271d8984b1b19a04}
```

The service verifies all twelve dispatcher transitions, PLC acceptances, measured completions, and the local handback against product history. The flag appears in the top-level `flag` field.
