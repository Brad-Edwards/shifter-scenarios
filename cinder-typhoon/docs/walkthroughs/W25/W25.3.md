# W25.3 Walkthrough — Accepted is not actuated (movement)

Requires W25.1 and W25.2 to pass. Prerequisite: W25.2 `may_proceed` confirmed.

## Step 0 — Access

```
# OT engineering desktop
sudo docker exec -it --user fieldlink cinder-arwc-ot-engineering bash
# Or via RDP to the engineering workstation (see Connections/README.md)
```

## Step 1 — Read the current HMI sequence

From the OT engineering desktop or the FUXA viewer, read the current
`HmiAccepted` value so you know the baseline sequence to increment.

```
# From OT engineering desktop — read current HmiAccepted via FUXA REST (admin, QA only)
# Human participants: read HmiAccepted from the FUXA crr-controls view in the browser
curl -s http://172.29.63.21:1881/api/getTagValue?ids=%5B%22HmiAccepted%22%5D \
  -H "x-access-token: <admin_token>"
# Returns: [{"id":"HmiAccepted","value":<N>,...}]
# Next sequence = N + 1 (mod 65535)
```

## Step 2 — Issue the HMI command via FUXA browser (participant path)

**Primary path (human participants):**

1. Open Firefox on the OT engineering workstation.
2. Go to `http://172.29.63.21:1881`.
3. Log in as `operator` using the password from `Connections/README.md`.
4. Open the `crr-controls` view.
5. Set **A target** = 30 %, **B target** = 10 %, **mode** = Manual, **flow** = 0.20 m³/s.
6. Click **Apply**. Record the sequence number shown after the Apply.
7. Watch **HmiAccepted**: wait until it matches the sequence you sent.
8. Watch **PositionPct** and **PositionBPct**: wait until both settle near 30 % and 10 %.
9. Record `accepted_at` (when HmiAccepted changed) and `settled_at` (when positions settled).

**QA scripted equivalent (admin REST only — not the participant path):**

```
# Step 2a: Obtain admin token
FUXA_PASS=$(sudo python3 -I -c "import json; c=json.load(open('/slice/.operator/credentials.json')); print(c['fuxa'])")
TOK=$(curl -s -X POST http://172.29.63.21:1881/api/signin \
  -H "Content-Type: application/json" \
  -d "{\"username\":\"admin\",\"password\":\"$FUXA_PASS\"}" \
  | python3 -I -c "import json,sys; print(json.load(sys.stdin)['data']['token'])")

# Step 2b: Read current sequence, compute next
SEQ=$(curl -s "http://172.29.63.21:1881/api/getTagValue?ids=%5B%22HmiAccepted%22%5D" \
  -H "x-access-token: $TOK" \
  | python3 -I -c "import json,sys; print((json.load(sys.stdin)[0]['value'] % 65535) + 1)")

# Step 2c: Issue HMI command
curl -s -X POST http://172.29.63.21:1881/api/setTagValue \
  -H "Content-Type: application/json" -H "x-access-token: $TOK" \
  -d "{\"tags\":[{\"id\":\"HmiTargetPct\",\"value\":30.0},{\"id\":\"HmiTargetBPct\",\"value\":10.0},{\"id\":\"HmiSequence\",\"value\":$SEQ}]}"

# Step 2d: Poll until PLC accepts
curl -s "http://172.29.63.21:1881/api/getTagValue?ids=%5B%22HmiAccepted%22%2C%22PositionPct%22%2C%22PositionBPct%22%5D" \
  -H "x-access-token: $TOK"
```

## Step 3 — Submit movement evidence

From the OT engineering desktop, with the `process_session` from W09.4:

```
POST /api/process-movement/current
Authorization: Bearer <process_session>
```

```json
{
  "record_id": "CRR-OP-W25-R1",
  "hmi_sequence": <accepted_sequence>,
  "target_a": 30,
  "target_b": 10,
  "accepted_at": "<ISO8601 when HmiAccepted changed>",
  "settled_at": "<ISO8601 when positions settled near A30/B10>"
}
```

Expected response includes the flag:

```json
{"flag": "FLAG{fca8c6786592eb89}", "record": {"record_id": "W25-MOVEMENT-CRR-R1", "actuation_confirmed": true}}
```
