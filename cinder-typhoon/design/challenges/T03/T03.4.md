## Challenge description — player-facing

Deliver a compatible training formatter that adds Cinder's rehearsal marker to the intended consumer's delivery report.

## Story purpose

Completes a miniature supplier-to-consumer episode.

## Prerequisites and starting position

**Required access or evidence:** [T03.2](../T03/T03.2.md).

**Starting material:** The training repository, retained build diagnostics, a sample package, and the rehearsal publication/consumer interfaces.

**Campaign references:** No separately named capability output.

## Completion and downstream use

Demonstrate a fresh consumer report with the marker and preserved ordinary behavior. Construction, publication, activation, and consumption earn one score here.

## Difficulty and inspiration

A bounded interface adaptation and consumer-binding problem.

**Inspiration:** Original challenge for this campaign.

## Technical design

### Surface and normal behavior

The training registry serves a formatter package to a separate consumer
emulator. The emulator resolves a semver-compatible version, runs a normal
formatting report, and posts a receipt containing its resolved package and
output digest.

### Vulnerability and intended solution

This is a controlled supply-chain construction task. The intended solution
combines T03.1's expected behavior with T03.2's scoped publication capability
to create a compatible package that preserves the ordinary report while adding
the named rehearsal marker.

### Evidence and completion

Completion requires registry publication, consumer resolution after publication,
and a fresh report receipt showing the marker and baseline behavior. The event
chain is the score; publishing an unused version does not count.

### Boundaries and reset

The registry scope, consumer tenant, and report data are player-specific.
Packages cannot affect other consumers, external package resolution, or later
campaign systems. Reset restores the consumer lock state and removes player
published versions.

### Author checks

Test baseline consumer behavior, incompatible version rejection, intended
compatible resolution, preserved report fields, marker receipt correlation, no
cross-player consumption, and full package/consumer reset.
