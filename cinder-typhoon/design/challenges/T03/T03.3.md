## Challenge description — player-facing

Inspect the supplied training package without installing it. Recover the extra action installation would trigger, including the data involved and its destination.

## Story purpose

Foreshadows the fictional supply-chain compromise behind the campaign.

## Prerequisites and starting position

**Required access or evidence:** the supplied training workspace.

**Starting material:** The training repository, retained build diagnostics, a sample package, and the rehearsal publication/consumer interfaces.

**Campaign references:** No separately named capability output.

## Completion and downstream use

Recover the package's actual extra behavior with its source and destination binding. A suspicious filename or a generic warning is insufficient.

## Difficulty and inspiration

A small readable package-analysis task.

**Inspiration:** Original challenge for this campaign.

## Technical design

### Surface and normal behavior

The supplied npm-compatible training package has a normal manifest, lockfile,
and unpacked package contents. Its installation lifecycle includes an extra
action intended for the rehearsal consumer, with data source and destination
named in the package metadata and fixture code.

### Vulnerability and intended solution

The exercise teaches static package inspection before execution. The intended
solution class is manifest and source analysis that reconstructs the lifecycle
action and its bound data flow; no package installation is necessary.

### Evidence and completion

Completion records the lifecycle action, source fixture ID, and intended
destination ID. The scorer validates all three against the authored package
revision, rejecting generic warnings or a suspicious filename alone.

### Boundaries and reset

The package is presented as content only; its lifecycle action is never invoked
by the player environment. The data names resolve only to synthetic training
fixtures and reset clears the submitted evidence.

### Author checks

Verify ordinary package metadata remains useful, static inspection exposes the
complete action, the source and destination are unambiguous, installation is
not required, incomplete data-flow answers fail, and reset is idempotent.
