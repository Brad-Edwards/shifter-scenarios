## Challenge description — player-facing

The identity desk's public directory hides rehearsal assignments from visitors. Recover the private assignment and associated staff detail it should not expose.

## Story purpose

Adds an independent data disclosure to the identity story.

## Prerequisites and starting position

**Required access or evidence:** the supplied training workspace.

**Starting material:** The rehearsal identity desk, candidate account notes, a public directory, recovery workflow, and assignment service.

**Campaign references:** No separately named capability output.

## Completion and downstream use

Recover the actual private roster entry. Its staff detail supports T02.3; the public name list alone does not count.

## Difficulty and inspiration

A bounded application-data discovery.

**Inspiration:** Original challenge for this campaign.

## Technical design

### Surface and normal behavior

The public directory renders a limited staff list from an API used by the
identity desk. Its browser bundle also contains an assignment-detail request
used by internal rehearsal coordinators and seeded roster records with staff
IDs and assignments.

### Vulnerability and intended solution

The detail route relies on a client-side visibility decision and lacks the
corresponding server-side authorization check. The intended solution is to
inspect the normal public application and retrieve the one roster detail named
by the training context.

### Evidence and completion

The roster service emits a detail-read event with the assignment and staff
record version. That exact private entry becomes player evidence for recovery;
the public display response cannot satisfy the score.

### Boundaries and reset

The API exposes only synthetic rehearsal roster entries and no identity
mutation. Reset removes player read events; it does not change staff data.

### Author checks

Confirm public listing works, the coordinator route is discoverable from normal
client material, one expected detail returns, unrelated roster IDs are denied,
and the recorded entry matches T02.3's recovery data.
