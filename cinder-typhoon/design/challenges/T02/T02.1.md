## Challenge description — player-facing

Identify the active rehearsal account and recover the account-bound case reference exposed by the identity desk.

## Story purpose

Provides a useful identity lead without password guessing.

## Prerequisites and starting position

**Required access or evidence:** the supplied training workspace.

**Starting material:** The rehearsal identity desk, candidate account notes, a public directory, recovery workflow, and assignment service.

**Campaign references:** No separately named capability output.

## Completion and downstream use

Recover the actual active account and its case reference. Submitting candidate names alone is insufficient. These are inputs to T02.3.

## Difficulty and inspiration

A small identity investigation with a short candidate set.

**Inspiration:** Original challenge for this campaign.

## Technical design

### Surface and normal behavior

The identity desk is an authored self-service front end backed by the training
realm in the shared identity broker. It accepts an account-recovery lookup and
creates a case record for an active rehearsal account.

### Vulnerability and intended solution

Its recovery lookup distinguishes inactive, unknown, and active accounts and
returns a case-reference fragment only for an active assignment. The intended
solution is to use the supplied contextual leads and response differences to
identify the actual account, not to submit an unrestricted name list.

### Evidence and completion

The desk writes a lookup event for the active subject and discloses its linked
case reference. Scoring checks both values and makes the evidence available to
T02.3 without authenticating the player.

### Boundaries and reset

The endpoint is limited to the small rehearsal account set, rate-bounded, and
has no password reset or session creation path. Reset clears lookup events and
returns the fixed account states.

### Author checks

Verify the supplied lead narrows the candidates, response classes are stable,
only the active account yields the case fragment, bulk submission is bounded,
and a correct lookup records the expected subject.
