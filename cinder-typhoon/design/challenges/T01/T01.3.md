## Challenge description — player-facing

Recover the retired courier client's usable access and retrieve the sealed manifest assigned to that courier.

## Story purpose

Turns recovered access into a scoped information result.

## Prerequisites and starting position

**Required access or evidence:** the supplied training workspace.

**Starting material:** The supplied training workspace, dispatch site, retired courier-client material, and a diagnostic helper.

**Campaign references:** No separately named capability output.

## Completion and downstream use

Recover and use the limited credential to obtain the protected manifest. Credential discovery and use earn one score.

## Difficulty and inspiration

A bounded client-artifact and access task.

**Inspiration:** Original challenge for this campaign.

## Technical design

### Surface and normal behavior

Retired courier-client material in the workspace includes a configuration
profile, request history, and a courier API with normal manifest retrieval.
Each courier token is bound to a courier record and one sealed delivery.

### Vulnerability and intended solution

A decommissioned client profile retains a still-valid, narrowly scoped bearer
credential. The intended solution is to identify its scope from surrounding
client material and use the actual courier API for the assigned delivery.

### Evidence and completion

The API emits a manifest-read event containing the token's courier ID, target
delivery ID, and object version. Scoring accepts only the expected scoped read,
which also makes the manifest available as player evidence.

### Boundaries and reset

The token can read one synthetic manifest and cannot list, write, or access any
non-training service. Its per-player copy is revoked and reissued on reset.

### Author checks

Confirm a normal courier read succeeds, the intended profile maps to one
courier, a different delivery is denied, copied token text without an API event
does not score, and reset invalidates the old token.
