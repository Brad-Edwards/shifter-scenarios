## Challenge description — player-facing

Make the dispatch diagnostic helper reveal the internal delivery summary that its ordinary report leaves out.

## Story purpose

Provides an early application-exploitation payoff.

## Prerequisites and starting position

**Required access or evidence:** the supplied training workspace.

**Starting material:** The supplied training workspace, dispatch site, retired courier-client material, and a diagnostic helper.

**Campaign references:** No separately named capability output.

## Completion and downstream use

Recover the internal summary through an action in the helper's actual context. Echoing supplied text or returning an ordinary report is insufficient.

## Difficulty and inspiration

A single approachable application boundary with clear feedback.

**Inspiration:** Original challenge for this campaign.

## Technical design

### Surface and normal behavior

The dispatch diagnostic helper accepts a delivery selector and produces a
sanitized public report from a local rehearsal dataset. A separate internal
summary is available only to the helper's service context and is tied to the
same delivery record.

### Vulnerability and intended solution

One helper argument is incorporated into a secondary diagnostic action without
the validation applied to the public report path. The intended solution class
is analysis of the supplied helper's real input handling to invoke that action
in its existing context; it is not a generic host compromise exercise.

### Evidence and completion

The helper records a successful internal-summary retrieval with the selected
delivery and returns the record's immutable summary. Completion requires that
server-side action, not echoed input or an ordinary public report.

### Boundaries and reset

The helper runs against a card-local data directory with no network route,
shell persistence, or reusable system credential. Reset recreates its player
workspace and diagnostic audit log.

### Author checks

Test an ordinary report, the intended bounded secondary action, rejected
malformed selectors, absence of access outside the fixture directory, the audit
record, and a clean reset.
