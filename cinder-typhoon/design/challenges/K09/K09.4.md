## Challenge description — player-facing

Use the compromised job workflow to execute a limited action in its runner context and recover the protected job note.

## Story purpose

Turns build access into a useful scoped execution foothold.

## Prerequisites and starting position

**Required access or evidence:** [K09.3](../K09/K09.3.md).

**Starting material:** The developer's build history, ordinary job interface, artifact references, and a sample FieldLink build.

**Campaign references:** No separately named capability output.

## Completion and downstream use

Demonstrate actual execution and recover the job note. This context enables workload and maintenance branches; it grants no customer execution.

## Difficulty and inspiration

Requires adapting the earned job capability to a separate execution objective.

**Inspiration:** Original challenge for this campaign.

## Technical design

### Surface and normal behavior
The test-job workflow renders the selected review output with a constrained diagnostic action executed by the `svc-fieldlink-ci` runner identity.

### Vulnerability and intended solution
The resolved support input can alter one declared diagnostic action after K09.3. The intended solution demonstrates that action in the runner context and retrieves the protected job note.

### Evidence and completion
The runner audit records identity, permitted action, run ID, and protected note revision, awarding the bounded workload lead used by K14 or K30.

### Boundaries and reset
Execution is an authored one-action sandbox with no shell, persistence, workload deployment, or broad CI control. Reset destroys job state and its scoped token.

### Author checks
Test ordinary job, K09.3 prerequisite, intended diagnostic action, action allowlist denial, audited identity/note, and reset.
