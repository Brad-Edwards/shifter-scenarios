## Challenge description — player-facing

The failed build's public summary omits its useful details. Recover the retained runner log and the release-dossier reference it exposes.

## Story purpose

Makes routine build output a useful cloud and release lead.

## Prerequisites and starting position

**Required access or evidence:** [G01 — K01.1](../K01/K01.1.md).

**Starting material:** The developer's build history, ordinary job interface, artifact references, and a sample FieldLink build.

**Campaign references:** No separately named capability output.

## Completion and downstream use

Recover the actual log and its job binding. Its dossier reference can introduce K29 or K30; it grants no cloud principal.

## Difficulty and inspiration

A direct log-disclosure task with a clear failed-job lead.

**Inspiration:** Original challenge for this campaign.

## Technical design

### Surface and normal behavior
The CI public summary links a failed run while a retained runner log contains ordinary execution details and a release-dossier reference.

### Vulnerability and intended solution
Summary redaction does not extend to the run's normally archived log. The intended solution recovers that log through its run provenance and validates the dossier reference.

### Evidence and completion
The log digest, run ID, and dossier ID are recorded as player evidence; no runner or release authority results.

### Boundaries and reset
Run history is read-only synthetic data; reset removes player reads without changing CI records.

### Author checks
Verify summary omission, a fair run lead, retained log access, matching dossier reference, no job execution, and reset.
