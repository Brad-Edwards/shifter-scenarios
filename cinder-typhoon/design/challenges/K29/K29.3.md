## Challenge description — player-facing

Deliver one signed support release that carries Cinder's change for ARWC while preserving the unrelated reference customer's behavior. Both the current and retained supported connector interfaces must continue to accept the release.

## Story purpose

Demonstrates a complete trusted-delivery compromise.

## Prerequisites and starting position

**Required access or evidence:** [K29.2](../K29/K29.2.md).

**Starting material:** The current customer binding, a release-dossier lead, build records, and a private release-rollover rehearsal.

**Campaign references:** No separately named capability output.

## Completion and downstream use

Produce fresh customer test results tying the signed revision to its actual consumed content. ARWC must exhibit the chosen change; the supplied reference customer and both supported interfaces must retain their required behavior. Merely signing an artifact with K29.2's key does not count.

## Difficulty and inspiration

Requires constructing a targeted, compatible release across two supplied interface versions and customer contexts, not just applying an already recovered signing credential.

**Inspiration:** [PipeDream (HTB Business CTF 2025; Hard)](../../reference-catalog.md#c27). PipeDream supplies the cloud/source/signing composition. The final rollover objective is an authored extension.
