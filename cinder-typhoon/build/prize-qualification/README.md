# Event prize qualification

This directory qualifies the Cinder Typhoon 50-prize automation without a
score export, spreadsheet, manual draw, or second application service.

`candidate.json` pins the challenge catalog, participant-content digest,
operator policy digest, and every automation or schema file used by the
rehearsal. `summary.json` is the credential-free result attached to that pinned
candidate. It contains aggregate counts, assertions, and digests only.

Run the complete staging rehearsal from the repository root:

```sh
python3 cinder-typhoon/build/prize-qualification/qualify.py \
  --verify-summary cinder-typhoon/build/prize-qualification/summary.json
```

The command builds 320 organizer-authorized participant histories concurrently,
collects Good Citizen ballots through the actual nomination component, runs
concurrent evaluator retries, delivers winner messages, renders the participant
and staff claim surfaces, claims packs 1–25, expires the other initial winners,
runs final rollover, and claims packs 26–50. It also performs fresh-state
rebuild and fail-closed variants for missing inputs, policy/content mismatch,
no complete stage clears, and insufficient nominations.

Regenerate the candidate only when an intentional reviewed source change is
ready to invalidate the prior evidence:

```sh
python3 cinder-typhoon/build/prize-qualification/qualify.py --write-candidate
python3 cinder-typhoon/build/prize-qualification/qualify.py \
  --output cinder-typhoon/build/prize-qualification/summary.json
```

Generated files are written mode `0600`. The committed summary is safe to
share with the release candidate, but the temporary SQLite databases, claim
codes, draw seed, nomination export, delivery payloads, and rendered authorized
pages are not release artifacts.

This automated result proves deterministic service behavior and disclosure
boundaries for the prize lifecycle. It does not claim human discovery,
fairness, difficulty, event capacity, or overall Cinder Typhoon release
qualification. Event-owner merge approval is the signoff on the displayed
triggers, cutoffs, and claim flow; it is not generated by the rehearsal.
