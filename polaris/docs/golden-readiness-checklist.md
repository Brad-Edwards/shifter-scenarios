# Polaris golden-readiness checklist

Polaris remains `draft`. Keep every box unchecked in source; copy this
checklist into a final review record and mark only what a real run proves.

## Golden Definition Of Done

- [ ] The declared range applies from a clean checkout using committed pack content.
- [ ] The profile is isolated from shared infrastructure and avoids uncontrolled egress.
- [ ] Every declared enterprise, identity, industrial, objective-verdict, and CTFd-adapter component is real, range-local, and working.
- [ ] Industrial services use authentic vendor-supported systems or twins rather than authored protocol simulations.
- [ ] The declared provider realizes every required SDL host and isolation boundary as independent infrastructure.
- [ ] The declared build enters the participant start state without hidden operator setup.
- [ ] The participant execution surface is documented and reachable.
- [ ] The full intended path reaches every required objective from participant context.
- [ ] Negative gates show protected objectives are not reachable prematurely.
- [ ] The automated rehearsal passes against the same profile.
- [ ] A durable, redacted rehearsal report records the exact evidence.
- [ ] Teardown is verified and leaves no live range resources behind.

## Final Manual Participant Walkthrough Protocol

- [ ] Stand up the declared golden profile from the documented build entrypoint.
- [ ] Enter solely through the participant execution surface.
- [ ] Execute the intended happy path manually, command by command.
- [ ] Use operator channels only for provisioning, diagnostics, reset, observation, or teardown.
- [ ] Repair every defect on the branch and rerun the affected manual step.
- [ ] Complete the path after the final repair.
- [ ] Run automated rehearsal and static checks after the manual path succeeds.
- [ ] Tear down the range and verify cleanup.
- [ ] Report exactly what was manual, automated, and out of scope.
